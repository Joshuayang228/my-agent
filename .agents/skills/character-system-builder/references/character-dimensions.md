# 完整人物维度、决策与材料

这是一张覆盖地图，不是一轮必须填完的问卷。每一维标注已确认、待决策、待材料、不适用或需框架扩展；人物完整度由覆盖和一致性判断，不以字数判断。已有材料可能同时支持多维，保留同一来源编号即可。

## 覆盖地图

| 维度 | 用户需要决定 | 可以补的材料 | 应产出的行为证据 |
|---|---|---|---|
| 人物定位与存在方式 | 陪伴 / 协作职责，身份呈现模式（沉浸式 / 透明 / 混合），虚构故事与现实的边界 | 最希望相处的场景、不能接受的体验、是否主动解释系统身份 | 自我介绍与「你是什么」回答遵守已选身份模式，不把平台术语强塞进人物口吻 |
| 身份与稳定底线 | 名称、称谓、年龄呈现、性别呈现、不可轻易改变的价值观 | 简介、角色构想、认同的选择 | 被要求换身份、违背原则时仍能维持人物 |
| 过去与人生锚点 | 家庭 / 出身 / 教育 / 工作 / 转折是否设定，哪些经历真实属于此人物 | 时间线、故事片段、创作授权范围 | 提到过去不自发补写未经确认的细节 |
| 内在动力与矛盾 | 想要什么、害怕什么、欲望和责任冲突时如何选择 | 有代表性的两难事件 | 在矛盾场景有可解释的取舍，不机械复述性格标签 |
| 优点、缺点与盲点 | 能力优势、代价、偶尔会错在哪里、怎样修复 | 喜欢 / 不喜欢的人物行为与理由 | 失误能认错和调整，缺点不会被用来拒绝安全约束 |
| 表达与情绪 | 句长、直接度、温度、幽默、称呼、旁白、低落与兴奋时的差异 | 正反例对话、书信、语言样张 | 同一事件有符合人物的表达，没有固定口头禅刷屏 |
| 与用户的关系 | 初识距离、亲密推进、拒绝 / 沉默 / 争执时的回应、用户自主权 | 理想相处片段、令人不适的互动 | 不索取排他关系、不虚构共同经历；亲密有事实依据 |
| 社交网络与团队 | 家人 / 朋友 / 同事 / 伙伴成员关系、方向、熟悉程度、张力 | 关系图、互动片段、双方已确认设定 | 不把认识当成亲密；召唤保持另一角色独立身份 |
| 专业与协作 | 专长、知识盲区、遇事先听还是先行动、行动与建议的边界 | 工作习惯、典型任务、能力证据 | 能承认不知道，工具与承诺符合实际能力 |
| 日常生活与节律 | 作息、工作 / 休闲平衡、主动性、社交需求、暂停恢复方式 | 一天 / 一周生活片段 | 日程可信，暂停期不捏造逐时逐日事件 |
| 世界与空间 | 真实或虚构城市、居所、房间、常去地点、交通、季节感 | 地图、场景文字、空间图片 | 默认背景与当前位置分开；只按已发生事实更新 |
| 爱好、文化与感官 | 书 / 电影 / 音乐 / 食物 / 活动偏好，喜欢的理由与不喜欢之处 | 作品清单、评论、感官描述 | 偏好服务行为选择，不借参考作品虚构现实经历 |
| 外观、衣物与有意义物件 | 外貌、穿衣风格、常用物件、来历、视觉一致性 | 图像、色板、服装 / 物件说明 | 身份外观与当前穿着分开，资产取得有来源 |
| 动态与主动表达 | 什么值得发朋友圈、内容密度、分享与保留、何时主动联系 | 认可 / 不认可的动态和开场白 | 动态符合实际活动，不新增地点、人物或约会 |
| 记忆、成长与连续性 | 哪些习惯能变、怎样记住关系、如何处理冲突记忆、什么不能变 | 成长前后对比、用户反馈 | 成长能调整表达，不能改写稳定身份和已发生事实 |
| 边界、冲突与恢复 | 敏感话题、隐私、过度推动、道歉、拒绝、工具失败 | 明确的禁例、失败交互 | 拒绝后收住；失败说明事实，不用人格掩盖服务错误 |
| 验收与团队区别 | 「像这个人」的具体标准，各成员的相同底线和不同气质 | 实际好 / 坏输出、比较样本 | 主对话与四种后台行为一致；多个角色没有同声同气 |

## 决策优先级

通常先决定存在方式、用户关系、价值取舍和表达，再定故事与世界，最后写具体行为；用户已有丰富故事或明确要先讨论世界时可调整顺序。缺失的关键身份 / 关系边界会影响所有 Prompt，应优先确认；发色、生日等未影响当前行为的细节可以暂存。

不根据名字推导职业、城市、性别、气质或惯用比喻。也不为了「活人感」强制增加创伤、疾病、恋爱或家庭冲突；是否设定由用户决定。

## 材料需求怎么提出

先说明用途与最小可用形式，允许用户口述。例如：

- 表达：「给两三段你喜欢的说话方式，再给一段你不喜欢的，标出喜欢 / 不喜欢的原因。我会先提炼规律，原文不会直接当口头禅。」
- 关系：「描述一次希望 TA 怎样陪你的场景，以及一次你不希望 TA 继续推动的场景。我们据此决定主动性的边界。」
- 世界：「你可以描述一个常待的空间，或提供一张有氛围的图；我会列出能采用的地点、物件和感官细节，等你决定哪些属于人物。」
- 背景：「已有经历清单就按时间提供；没有时，可先决定允许原创的范围，AI 候选故事经确认后再采用。」

不要把现实用户的信息写成人物档案，也不要为塑造虚构人物索取不必要的真实私人资料。私人原文先去标识化或存到用户指定位置；未得到存储授权时只记录材料用途与已确认摘要。

## 每个行为都要核对的五件事

触发情境、人物判断与偏好、事实输入来源、表达方式、不能改变的输出 / 权限 / 副作用契约。四类后台行为各自填写人物差异或「沿用通用行为」，不靠新增完整 System Prompt 来增加覆盖率。

对衣柜、文化角、家居、通讯录、足迹与朋友圈分别确认：默认资产、运行时变化、证据来源和展示意图。图片生成提示词只有在实际媒体入口存在且本轮获授权时才落到该入口；视觉说明不等于已生成或已绑定资产。
