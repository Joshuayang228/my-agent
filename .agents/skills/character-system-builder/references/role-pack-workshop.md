# Role Pack 施工循环

这份参考只记录可复用的方法，不记录某个角色的姓名、作品经历或固定文案。

## 1. 先做边界盘点

读取项目模块卡、Role Pack loader、类型、默认宇宙 manifest、relations 和现有资产测试。列出：

- 已确认的人物决定、待用户决定的事实、需要用户材料的维度；
- 稳定身份、档案、表达、默认世界、可变成长、行为入口和场景样张各自的生产落点；
- 现有角色是否是生产事实、测试夹具或历史文档，不要把测试样本当成名册。

如果用户要求从零开始，先记录删除范围、影响和不清理的运行时数据，再删除角色资产；不要顺手删除数据库历史、通用代码或测试夹具。

## 2. 用高层骨架接通

首轮人物只写能被用户确认的稳定方向和行为差异。原作角色的公开印象可以作为参考，但原文台词、长段剧情、未提供的时间线、关系和隐私不能直接成为生产事实。未决定的字段写成明确的“待确认”，不能用空泛形容词伪装已完成。

Role Pack 的职责固定为：

| 文件 | 作用 |
|---|---|
| `manifest.json` | 名册身份、主角资格、简短描述、可选 aside 风格 |
| `protected.md` | 稳定身份、价值排序、行为底线和平台边界内的人物差异 |
| `mutable.default.md` | 可随关系和反馈调整的表达倾向，不得改写安全边界 |
| `voice.md` | 句长、直接度、温度、玩笑和场景收放 |
| `profile.json` | 结构化档案、兴趣、缺点、表达五维和已确认外观 |
| `world.default.json` | 虚构或现实生活骨架；不等于运行态世界状态 |
| `behaviors/*.md` | 现有行为入口的角色增量，不能重写协议、回退或副作用 |
| `scenes/*.md` | 展示、互动、执行的审阅样张，不自动新增运行时入口 |

## 3. 顺序化审阅

按“身份 → 表达 → 档案 / 外观 → 世界 → 行为入口 → 关系”顺序审阅。每个维度用“情境 → 人物判断 → 表达 / 行动 → 不该出现什么”写一个正例和一个反例；如果一个差异无法影响实际选择，就留在草稿，不塞进生产。

## 4. 接线与验证

新人物只通过 loader 支持的目录接入。更新默认宇宙 manifest 和关系边后，检查默认角色入口、角色切换、Prompt 注册来源、图片外观锚点和四类行为消费者。随后依次运行资产检查、类型检查、单元测试、构建和文档检查。

没有真实模型或生图授权时，只报告静态、编译和本地回退验证；不能把“文件存在”说成人物效果已通过。

## 5. 迭代归因

收到反馈时先判断问题属于人物决定、材料缺口、写作方法、运行时能力还是验收标准。只有能在第二个人物上复用的规则才回写本 skill；角色专属的称呼、经历、喜好和关系留在 Role Pack 与人物合同。每次回写都保留变更原因，并用既有正反例回归。
