My Agent 产品案例

这是一个人格化桌面 AI Agent 的产品设计与实现案例。重点不是模型接入，而是如何把身份、记忆、工具、生活状态和诊断能力组织成可持续迭代的产品系统。

问题定义：功能存在，但关系无法连续

用户在多次使用中反复提供背景；系统有能力，却缺少稳定的身份、记忆来源和状态反馈。

01

问题一：上下文不能沉淀

会话任务可以完成，但重要事实、偏好和关系变化无法沉淀为可复用记忆。

02

问题二：人格不可维护

单段角色提示词无法覆盖关系、生活资产、工具权限、场景行为和版本演进。

03

问题三：系统状态不可解释

工具、记忆、事件消息和世界状态分散在系统里，没有形成清楚的用户旅程。

产品目标：让每一次交互都能回答三个问题——它是谁、它依据什么、下一步如何继续。

产品原则：把复杂度拆成可验证的层

每条原则都对应数据边界、界面呈现和测试门禁。

A

1. 人格资产分层

稳定身份、动态上下文、行为策略、工具环境和协议契约分离；Prompt 通过注册表统一管理。

B

2. 记忆可追溯

记忆保留来源、作用域、引用和纠错入口；读取层不把缺失事实补成默认值。

C

3. 世界状态建模

人物、关系、位置、家居、足迹、衣柜、物品和事件是可查询的结构化资产。

D

4. Debug 只读真相

Debug 展示真实注册资产、装配上下文、调用链、运行状态和失败原因；Playground 只做隔离实验。

用户旅程地图：从一次对话到长期使用

每个阶段都明确用户目标、系统动作、所需 Prompt、状态数据、失败路径和验收证据。

01

阶段一：建立身份

用户确认“它是谁”；系统加载稳定身份、初始生活资产和行为边界。

02

阶段二：完成任务

用户在聊天、日程、工具、位置、家居和朋友圈中获得连续上下文。

03

阶段三：沉淀变化

事件、评论和记忆提炼让 Agent 对变化做出回应。

事件触发 + 反馈

系统拆解：从用户旅程反推产品能力

每一层都有稳定接口和单一事实源；新增能力先补注册、数据、界面和测试，再接入正式旅程。

验证方法：用一个人物贯穿全功能

第一位完整验收角色是路飞。选择一个资料丰富、关系明确、生活资产具体的人物，能更早暴露系统缺口。

1

验收对象

从身份、伙伴、千里阳光号、草帽和基础衣柜开始，覆盖对话、生活、记忆、主动消息和 Debug。

5

层能力链

任务、生活、记忆、事件和 Debug 互相提供证据。

∞

可复用方法

把资料采集、设定决策、注册、实现、验收和迭代沉淀为人物制作 Skill。

迭代计划：先补闭环，再扩大范围

优先处理影响可信度和可解释性的缺口，暂不为了数量扩展入口。

NOW

P0：全旅程闭环

补足伙伴关系、朋友圈、评论、事件消息、记忆提炼和基础生图资产。

NEXT

P1：人物制作 Skill

把资料采集、设定决策、Prompt 注册、验收和迭代整理成可复用流程。

THEN

P2：角色网络

从单一主角扩展到有关系、有分工、有共同世界的角色网络。

ALWAYS

持续：生产证据

保证每个能力都有来源、状态和失败路径，能定位问题并支持回归。

这是一套可持续迭代的人格化 Agent 产品方法。

面试交流可以从问题定义、取舍、数据边界、验收方法和下一步计划展开。
