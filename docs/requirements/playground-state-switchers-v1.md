# 施工合同：Playground 状态切换统一 v1

> 状态：进行中
> 生命周期：进行中
> 授权：用户要求统一 Playground 状态切换，允许基于证据选择样式；本轮仅 P0。

## Why

Chat 使用外框分段条，MCP 使用独立选项，记忆和工作区又有不同字号与内边距。同一类审阅动作呈现多套视觉语言。

## What

采用 MCP 的紧凑独立选项：32px 高、11px 字号、16px 行高、10px 水平内边距、4px 间距，主题圆角与颜色取自现有 settings-option 语义。选项自然换行，选中态有主题描边与浅底色，键盘焦点独立可见。

覆盖 Chat 主旅程及宽度、记忆分类及场景、模型/MCP/Skills 场景、工作区功能及形态/宽度、公共基础故事切换。工作区内可关闭内容标签、产品导航、表单选项和被展示的基础控件不属于场景控制器，保持原有语义。

## How

用 Playground 专属样式文件及显式 data 属性标记控制器，共享一处样式，保留各处事件、ARIA 和测试标识。Chat 删除分段外框与局部选中色；公共故事选择删除下划线皮肤，改用同一选项样式。不修改生产 settings-option 默认值、不增加依赖。

## 验收与步骤

1. 标记现有控制器并移除冲突的局部样式。
2. E2E 比较五处及其他场景选择器的计算样式、选中状态和点击结果；深浅主题、宽窄视口截图。
3. 单测、类型检查、构建、资产和文档门禁后交给用户审阅。

## 影响与权衡

可换行会增加多选项导航的高度，但全部场景可见，不需要横向寻找。仅改变审阅控制器的外观，不改变数据、生产布局或实际工作区标签。
