# 施工合同：注册提示词请求边界

> 状态：已完成施工快照（冻结，2026-10-13）
> 生命周期：已完成施工快照（冻结）
> 授权：用户确认“好，做”，按已提出的模型入口强制编译结果方案施工。

## 背景与目标

现有 AST 门禁仍可被不规范命名、多层组装和手填 key 绕过。让模型入口只接受本进程真实编译器生成的请求；正文与资产依赖在固定行为工厂自动生成，禁止调用点给任意文本挂生产 key。

## 技术方案

纯 Prompt 领域提供封闭的生产配方、主对话 / 子任务编译结果和请求组装器。编译对象由私有身份表认证并保存不可变消息快照；共享类型提供不透明类型。streamChat / chatComplete 不再接收原始 messages、promptAssetKeys 或 promptlessReason；运行时先拒绝伪造对象、额外正文覆盖和未知资产，再进入网络 / Trace 路径。

用户消息、历史、工具结果是运行时数据；固定包装由配方生成。Playground 与 Eval 具有明确实验资产来源，生产文件不能导入 Eval 编译入口。主对话与后台实际依赖由配方推导，不维护第二套 key 列表。

## 影响范围

改动 prompts、统一 LLM 入口、Loop / Runtime、后台辅助调用、Eval、共享类型及测试。LLM 入口已有其他任务改动，保留并只提交本次增量。删除旧调用参数与 promptless 逃生入口，范围限于模型请求契约，不改 Provider、权限、数据库或正式 UI。

Debug 生产资产目录仍只读。动态模板与实际调用区别如实说明；原有实验草稿和用户补充指令受控保存不在本次移除，不重排 UI。

## 实施步骤与验收

1. 建立编译身份与固定生产配方；验证伪造、篡改、未知来源失败。
2. 迁移真实调用与 Loop / Eval；验证正常调用、重试、压缩、截断恢复与实验来源。
3. 加强防漏门禁，禁止旧参数及生产 Eval 逃生；验证负例。
4. 更新模块卡、架构、质量与 Debug 边界说明，按顺序完成测试、类型、构建、资产和 staged 文档门禁，提交推送。

## 风险与权衡

身份校验防止误调用和来源伪造，不宣称阻止恶意修改整个应用代码；语义数据与指令仍需要来源约束及模型行为 Eval。实验输入必须显式标源，不能假装为内置生产正文。主进程独立类型债沿 WISH-043 管理并对比新增诊断。


## 自审修正记录

- 删除对象：旧的原始模型消息 / 手填来源参数、Playground 服务内重复消息组装、子角色定义在 Agent 层的重复承载。原因：来源必须随固定配方生成，纯正文定义不能形成 LLM → Agent 反向依赖。角色正文与默认工具内容不改，测试夹具继续复用纯函数。
- 续跑根因：subagent-registry 的 continue 调用没有 systemPrompt；捕获 coder / summon 实例续跑参数，实际来源为 undefined，Loop 会采用通用默认。补传同一角色编译结果，回归验证角色和召唤任务工边界。
- 攻击面：手工 / 复制 / 序列化请求、正文 / key 篡改、旧字段覆盖、实验冒充主对话、未知角色来源、伪造压缩 ID 均有失败路径；固定配方、调用作用域、私有身份表与注册解析分层约束。既有消息预算和实验输入长度限制保留。
