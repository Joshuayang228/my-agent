# Prompt 分层组合与人物适配施工合同 v1

> 状态：进行中
> 日期：2026-10-31
> 关联合同：[提示词全链路覆盖与内容审阅施工合同 v2](./prompt-coverage-and-review-v2.md)
> 目标：为每个功能建立通用 Prompt 合同，再由人物适配层生成具体人物行为。

## 1. 为什么做

当前 Prompt 已经完成注册、签发和 Debug 集中展示，但功能协议、平台约束、人物表达和运行时数据仍有部分混在同一构造器或人物行为文件中。继续新增人物时，容易复制整条 Prompt；继续新增功能时，也容易把人物语气、平台边界和输出协议写在一起，导致复用困难、覆盖关系不清、测试难以判断失败来自哪一层。

本合同建立一套可复用的 Prompt 组合模型：功能先有通用协议，人物再提供适配，运行时只注入事实和当前状态。路飞作为第一位完整迁移人物，用来验证这套模型能覆盖现有产品旅程。

## 2. 目标与完成定义

- 为每个进入模型的功能建立稳定的功能 Prompt 合同：目的、输入、通用规则、输出协议、失败处理、消费者和验收场景。
- 将 Prompt 组合固定为四层：平台约束、功能协议、人物适配、运行时上下文。
- 规定每层可覆盖范围和优先级，人物适配不能覆盖平台安全、事实边界、工具权限和输出校验。
- 将路飞现有主对话、日程、生活补叙、朋友圈、评论回复、主动消息、生图、记忆提炼、反思、压缩、召唤和工具协作迁移到组合模型。
- Debug 能分别展示通用功能定义、人物适配、运行时输入和最终调用关联，不复制正文作为第二事实源。
- 新增人物只需提供 Role Pack 和功能适配，不修改各功能实现中的硬编码人物分支。
- 新增功能必须先登记功能合同和真实消费者；无消费者、无输出校验或无失败路径的定义不能通过门禁。

## 3. Prompt 四层模型

### L1 平台约束

稳定的权限、事实来源、工具安全、用户自主、敏感信息、语言和协议边界。由平台生产代码维护，人物和功能都不能覆盖。

### L2 功能协议

描述一个功能要完成的任务，以及它需要的输入、决策规则、优先级、禁止事项、输出结构、长度和失败回退。功能协议不写具体人物口吻，不假设某个 Role Pack 存在。

### L3 人物适配

从 Role Pack 读取稳定身份、表达基线、价值排序、关系策略、世界边界和该功能的行为增量。人物只能调整表达、选择倾向和人物相关的解释，不得改变 L1 / L2 的约束。

### L4 运行时上下文

本轮用户输入、动态正文、关系阶段、世界切片、衣物、记忆、工具环境和其他事实数据。运行时数据不是静态 Prompt 资产，也不能通过数据字段注入新的上级指令。

组合优先级固定为：平台约束 > 功能协议 > 人物适配 > 运行时事实的表达化呈现。事实冲突时保留事实不确定性，不能用人物语气覆盖事实缺失。

## 4. 功能合同字段

每个功能合同至少包含：

- `key`：稳定功能身份。
- `purpose`：用户可理解的功能目的。
- `inputs`：静态适配输入与运行时事实输入分开列出。
- `rules`：通用行为规则和禁止事项。
- `overrideBoundary`：人物适配允许修改的字段。
- `output`：结构、字段、长度和格式要求。
- `fallback`：缺输入、模型失败、解析失败和持久化失败的处理。
- `consumers`：真实生产调用入口。
- `evidence`：正例、失败例、跨角色边界和 Debug 证据。

功能合同的元数据进入统一注册表；正文继续维护在生产构造器或 Role Pack 文件，不在注册表和 Debug 组件复制正文。

## 5. 本轮迁移范围

| 功能域 | 通用协议 | 人物适配 | 运行时事实 |
|---|---|---|---|
| 主对话 | 任务执行、事实边界、工具协作、输出优先级 | 身份、表达、价值排序、关系策略 | 用户消息、记忆、世界、工具 |
| 日程 / 生活 | 结构化活动、事实与建议分离、生命周期限制 | 行动节奏、生活偏好、表达方式 | 日期、世界状态、资产、关系 |
| 朋友圈 | 事件转动态、正文范围、发布约束 | 叙事口吻、伙伴关注点 | 事件、地点、参与者、图片 |
| 评论回复 | 只回应已给动态和评论、短格式输出 | 语气、热情度、关系表达 | 动态正文、评论、关系阶段 |
| 主动消息 | 只在投递门闸允许后生成、短句和回退 | 关心方式、称呼和语气 | 新动态、日期、回执状态 |
| 生图 | 图片描述协议、视觉安全、格式和保存约束 | 外观、衣物、人物视觉锚点 | 用户描述、穿搭、场景、目标资产 |
| 记忆提炼 | 用户主体、原话证据、敏感过滤、结构校验 | 人物反馈的解释方式 | 对话、已有记忆、来源证据 |
| 反思 / 成长 | 只修改可变层、事实与建议分离 | 成长方向、承认缺点、行动倾向 | 用户材料、生活信号、关系事件 |
| 压缩 / 召回 | 上下文预算、关系最小集、事实边界 | 人物事实的保留方式 | 历史消息、记忆、当前任务 |
| 召唤 / 工具协作 | 工具权限、子任务边界、结果可信度 | 人物身份和转述风格 | 工具结果、名册、工作区 |

## 6. 技术方案

- 在 `electron/main/prompts/` 增加通用功能合同与组合器，组合器只负责按固定顺序拼接已登记层，不负责业务副作用。
- 扩展注册元数据，记录 `layer`、`featureKey`、`overrideBoundary`、`dependencies` 和真实消费者；兼容现有 Prompt key，不新建第二套目录。
- Role Pack 的 `behaviors/` 改为明确的功能适配层；稳定身份和表达文件仍保持独立。
- `registered-request.ts` 的每种配方签发组合后的请求，并保留各层 key，便于 Debug 查看最终调用由哪些层组成。
- 运行时上下文只作为结构化输入进入组合器；用户文字、记忆、动态和工具返回不进入静态注册表。
- Debug 提示词管理器增加“通用功能 / 人物适配 / 最终组合”关系阅读，默认正文仍简洁，完整层级按需展开。
- Playground 只展示组合规则和隔离样本，不复制生产 Prompt 或真实运行数据。

## 7. 实施步骤与验证

1. 盘点现有 Prompt 构造器、Role Pack 行为、注册项和真实消费者，生成迁移表。
2. 定义功能合同类型、组合顺序、覆盖边界和注册元数据，补类型与门禁负例。
3. 先迁移评论回复、生图、主动消息和记忆提炼四个边界清晰的功能，跑正反例。
4. 迁移主对话、日程、生活、反思、压缩、召唤和工具协作，删除功能实现中的人物硬编码分支。
5. 以路飞跑完整人物验收；再用一个隔离测试人物证明新增人物无需修改功能实现。
6. 更新 Debug、人物制作 Skill、模块卡、架构、质量和进度文档。
7. 运行 Prompt 注册 / 消费门禁、专项 Unit、Electron 本地协议、类型检查、构建、资产审计和文档门禁。

每一步都必须能独立证明：定义存在、真实调用、人物适配来源、运行时输入边界、输出校验和失败回退。没有外部模型凭据时，只报告本地协议和结构验证，不宣称人物表达质量通过。

## 8. 影响范围与风险

涉及 `electron/main/prompts/`、Role Pack、注册表、Debug 资产聚合、人物制作 Skill、测试和相关模块文档。生产请求的来源签发、权限、数据持久化和 IPC 边界保持不变。

主要风险是迁移期间把运行时数据误注册成静态资产，或让人物适配覆盖平台 / 功能协议。注册门禁、组合层快照、跨人物负例和现有功能回归必须在每个迁移批次完成后运行。

本合同不建设自主朋友圈配图、图片识别回填、阅读感想等独立 P2 产品；它们若开工，必须另写功能合同，但应复用本合同的四层组合模型。

## 9. 完成条件

- 所有现有生产 Prompt 都能标明属于平台、功能、人物适配或运行时上下文层。
- 每个需要模型生成的功能都有通用合同、真实消费者、人物适配边界、输出校验和失败处理。
- 路飞所有已接入功能通过组合层和人物验收；新增隔离人物通过无需改业务代码的验证。
- Debug 能读出通用定义、人物适配和最终组合关系。
- Prompt 注册、消费、类型、构建、专项测试、Electron 验收、资产和文档门禁全部通过。
- 稳定事实吸入模块卡 / Architecture / Quality 后，合同冻结为完成施工快照。
