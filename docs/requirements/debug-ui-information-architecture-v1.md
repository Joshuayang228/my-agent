### 背景与目标

当前候选已覆盖七组 26 入口，也改善了字号和内容高度，但多数领域仍共用「搜索 / 人物筛选 / 长边界说明 / 卡片列表 / 字段详情」。日程、状态和画像需要逐条点击，重要业务信息被记录结构、id 与解释语句打断。Alice 的 ZM 为提示词使用工作台、其他领域使用阅读布局；iM / aM / wM / HM 分别用时间行、事件流、状态与住所分区、指标及字段展示。需要对齐其按阅读任务选择形态的做法。

目标：打开页面即可读到最重要的事实；只有多对象定位、长正文和来源追查需要展开或进入详情。页面不追求同一种布局，基础控件、状态、间距、主题、人物范围及证据语义保持一致。现有六生活面、调用关联和质量证据完整保留，不为照搬菜单引入不存在的数据模型。

### 提示词管理器

1. 页头为「提示词管理器 + 目录总数」，右侧只读状态；下一行人物胶囊筛选，再下一行通栏搜索。形态筛选放在轻量工具行，避免缩窄主搜索；语言仅中文，不搬入语言切换或编辑入口。总数、筛选命中数与当前分组数量明确区分。
2. 全部人物按生产来源类别组织目录：平台 / 行为、人物、世界与生活、记忆、工具与技能、权限、模型、验收；类别是现有资产类型 / 来源的展示映射，不能成为新的生产定义。选中人物后按其明确关联的用途组织：身份、成长与关系、行为、生活情境、工具环境、输出协议；未关联到该人物的共用资产放独立「平台共用」，不称作该人物实际注入。缺少关联元数据时显示未登记关联，不在 Renderer 猜来源。
3. 目录采用 Alice 的分组树与短条目：固定 340px，分组标题可吸顶，展开显示类型 / 变量数量、可读名称和一行摘要。默认不显示完整 key / 文件路径；选中状态用稳定底色，禁止新增左侧强调竖线。分组类型计数有可辨识颜色和文字图例 / 可访问名称；颜色仅表示类型，不代表验收通过或风险级别。
4. 详情顶部依次为来源类别与类型、可读名称、key；其后是紧凑变量 / 参数区、正文。中文自然语言按普通阅读文字展示，协议 key / JSON 保留适当代码形式；没有正文的结构资产展示其真实结构，动态资产解释模板与最终输入的区别。
5. 版本 / 指纹 / ownership / source 折叠为「来源与版本」，调用关联折叠为「相关调用」并给数量，正文优先获得空间。不丢任何现有证据；仅在有显式 key / callId 时跳转。
6. 搜索覆盖名称、key、来源、正文、变量，命中时自动展开分组；人物 / 形态改变后清除无效选择，搜索词保留。刷新失败保留上次选择与数据并标明失败；窄屏选择进入详情，返回恢复筛选、分组与焦点。空结果可清除筛选，未读取与真实空目录分开。

### 全部页面的阅读形态

| 页面 | 默认直接展示 | 深入查看 |
|---|---|---|
| 今日日程 | 日期 / 人物范围、时间行：时间、活动、地点、已知计划 / 发布状态 | 行内展开来源事件、生成来源与未记录项；不造执行完成、跳过状态 |
| 最近事项、行为日志、实时事件 | 时间顺序事件流：时间、事件名、类型、短结果与来源 | 关联事件 / 请求 / Span 及详情；生活事件、反思、运行日志保留各自类型 |
| 此刻、当前位置、系统状态 | 当前状态分区：活动、地点、情绪 / 能量或环境 / 连接；更新时间与范围 | 来源、缺失字段与诊断依据；不把当前快照称为历史输入 |
| 人物档案、用户画像 | 人物资料或身份 / 协作 / 表达三个完整摘要区直接展开 | 人物资料版本、记忆类别、证据条目与真实聚合范围；伙伴与用户不混淆 |
| 家居 | 住所摘要 → 空间分区 → 所属物件；未归置单独区 | 展示决定、理由、依据、来源、缺失图片；不按名字推断归属 |
| 足迹 | 旅行清单：目的地、日期、旅行状态与经历摘要；计划 / 取消 / 旧地点单独区 | 旅行经历、停留日期与正文；缺日期不补造，不把旧地点变旅行 |
| 朋友圈、主动消息证据 | 已发布动态 / 会话消息时间流，正文优先、来源标签次之 | 评论、关联事件和实际保存的投递证据；普通消息不冒充主动发送证明 |
| 通讯录 | 人物名称、关系短句、当前忙闲与有来源的经历概览 | 人物资料、共同经历与用户关系证据；不引入 Alice 信任分模型 |
| 衣柜、文化角 | 各自分类的资产清单 / 卡片：衣物与穿着；阅读 / 音乐 / 影视 / 摄影 | 衣物来源、作品状态、完整笔记及所属作品；实物留在家居 |
| 成长与反思、用户记忆 | 成长覆盖 + 反思记录；或有明确范围的记忆清单 | 人格版本、反思门闸、记忆类别与关联；不声称存储即注入 |
| 生活事件关联、调用链 | 显式事件关联图 / 列表；或 Span 阶段时间线 | 关联对象、失败节点与来源；缺少标识不按时间猜关系 |
| 上下文 | 当前语义模块 / 输入范围及正文保存边界 | 模块正文与来源，历史实发仅接受该次保存证据 |
| LLM 调用 | 可筛选调用清单 + 调用详情工作台 | 输入 / 执行 / 来源；沿用已验证关联与失败路径 |
| 技能与工具 | 注册、当前可用、此次实际使用三层清单 | schema、Skill 指南、权限来源与调用证据，不把注册等于使用 |
| Skill 验收、人格验收 | 结论、通过 / 失败 / 待人工项、关键证据 | 完整检查与报告；人工体验结论不由自动一致性判定替代 |

所有页面保留人物范围；单个当前对象不为了通用性增加无意义列表。日期只给时序查询，搜索只给可搜索清单，当前状态不强塞搜索框。先展示业务信息，关键异常和数据缺失紧邻受影响内容；一般能力边界、技术 source / id 和展厅说明折叠保存。不会把影响解释的「未出发」「没有历史正文」等关键信息藏进页尾。

### 共享设计与技术方案

- 统一壳继续七组 26 入口，默认提示词管理器。使用按页面区分的图标，避免一整个生活分组都用同一个爱心；导航隐藏滚动条但保留滚轮 / 键盘。不因 Alice 菜单改变本项目能力分布。
- 字体、对比度、语义色、圆角、间距、空 / 错 / 加载态、范围提示、返回与焦点恢复复用 Foundation 和当前主题。类型、业务状态、诊断结果分别表达，不用一种颜色暗示所有含义；不新造通用控件或主题皮肤。
- 拆分当前 DebugEvidenceCandidate 的强制布局：保留共享筛选、状态及显式关联行为；按时间流、状态阅读、资料摘要、领域资产、请求 / 验收证据组织页面 renderer。每个 renderer 消费有类型的领域字段，不依赖「字段 label 等于某中文」拆解业务关系。样张只供适配数据，不保存第二份人物 / Prompt 事实。
- 家居 / 足迹 / 文化 / 通讯录优先复用已存在的纯展示组件或解析器；只有 Debug 专属来源和诊断内容才由候选 wrapper 增补。复用前确认不会读取 IPC、触发初始化、换装、召唤或写盘。生产组件默认行为不为候选修改。
- P0 数据流：隔离样张 → 纯领域适配 → 页面 renderer → 显式证据跳转。Prompt 人物用途关联也使用显式样张关系；不会借此改动生产注册表、组装器或人物材料。新增文件同步 experience.debug.sourcePaths、资产家族和隔离门禁。
- P1 数据流：现有生产聚合器 / 只读有界查询 → 类型化响应 → 同形态展示。资产只读查询、历史范围 / 截断、人物与共享记忆、用途关联不足的生产契约仍按下方约束补齐；有新增 IPC 时同步四处。P0 展示不会被作为生产接线已经完成的证据。

### 影响范围、实施与验收

P0 修改范围为 src/components/playground 的 Debug 候选、样张 / 适配器 / 局部 CSS、experience.debug 登记与资产归属、Unit / E2E 和对应文档。替换通用列表详情的原因是阅读任务不匹配；原数据字段、筛选、关联和空错态不得被顺手删除。正式 DevPanel、生产 Prompt / Role Pack、Agent Loop、权限、设置、数据库与 IPC 不在 P0 改动范围，无新增依赖。P1 仅在实际候选验收后另行施工，不把 P0 / P1 分成假功能或占位交付。

实施顺序：确认本方案 → 建立人物用途 / 领域展示契约并检查现有纯组件 → 完整实现提示词工作台与全部页面形态 → 逐页检查失败 / 空态 / 缺关联与恢复 → 自审、类型、Unit、UI、构建、资产与文档检查 → 提交推送并展示深浅 / 宽窄截图。完成 P0 后用户实际查看并明确授权回流，再补齐 P1 真实只读契约和生产接线。

验收要求：

1. 26 个入口均实际进入，默认无需点开记录就能读到其核心信息；日程可同时比较多个时段，画像直接读到三类摘要，家居可辨住所 / 空间 / 物件，足迹可辨实际出发 / 计划与停留。
2. 提示词默认来源分组与人物用途分组可验证；平台共用不冒充实际人物注入。类型计数可理解、正文可读，长目录 / 长正文独立滚动；筛选、返回、来源与调用关联全流程有效。
3. 深浅主题，1280 / 1096 / 600 宽度、704px 短窗口、长名称 / 正文 / 无图片、键盘 / 焦点恢复，无横向溢出、遮挡或未验证的按钮。普通阅读文字对比度至少 4.5:1，透明底色按实际背景合成。
4. 空数据、未读取、读取失败、未记录、未支持、历史截断各有明确语义；刷新失败保留可用内容，不把计划 / 发布冒充执行。
5. 隔离门禁覆盖全部候选来源；无生产 API、模型调用、写盘、资产播种或复制生产正文。整体实际查看前不修改生产 UI。

风险与权衡：领域 renderer 增多会带来展示代码，但可避免通用字段列表丢语义；只共享基础交互，不再次收敛成万能页面。用途分组必须有真实来源关系，P0 只能验证展示规则，P1 不足的契约须显式补齐。Alice 有未接完的画像 / 记忆入口和更丰富的生活数据，借鉴其呈现不能冒充本项目具备相同能力。较高信息密度可能压缩窄屏正文，窄屏保留列表 / 详情逐层进入而不强行并排。

### 参考证据与问题根因

- Alice 提取源码 `_reference/framework-harness/repos/alice-source/_extract/index-ppRSWnkN.js`：`ZM` 定义六组、26 个入口，默认 `promptManager`；提示词页占满剩余高度并分别滚动目录与详情，其他页使用阅读布局。
- `tM` / `sM`：提示词有总数、人物映射筛选、按来源或人物用途分组、常量 / 模板计数、正文搜索、变量 / 参数和正文详情。截图中的 1389 是 Alice 当时的条目数，不是本项目目标数。
- `iM` / `aM` / `oM`：今日日程、按日期最近事项、行动与 Planner 记录相互独立。不能用 LLM 调用列表替代生活计划与行为结果。
- `gM` 至 `VM`：逐项读取了生活、社交、资产、用户和系统页面的真实读取方法与动作。Alice 的重生成、改写 Prompt、强制触发、换头像等写动作不随信息布局自动获得本项目授权。
- 我们的 `DevPanel` 已有明确提示词入口，而新候选把它改称「生产资产」；`WorldStatePanel` 和 `debug-world-snapshot` 已含日剧本等数据，新候选却把全部伙伴内容压成两组摘要。问题是信息丢失，并非生产能力全部不存在。

### Alice 26 个入口与本项目逐项映射

「可拆分」指已有数据可以组织为独立页，尚未完成新页接线；「部分」指只能展示标明边界的现有证据；「缺口」指未找到同等完整数据模型和读取链，不得用空数组伪装已接入。

## 1. 需求背景（Why）

当前项目已经具备正式 Debug 的真实数据链路：Prompt、生产资产、LLM 请求、Trace、Event、伙伴世界快照、Eval、系统信息和工具目录。但 `DevPanel` 仍以功能面板集合为主，用户需要在多个分区之间自行拼接一次运行的上下文，难以快速回答“系统现在是什么”和“刚才为什么这样运行”。

Debug 不应成为第二个 Settings，也不应复制 Playground 的实验控制器。它需要把真实运行事实、证据明细和受控诊断动作分层表达，并保持真实 IPC、脱敏和只读边界。

## 2. 功能目标（What）

1. 让 Debug 默认入口先呈现当前运行概览，而不是直接落入某个内部面板。
2. 将真实运行状态与证据明细分层，支持从资产、LLM 调用、Trace、Event 之间定位关联。
3. 保留现有 Prompt、伙伴状态、Eval、系统信息和工具能力，不因重排 UI 丢失真实数据入口。
4. 明确只读信息、受控诊断动作和禁止进入 Debug 的 Settings / Playground 能力。
5. 对长文本、加载、空态、错误、脱敏、窄宽和键盘操作建立统一验收标准。
6. 让每个 UI 数据块都能追溯到真实组件、IPC 或主进程聚合器。

## 3. 技术方案（How）

### 3.1 三层信息模型

```text
运行概览
├── 当前会话 / 当前任务
├── 当前模型与运行预算
├── Prompt / 记忆 / 工具摘要
└── 当前错误与运行状态

真实证据
├── Prompt 与生产资产
├── LLM 请求与响应摘要
├── Trace 调用链
├── Event 时间线
├── 伙伴 / 世界快照
└── Eval 报告

受控诊断
├── 刷新真实状态
├── 运行受限诊断
├── 导出脱敏报告
└── 清理或归档调试日志
```

### 3.2 真实数据边界

- UI 只消费 `window.electronAPI.debug` 和已有事件流，不在 Renderer 推断生产事实。
- Prompt、资产、模型、工具、权限和 MCP 状态必须来自对应主进程聚合器或正式 IPC。
- 用户 API Key、Prompt 隐私正文、原始请求秘密和内部文件路径继续遵守现有脱敏规则。
- Playground fixture、故事注册表、来源路径和实验控制器不得进入正式 Debug 默认视图。
- 受控动作若新增 IPC，必须在主进程重新校验输入、权限、取消和审计，不得仅依赖 Renderer 隐藏按钮。

### 3.3 关联模型

一次运行的概览、LLM 请求、Trace 和 Event 应尽量使用稳定的会话 / 任务 / span 标识关联。若现有数据无法支持某种关联，先展示明确的“未关联”状态，不在 UI 中猜测关系；需要补充跨层标识时另行扩大施工范围。

## 4. 影响范围评估

### 4.1 预计修改

- `src/components/DevPanel.tsx` 及 `src/components/debug/` 的页面组合和展示层；
- 必要的 Debug 共享类型和只读数据适配；
- 正式 Debug 的 Renderer E2E 与相关 Unit；
- 本合同、质量门禁、进度和变更记录。

### 4.2 默认不修改

- Agent Loop、Prompt 正文、Provider 路由和模型行为；
- 权限规则、凭据存储、记忆写入和正式设置保存；
- Playground 候选、fixture 和 Playground 导航；
- 现有 Debug IPC 的语义。

### 4.3 升级条件

如果实现需要新增或修改 IPC、日志存储、权限判断、跨模块事件标识、Prompt / 资产聚合契约或运行时状态模型，必须先更新本合同技术方案和影响范围，再开始对应代码施工。

## 5. 实施步骤

1. **现状映射**：建立 Debug 分区、组件、IPC、主进程来源和现有测试的映射表。
2. **信息架构候选**：只在 Debug 设计候选中验证运行概览、证据明细和受控动作的层级，不改变真实数据。
3. **用户验收**：确认默认入口、分区命名、信息密度、状态表达和关键跳转。
4. **正式 UI 实施**：在 `DevPanel` 和正式 Debug 子组件中选择性重排，保持现有 IPC 和数据边界。
5. **行为验证**：补齐正式入口、数据加载、错误、空态、脱敏、关联跳转、深浅主题、窄宽和键盘 E2E。
6. **受控动作评估**：只有有明确用户价值且能完成主进程校验、取消和审计的诊断动作才进入实现；其余留在只读展示。
7. **文档收口**：更新质量门禁、进度、变更日志和受影响模块卡；确认资产目录仍只登记真实生产来源。

## 6. 风险与权衡

- 运行概览可能重复 Settings 内容，必须展示“当前实际状态”，不能展示“用户默认设置”。
- 证据明细容易退化成原始 JSON，优先提供可读摘要、时间线和关联跳转，原始内容只作为受控展开。
- Debug 的诊断动作可能产生费用、写入日志或改变运行状态，默认只读，新增动作必须单独评估风险。
- Alice 的分组方式只能作为信息架构参考，不能替代本项目的 IPC、脱敏和权限契约。
- 如果现有 Trace、LLM 和 Event 缺少共同标识，不为视觉上的“统一时间线”伪造关联。

## 7. 必测点

- 默认进入 Debug 时能看到运行概览，并能进入真实证据明细；
- 每个展示区能定位到真实数据来源；
- LLM、Trace、Event 之间的关联存在时可跳转，不存在时明确说明；
- Prompt、资产、模型、工具、权限和 MCP 信息不泄露凭据或不必要的内部细节；
- 加载、空态、错误、长文本、窄宽、深浅主题和键盘焦点可用；
- 刷新失败不会清空已有可用证据，且错误可理解；
- Debug 不写入 Settings、记忆、会话或 Playground fixture；
- 任何受控诊断动作都有主进程校验、取消 / 失败反馈和审计证据；
- Playground 与正式 Debug 的边界没有被 UI 复用意外打穿。

## 8. 完成判定

在用户确认信息架构候选、正式 Debug 入口和真实证据映射成立前，本合同不得进入正式 UI 实施。完成后，必须满足：正式 UI 仅展示真实生产事实；测试覆盖关键状态和安全边界；文档已同步；未实现的诊断能力继续明确登记为缺口，而不是用静态按钮占位。
