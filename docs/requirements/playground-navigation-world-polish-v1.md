# Playground 导航与生活面精修 v1 施工合同

> 状态：进行中（2026-08-28）
> 生命周期：Phase P0 候选已获回流许可；本合同继续指导正式 UI 回流与 Playground 边界验收，尚未冻结。
> 统一称呼：施工合同

## 1. 需求背景（Why）

上一轮页面基线已经解决了候选 Sidebar、静态文件样张、朋友圈样张和 Toast 的基础验收，但人工查看后仍有三类结构问题：Playground 左侧把任务域、页面目的和组件子分类叠成了二级导航，信息层级过多；Right Dock 把文件树和预览上下堆叠，且文件 / 审阅 / 终端默认像真实生产工具；朋友圈仍保留重复的“生活广播”标题和独立 Catch-up 卡，不像微信朋友圈的内容流；记忆分类颜色过多，削弱了结构识别。

本轮继续只做 Playground P0。参考 Alice 的朋友圈方法论与源码：展示层是人格生活事件的派生视图，采用社交动态卡片、克制的时间与互动信息、近期窗口声明；导航采用单一侧栏和一级目的地，不在页面内再嵌套一套导航。

## 2. 功能目标（What）

1. Playground 导航收敛为三个工作域：基础、产品体验、Agent 实验；基础与产品体验形成“基础生产 → 成品组合”的两层关系，Agent 实验保持独立。
2. 基础工作域只负责设计语言、图标与视觉资产、基础组件；产品体验工作域只负责页面、业务场景和状态组合，禁止在业务页复制基础组件实现。
3. 产品体验开发若发现基础能力缺失，必须先回到基础组件工作台建立、登记并验收，再引用回成品。
4. Playground 导航改为设置式一级目的地：所有设计故事和 Agent 实验直接作为侧栏一级入口；组件故事不再在“组件”页面内再开一层子导航。
5. Right Dock Playground 候选采用四种可添加 Tab：文件、预览、审阅、终端；默认只打开预览，文件 / 预览 / 审阅 / 终端都可通过右侧“+”重复添加多个实例，“+”位于关闭按钮左侧。
6. Right Dock 候选中预览单独成为一个 Tab，文件 Tab 只展示文件树；审阅、终端使用隔离静态占位，不默认连接真实能力。
7. 人物世界候选去掉重复的朋友圈标题行和 Catch-up 独立卡，借 Alice 的人物头图 / 身份收束、单一内容导航和社交流动态节奏，改为更接近微信朋友圈的社交动态流：头像 / 主角名、正文、相对时间 / 地点和互动信息；底部保留轻量近期内容声明。头图与卡片仅作为 Playground 视觉候选，不引入生产图片资产。
8. 记忆候选只保留三种主色，其他记忆类型统一使用灰色，筛选与卡片颜色保持同一语义。
9. Chat 壳候选不再单独保留“新对话”顶部框，欢迎区直接承接主内容；侧栏的新对话入口保持不变。
10. 把“持久目的地必须是一级界面，不在页面内嵌套二级导航”的规则写入 `agent-skills/frontend-guidelines.md`。
11. 建立产品体验依赖门禁：体验必须声明使用的基础组件，阻止不存在、非基础层或生命周期不兼容的引用，并从注册表派生依赖关系。
12. Playground 进入后替换产品主壳，像设置一样使用独立全屏的单一侧栏 + 内容区，不再与 Primary Sidebar 叠成双层导航。
13. 删除页面顶部重复的用途说明块、基础组件“组件索引”和全局“显示已采用”开关；采用标记只允许落到有直接 sourcePaths 证据的具体资产；图标采用状态由 icon registry 单项登记。
14. 图标目录压缩为“图标 + 中文名 + 灰色英文名”，语义 key、用途和优先级继续保留在注册数据中，但不占用目录卡片空间。

## 2.1 Playground 资产与 Tab 归属（本轮固化）

Playground 只保留两个产品设计层，并把 Agent 实验作为独立工作域：

```text
基础 Foundation
├─ 设计语言：颜色、主题、圆角、动效
├─ 图标与视觉：可复用 Lucide 图标资产
└─ 基础组件：按钮、输入、工具卡、空态、错误、提示、Tabs 等可脱离业务复用的能力

产品体验 Experience
├─ Chat：伙伴身份、会话、欢迎区、消息流
├─ 人物世界：朋友圈、物什、名册
├─ 记忆：列表、筛选、敏感项、编辑、记忆引用
├─ 设置：分组、字段、自动保存、恢复
├─ 工作区：文件、预览、审阅、终端
└─ 业务状态：空态、确认、错误与反馈的业务组合

Agent 实验（独立工作域）
└─ 对话试验、模型能力、工具手测
```

这里的“基础 / 产品体验 / Agent 实验”是 Playground 的工作域分组，不是新增的第三层产品架构。产品体验只能引用已登记的 Foundation 资产；缺少基础能力时，先在基础工作域建立故事、登记真实来源、通过候选验收，再回到产品体验组合。

业务专属结构（例如伙伴状态条、角色架、生活事件卡、角色卡、记忆引用芯片、完整右侧工作坞）登记为 Experience，不得塞进 Foundation 组件目录。右侧工作坞只复用基础的 Tabs、文件树、分栏等能力。

### Tab 事实表

| 工作域 | 一级 Tab | 页面内允许的内容 | 不允许放入 |
|---|---|---|---|
| 基础 | 设计语言 | 颜色、主题、圆角、动效 | 业务组合实验、记忆或人物状态 |
| 基础 | 图标与视觉 | 图标 + 中文名 + 灰色英文名；分类筛选 | raw key、用途正文、整组采用标记 |
| 基础 | 基础组件 | 组件故事和边缘态 | 记忆芯片、伙伴状态条等业务结构 |
| 产品体验 | Chat | Chat 组合与状态 | 复制通用基础组件实现 |
| 产品体验 | 人物世界 | 朋友圈 / 物什 / 名册三个并列 Tab；角色架归入设置 | 额外二级页面导航 |
| 产品体验 | 记忆 | 记忆业务流与引用 | 把记忆业务组件伪装成 Foundation |
| 产品体验 | 设置 | 设置分组与自动保存组合 | 保存按钮或假语言设置 |
| 产品体验 | 工作区 | 文件 / 预览 / 审阅 / 终端四个 Dock Tab | 默认连接真实终端或审阅数据 |
| 产品体验 | 业务状态 | 业务语义下的状态组合 | 维护第二份基础组件实现 |
| Agent 实验 | 对话试验 / 模型能力 / 工具手测 | 隔离试验输入、结果和边界 | 写入真实会话、生产资产或设置 |

## 2.2 Foundation 基础模块补齐范围（2026-08-23）

本轮将“基础组件”定义为**可直接查看和操作的 Foundation 预览入口**，不再把资产登记清单堆在预览页中：

- 已建立故事的 Foundation 资产必须在基础组件工作台拥有可点击的故事 Tab，至少覆盖：按钮、输入框、标签切换、工具调用卡、提示条、空状态、加载指示器、权限确认、错误反馈、Markdown 渲染、资产目录、文件树和分栏拖拽。
- 基础组件工作台只展示真实预览、隔离样张和必要的来源证据；不再显示“已建立故事 / 候选能力 / 共 N 项”的文字资产总览，也不把没有预览的候选项堆在页面底部。
- 完整资产登记、候选状态和来源仍由 `src/shared/ui-component-registry.ts` 维护，并在 Debug 资产目录中查看；这不等于从生产注册表删除资产。
- Foundation 工作台的故事必须使用正式组件、正式 class 或明确隔离 fixture；不读取真实会话、设置、文件或 Agent 运行数据。
- 新增 Foundation 资产时，必须同时补齐：注册表项、可交互故事或明确候选登记、基础层级测试、Playground E2E 和文档事实。

## 2.3 Playground 布局收口范围（2026-08-23）

本轮不新增页面层级，解决的是“同一页面内部的密度、容器和信息层级不一致”：

- Playground 壳提供唯一的页面标题栏：显示工作域、当前一级 Tab 和一句中文目的说明；内容面不再由每个面板重复伪造页面标题。
- 主内容采用统一的 `max-w-6xl + w-full` 容器；面板不得再各自使用互相冲突的 `max-w-4xl / max-w-5xl`，避免页面宽度跳变。
- 一级导航保持单一侧栏；内容里的 Tab 只承担同一页面内的故事 / 场景筛选，不再出现“页面标题 + 说明块 + 外层故事卡 + 内层故事卡”的多重包裹。
- Foundation 故事在数据层保留“基础控件 / 状态反馈 / 开发基础”三组归类，但界面只呈现一条无分组标题的可横向滚动状态切换行；产品体验页按“页面组合 / 业务状态”展示。分组只是视觉整理，不新增路由或二级页面。
- 完整资产总览、候选状态和来源属于开发者证据层，由注册表 / Debug 展示；Playground 只在具体预览卡上保留必要的来源和采用标记，不抢占故事预览的主视觉。
- 页面基线、业务样张和组件故事统一使用同一套间距、标题、边框和滚动规则；窄宽时优先横向滚动 Tab 条，不让内容卡片被压缩成难读的窄列。
- 壳层页头是本轮布局唯一新增的页面级说明；面板内部只保留故事导航、证据摘要和预览，不再重复页面标题。

验收核心：进入任意 Playground 一级 Tab 后，用户先看到“我在哪 / 这里验收什么”，再看到一套稳定宽度的故事内容；不因为切换基础、体验或 Agent 实验而改变主内容的左右边界。

## 2.4 Foundation 常用与候选组件补齐范围（2026-08-24）

本轮在不改变正式页面默认行为的前提下，补齐当前已使用控件和已批准探索控件的隔离故事：

- 已使用或高频基础控件：下拉选择、表单字段、复选框、开关、差异查看器。
- 已批准探索的候选控件：对话框、弹出层、下拉菜单、可搜索选择、命令面板、右键菜单、滚动区域、提示浮层、骨架屏、进度条。
- 候选故事可以使用静态 fixture、原生控件和现有 CSS 规则表达交互形态，但不因此变更为 `adopted`，也不引入未确认的第三方依赖。
- Foundation 工作台的完整故事入口必须有可见预览；注册表继续记录稳定 key、候选来源、故事范围和无障碍约束，Debug 继续承担完整资产登记。
- 本轮补齐完成后，后续施工转入 Foundation token、密度、焦点、禁用、错误、窄宽和深浅主题的统一样式验收，不再继续扩大基础组件目录，除非出现新的真实产品场景。

## 2.5 Foundation 故事一致性架构（2026-08-24）

Foundation 不再让资产注册表、Playground catalog 和渲染分支各自维护故事事实：

- `src/shared/ui-component-registry.ts` 是组件资产事实源，记录组件身份、来源、采用生命周期和无障碍约束。
- `src/shared/foundation-story-registry.ts` 是 Playground 故事事实源，记录稳定 `story key`、`viewId`、`assetKey`、视觉分组和 renderer 类型。
- `catalog.ts`、Foundation 工作台分组和工作台资产摘要只能从故事注册表派生；不能再手写一份完整 Foundation Tab 列表。
- `UiControlsPanel.tsx` / `FoundationAdvancedStories.tsx` 是 renderer 实现面；注册表的 renderer 类型必须能在对应源码中找到覆盖证据。
- 一致性门禁必须阻止：不存在的 assetKey、非 Foundation assetKey、重复 story key / viewId、无 renderer 分支和工作台摘要漂移。

## 2.6 Playground 基础视觉减噪（2026-08-24）

- 一级页面页头只保留当前页面标题和用途说明，移除重复工作域标签与“隔离实验”徽标。
- 图标尺寸故事必须把同一语义图标按 12 / 14 / 16 / 20 实际展示；搜索默认收起为图标按钮，展开后才显示输入框。
- 设计语言的 motion token 必须提供可交互动画样张，不能只显示 CSS 变量文本；Token 展示不增加没有实际用户流程的手动重新读取按钮。
- Markdown 渲染故事的代码块必须使用独立于页面底色的 Foundation 层级色；该视觉只通过 Playground variant 验收，不改变正式 Chat 默认样式。
- 产品体验页面只就近显示当前体验声明的 Foundation 依赖；体验组成由页面自身表达，不再额外生成一层通用摘要。
- Playground 样张不得出现特定伙伴或外部参考产品名称，避免把参考对象误读为产品事实。

## 2.7 页面组合与图标目录减层（2026-08-25）

- Chat 页面组合样张不再单独渲染“页面组合样张 + source”说明行；样张来源与“标准宽度 / 分栏窄宽”切换合并为同一条紧凑工具行。
- 图标目录的数量统计与目录标题同行展示，不再占用搜索区域的独立高度；搜索仍默认收起为放大镜。
- 这些调整只改变 Playground 信息层级，不改变正式 Chat、Sidebar 或图标生产使用方式。

## 2.8 图标目录头部收口（2026-08-26）

- 图标搜索按钮 / 展开后的搜索框与目录标题、数量统计放在同一头部行，不再在目录内容区单独占一行。
- Playground 图标目录不展示 `src/shared/icon-registry.ts` 路径；稳定 key、来源和采用证据继续由注册表与 Debug 保留，开发者不需要在视觉目录中承担这类实现细节。
- `StoryBlock` 仅在确实需要定位实现时展示 source，并支持头部操作；该能力不改变其他故事格的来源证据。

## 2.9 Chat 页头与来源证据归位（2026-08-26）

- Chat 页头将用途说明放在 `Chat` 标题右侧，同一行表达页面名称与目的，避免标题下再单独占一层说明。
- Chat 的实现来源路径移入页头“基础引用”行的最右侧；组合样张下方只保留标准宽度 / 分栏窄宽切换，不重复展示 `.tsx` 路径。
- 来源仍由产品体验注册表维护并展示在 Debug / 资产治理链路中；本调整只改变 Playground 的信息分布，不改变正式页面或生产资产。

## 2.10 Playground 控件与故事导航收口（2026-08-26）

- Lucide 目录将 `.ts` 来源路径放在放大镜左侧，过长时单行省略并通过 `title` 保留完整路径；图标尺寸不再单独占一张重复故事卡，改为目录内的 12 / 14 / 16 / 20 固定值 + 可拖动自定义滑杆。
- 设计语言的圆角增加自定义滑杆与实时样张；motion 样张自动播放，时长值与 token 名同行展示，不再要求手动点击播放。
- Foundation story 注册表增加导航分组字段；基础组件页只展示较少的任务 Tab，但每个 Tab 仍渲染其分组下全部 story，不能删掉细粒度资产或 renderer 覆盖。
- 所有产品体验页的 sourcePaths 统一在页头基础引用行最右侧展示，过长省略并通过 hover 保留完整值；组合样张下不再重复显示来源。

## 2.11 Alice 基础组件对照与本轮补齐（2026-08-27）

参考 `_reference/framework-harness/repos/alice-source/_extract/page-playground.js` 的基础组件展示后，本轮只迁移与当前产品真实边界匹配的通用能力，不复制 Alice 的业务语义，也不为了目录数量引入新依赖：

- **补齐到 Foundation Playground**：图标按钮 `IconButton`、通用卡片 `Card`、徽标 `Badge`、标签 `Tag`、分隔线 `Divider`。它们均以隔离 fixture 建立可见预览，当前生命周期为 `playground`。
- **继续保留已有故事**：按钮、输入与表单、标签与选择、弹层、菜单与提示、状态反馈、加载与进度、工具卡、Markdown 与资产、文件与差异、滚动区域和分栏拖拽。
- **暂不单独补入**：`ToggleRow`、`NavItem`、`ThemePicker`、划词工具条和 `Kbd`。这些要么属于产品体验组合，要么当前没有稳定产品契约；若未来出现跨场景复用需求，必须先重新登记为 Foundation 候选。
- **导航原则**：13 个基础组件入口按组件数量、预览空间和开发者任务拆分；入口只是筛选，不删除底层 story。每个 story 必须同时存在于 `foundation-story-registry.ts`、对应 renderer 和 Renderer E2E 证据中。

本节是本轮补齐的边界记录；后续工作转入已登记 Foundation 组件的统一样式验收（token、密度、焦点、禁用、错误、窄宽、深浅主题），除非新的真实产品场景改变范围。

## 2.12 Playground → 正式 UI 回流（2026-08-28）

用户已明确授权将本合同中已经确认的视觉与真实产品交互回流正式页面。本轮回流范围收敛为四项：

- Markdown 代码块统一使用 `--bg-tertiary` 层级色，避免浅色主题下出现白底代码块；
- 正式记忆页使用 `accent`、`warm`、`success`、`muted` 四类语义色，分类之外的颜色不再承担记忆类型表达；
- 正式人物世界默认使用朋友圈式 `social-feed`，隐藏重复标题，保留真实动态、时间 / 地点、互动和近期窗口说明；
- 正式 Chat 右侧工作坞默认显示“预览”，通过“+”按需添加“文件 / 预览 / 审阅 / 终端”，并让文件与预览共享当前选中文件。审阅和终端仍连接真实正式组件，不使用 Playground 隔离占位。

以下内容继续只属于 Playground：`.tsx` 来源路径、采用标记、组件 / 资产目录、尺寸和圆角调试滑杆、隔离 fixture、静态审阅 / 终端占位、候选故事和开发者证据层。它们不得因为本轮回流而出现在正式产品 UI，也不得将候选资产自动标记为 `adopted`。

回流验收必须覆盖：正式 Chat 右坞默认态、文件 → 预览的上下文保持、审阅 / 终端真实调用边界、Markdown 深浅主题代码块、记忆四类语义色、人物世界默认朋友圈流，以及 Playground 既有隔离行为不回归。

## 3. 技术方案（How）

- `PlaygroundShell.tsx` / `catalog.ts` / `foundation-story-registry.ts`
  - 将导航重组为基础、产品体验、Agent 实验三个工作域；Playground 作为独立全屏 activeView，不再同时渲染产品 Primary Sidebar。
  - Foundation Tab、分组和故事顺序从 `foundation-story-registry.ts` 派生；组件资产注册表不再承担工作台故事摘要。
  - 原“设计令牌”入口改名为“设计语言”；移除设计语言中的“组合实验”；移除基础组件“组件索引”和全局目录级采用开关。
  - 基础组件工作台覆盖所有已建立 Foundation 故事：按钮、输入、标签切换、下拉选择、可搜索选择、表单字段、复选框、开关、对话框、弹出层、下拉菜单、命令面板、右键菜单、提示浮层、生成动作、工具调用卡、提示条、空状态、加载指示器、骨架屏、进度条、权限确认、错误反馈、Markdown 渲染、资产目录、文件树、差异查看器、滚动区域和分栏拖拽；完整候选登记由注册表 / Debug 展示，不在预览页重复堆叠。记忆引用、伙伴状态条等业务结构改由产品体验或业务状态展示。
  - 产品体验的 Foundation 依赖全部从注册表派生，放进统一页头的轻量元信息行，不泄漏 raw key；人物世界保留朋友圈、物什、名册三个并列 Tab，角色架移入设置样张。
  - 内容面去掉重复说明块；图标目录采用紧凑竖排网格，显示图标、中文名和灰色英文名；采用状态只在具体资产上表达。
- `ChatRightDock.tsx` / `FileBrowser.tsx`
  - 增加 Playground 专用 Dock 模式和文件浏览 `files` / `preview` 展示模式；正式模式启用预览默认 + 按需 Tab。
  - Playground Dock 的审阅 / 终端只显示静态占位，不调用 IPC 或真实会话；正式 Dock 保留 `ReviewPanel` / `TerminalPanel` 的真实调用链。
  - `FileBrowserPreviewState` 由正式 Right Dock 容器持有，文件 Tab 选择的文件在切换到预览 Tab 后继续可见。
- `MomentsPanel.tsx` / `WorldHub.tsx`
  - 增加只读社交流展示模式和隐藏重复标题的可选 props；正式默认采用 `social-feed` 并隐藏重复标题。
- `MemoryPanel.tsx`
  - 将分类颜色收敛为三种语义主色 + 灰色，保留分类 ID 和数据行为不变。
- `frontend-guidelines.md`
  - 增加一级界面、一级导航与内联状态筛选的边界规则。
- `ui-component-registry.ts` / `product-experience-registry.ts`
  - UI 资产增加 foundation / experience 层级；伙伴状态条、记忆引用芯片、生活事件卡、角色卡、完整工作坞等业务结构显式标为 experience。
  - 产品体验用稳定 key、真实 source、`experienceParts` 和 `usesFoundation` 声明组成与依赖；TypeScript 检查依赖 key，Unit 检查存在性、层级、生命周期、入口与源码。
  - 注册表从 `usesFoundation` 派生“使用的基础 / 被哪些体验使用”，体验组成也只维护在产品体验注册表，不在 Playground 复制第二份清单。

## 4. 影响范围

- 修改：Playground 一级导航候选、基础 / 产品体验注册层级、Right Dock / FileBrowser 展示模式、正式人物世界默认展示、正式记忆颜色语义、Markdown 代码块层级色、图标目录、产品体验依赖摘要、前端协作规范、Renderer E2E、施工合同与进度 / 质量文档。
- 不改：正式 Primary Sidebar、正式 Playground 入口、正式记忆数据与 IPC、LLM、Prompt、会话与写盘；Playground 的来源路径、采用标记、目录、调试滑杆和隔离 fixture 不进入生产。
- Playground 专属差异必须显式传入；生产新增默认行为必须由真实数据 / IPC 契约、状态共享和 E2E 证据支撑。

## 5. 实施步骤

1. 建立“基础 / 产品体验 / Agent 实验”一级工作域，按 Tab 事实表收口入口职责。
2. 将 Chat、人物世界、记忆、设置、工作区拆为可直接进入的产品体验候选，人物世界的朋友圈、物什、名册三个业务 Tab 并列可切换，角色架归入设置。
3. 将原“设计令牌”入口改名为“设计语言”，删除设计语言组合实验；基础组件移除业务专属故事。
4. 增加 Right Dock 四 Tab 的隔离候选和预览独立 Tab，允许同类型多实例，关闭当前实例后仍可继续添加。
5. 将朋友圈样张改为社交动态流，删除重复标题与 Catch-up 卡。
6. 收敛记忆颜色，并验证产品体验只通过基础工作台提供的故事组合。
7. 建立产品体验依赖注册表、生命周期门禁，并把当前体验的 Foundation 依赖放进统一页头元信息行。
8. 移除重复说明块、组件索引、目录级采用标记和全局开关，压缩图标目录。
9. 补 Renderer E2E、浅色 / 深色、窄宽和关键交互证据；取得用户回流许可后，将确认的视觉与真实交互选择性回流正式 UI。
10. 回流完成后更新模块卡、架构 / 质量 / 进度 / 变更日志和前端回流 Skill；保留本合同继续指导边界验收，待人工验证完成后再冻结。

## 6. 风险与权衡

- 一级路由数量会增加，但每个入口的认知成本下降，且设置式侧栏更适合开发者定位；任务域标题只做分组，不承担导航嵌套语义。
- Right Dock 的“+”在 Playground 和正式工作坞都承担按需添加 Tab 的职责；同一种 Tab 可以按任务重复打开多个实例，关闭只影响当前实例。正式模式默认预览，Playground 模式默认仍是隔离样张。
- Alice 的社交流视觉可以迁移结构和层级，不能复制其产品语义或虚构数据来源；样张仍必须明确是 Playground fixture。
- 颜色收敛只改变视觉语义，不改变记忆分类、敏感项检测或存储行为。

## 7. Phase P0 验收标准

- Playground 进入后产品 Primary Sidebar 消失，只保留与设置一致的单一侧栏 + 内容区；返回后恢复产品主壳。
- 页面内容顶部不再重复显示用途说明块；基础组件没有“组件索引”Tab，全局没有“显示已采用”开关，目录标题不批量附加采用标记。
- 图标目录卡片只显示小尺寸图标、中文名和低对比英文名，不显示 `navigation.*` key、用途正文或 P0 / P1。
- Right Dock 初始只有“预览”Tab；点击“+”可重复添加文件、预览、审阅、终端，“+”位于关闭按钮左侧；候选不触发真实 IPC。
- 朋友圈候选无重复“生活广播”标题和 Catch-up 卡；顶部有轻量人物头图 / 身份信息，下面是单一的朋友圈 Tab 导航和至少三条社交动态卡；动态使用相对时间、正文、地点 / 互动与底部近期声明。动态正文下方的赞 / 评论采用微信朋友圈式紧凑互动行：带 Lucide 心形 / 气泡图标、轻量分隔线、左对齐；赞可切换状态，评论按钮在隔离样张中只呈现选中态，不伪造生产写入。
- 记忆候选视觉上只出现三种主色与灰色。
- Chat 壳候选主内容区不再出现独立“新对话”顶部框，侧栏的新对话入口保持不变；欢迎区的“打个招呼 / 今天想怎么过？”进入正在聊天，“看看朋友圈”进入人物世界；处理任务展示隔离工作区，并可通过“回到对话”收起工作区，形成可实际走通的 Playground 用户旅程。
- 每个活跃产品体验都存在注册项和基础依赖；不存在、非 foundation 或生命周期不兼容的依赖会使测试失败。
- 产品体验的当前 Foundation 依赖显示在统一页头元信息行；业务结构和基础依赖都从注册表派生，不维护 Playground 第二份清单。所有一级 Tab 统一采用标题 / 用途同行、来源第二行右对齐的页头；真实 `.tsx` 路径固定宽度省略，hover/title 查看完整值。
- 基础注册表中不再出现记忆芯片、伙伴状态条、生活事件卡和角色卡等业务结构；它们只能在产品体验或业务状态中出现。Foundation 工作台必须覆盖全部已建立故事；候选和完整资产清单由注册表 / Debug 提供，不在预览页制造无预览文字区。
- 浅色 / 深色、窄宽和关键交互均有 Renderer 证据；正式页面默认行为未改变。
## 8. 正式 UI 回流验收标准（2026-08-28）

- 正式 Chat 右坞打开后默认只有“预览”；“+”可以添加文件、预览、审阅、终端，同类 Tab 可重复添加。
- 正式文件 Tab 只显示文件树，选择文件后切换到预览 Tab，文件名和内容仍保持；正式审阅 / 终端不出现隔离样张文案。
- 正式 Markdown 代码块在浅色和深色主题下使用独立层级色；正式人物世界默认是朋友圈式动态流；正式记忆颜色只使用四类语义色。
- Playground 原有 12 个场景 / 13 个基础入口、隔离 fixture 和候选边界不回归。
