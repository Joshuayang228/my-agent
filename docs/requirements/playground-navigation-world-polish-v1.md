# Playground 导航与生活面精修 v1 施工合同

> 状态：进行中（2026-08-19）
> 生命周期：Phase P0 候选施工；未取得用户明确回流许可前，不改变正式页面默认行为。
> 统一称呼：施工合同

## 1. 需求背景（Why）

上一轮页面基线已经解决了候选 Sidebar、静态文件样张、朋友圈样张和 Toast 的基础验收，但人工查看后仍有三类结构问题：Playground 左侧把任务域、页面目的和组件子分类叠成了二级导航，信息层级过多；Right Dock 把文件树和预览上下堆叠，且文件 / 审阅 / 终端默认像真实生产工具；朋友圈仍保留重复的“生活广播”标题和独立 Catch-up 卡，不像微信朋友圈的内容流；记忆分类颜色过多，削弱了结构识别。

本轮继续只做 Playground P0。参考 Alice 的朋友圈方法论与源码：展示层是人格生活事件的派生视图，采用社交动态卡片、克制的时间与互动信息、近期窗口声明；导航采用单一侧栏和一级目的地，不在页面内再嵌套一套导航。

## 2. 功能目标（What）

1. Playground 导航收敛为三个工作域：基础、产品体验、Agent 实验；基础与产品体验形成“基础生产 → 成品组合”的两层关系，Agent 实验保持独立。
2. 基础工作域只负责设计令牌、图标与视觉资产、基础组件；产品体验工作域只负责页面、业务场景和状态组合，禁止在业务页复制基础组件实现。
3. 产品体验开发若发现基础能力缺失，必须先回到基础组件工作台建立、登记并验收，再引用回成品。
4. Playground 导航改为设置式一级目的地：所有设计故事和 Agent 实验直接作为侧栏一级入口；组件故事不再在“组件”页面内再开一层子导航。
5. Right Dock Playground 候选采用四种可添加 Tab：文件、预览、审阅、终端；默认只打开预览，文件 / 审阅 / 终端通过右侧“+”添加，“+”位于关闭按钮左侧。
6. Right Dock 候选中预览单独成为一个 Tab，文件 Tab 只展示文件树；审阅、终端使用隔离静态占位，不默认连接真实能力。
7. 人物世界候选去掉重复的朋友圈标题行和 Catch-up 独立卡，改为更接近微信朋友圈的社交动态流：头像 / 主角名、正文、时间 / 地点和互动信息；底部保留轻量近期内容声明。
8. 记忆候选只保留三种主色，其他记忆类型统一使用灰色，筛选与卡片颜色保持同一语义。
9. Chat 壳候选不再单独保留“新对话”顶部框，欢迎区直接承接主内容；侧栏的新对话入口保持不变。
10. 把“持久目的地必须是一级界面，不在页面内嵌套二级导航”的规则写入 `agent-skills/frontend-guidelines.md`。

## 3. 技术方案（How）

- `PlaygroundShell.tsx` / `catalog.ts`
  - 将导航重组为基础、产品体验、Agent 实验三个工作域；基础组件和业务状态在各自工作台内用筛选切换故事。
  - 产品体验页面按 Chat、人物世界、记忆、设置、工作区直接进入，页面组合不再通过第二套页面导航承载。
  - 基础组件工作台展示基础故事；产品体验工作台只展示业务组合，缺失能力回流基础侧。
- `ChatRightDock.tsx` / `FileBrowser.tsx`
  - 增加 Playground 专用 Dock 模式和文件浏览 `files` / `preview` 展示模式；默认生产模式保持现状。
  - Playground Dock 的审阅 / 终端只显示静态占位，不调用 IPC 或真实会话。
- `MomentsPanel.tsx` / `WorldHub.tsx`
  - 增加只读社交流展示模式和隐藏重复标题的可选 props；正式默认展示路径不变。
- `MemoryPanel.tsx`
  - 将分类颜色收敛为三种主色 + 灰色，保留分类 ID 和数据行为不变。
- `frontend-guidelines.md`
  - 增加一级界面、一级导航与内联状态筛选的边界规则。

## 4. 影响范围

- 修改：Playground 一级导航候选、Right Dock / FileBrowser 可选展示模式、朋友圈候选展示、记忆颜色、前端协作规范、Renderer E2E、施工合同与进度 / 质量文档。
- 不改：正式 Primary Sidebar、正式 Playground 入口、正式 Right Dock 默认 Tab、正式 Moments 标题与 Catch-up 数据流、正式记忆数据与 IPC、LLM、Prompt、会话与写盘。
- 所有新增展示模式必须显式传入；未传入时继续使用生产默认行为。

## 5. 实施步骤

1. 建立“基础 / 产品体验 / Agent 实验”一级工作域，基础组件与业务状态改为工作台内筛选。
2. 将 Chat、人物世界、记忆、设置、工作区拆为可直接进入的产品体验候选，去掉页面组合内部导航。
3. 增加 Right Dock 四 Tab 的隔离候选和预览独立 Tab。
4. 将朋友圈样张改为社交动态流，删除重复标题与 Catch-up 卡。
5. 收敛记忆颜色，并验证产品体验只通过基础工作台提供的故事组合。
6. 补 Renderer E2E、浅色 / 深色、窄宽和关键交互证据，停留在 Playground P0。

## 6. 风险与权衡

- 一级路由数量会增加，但每个入口的认知成本下降，且设置式侧栏更适合开发者定位；任务域标题只做分组，不承担导航嵌套语义。
- Right Dock 的“+”是候选态的 Tab 管理交互，不代表已经改变正式产品的默认工具可见性。
- Alice 的社交流视觉可以迁移结构和层级，不能复制其产品语义或虚构数据来源；样张仍必须明确是 Playground fixture。
- 颜色收敛只改变视觉语义，不改变记忆分类、敏感项检测或存储行为。

## 7. Phase P0 验收标准

- Playground 侧栏没有“组件 → 子页面”或页面内第二套导航；按钮、输入、系统反馈、图标等都是一级入口。
- Right Dock 初始只有“预览”Tab；点击“+”可添加文件、审阅、终端，“+”位于关闭按钮左侧；候选不触发真实 IPC。
- 朋友圈候选无重复“生活广播”标题和 Catch-up 卡，至少有两条社交动态样张和底部近期声明。
- 记忆候选视觉上只出现三种主色与灰色。
- Chat 壳候选主内容区不再出现独立“新对话”顶部框，侧栏的新对话入口保持不变。
- 浅色 / 深色、窄宽和关键交互均有 Renderer 证据；正式页面默认行为未改变。
