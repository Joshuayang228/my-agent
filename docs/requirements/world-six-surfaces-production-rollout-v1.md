## 1. 背景与授权（Why）

完工边界（2026-10-08）：六面正式入口、真实维护 / 换装 / 关系读取、角色与异步隔离、受控媒体和备份恢复已验收；Playground 控制器、样张头像 / 配图及自动补造事实不回流。完整 Unit 1326 项、UI 459 项、提交文件快照真实 Electron 24 项、资产 40 项通过，根类型和构建通过。主进程独立类型债 WISH-043 及既有并发超时仍保留，不宣称这些范围外问题已修复。下文“当前落差 / 施工中 / 尚未完成”描述属于开工与分项验收时记录，不代表完工能力。

用户已逐面确认 Playground 的人物世界体验，并明确要求“不是只是通讯录的，人物世界要全部回流”。本轮对象是朋友圈、衣柜、文化角、家居、通讯录、足迹及其共同壳层，不是单独替换通讯录，也不是整个 Playground 回流。

当前正式页面已有资产、生活事件、朋友圈、名册、真实生图和备份链，但部分候选交互只在隔离内存中存在。仅复制样式或注入样张无法满足正式使用，因此需要同时补齐必要的数据契约、持久化与失败恢复。

旧 `companion-world-model-v1.md` 是冻结快照，不作为这轮候选已正式采用的证据。本合同以当前调用链审计为准，不重写该历史快照。

## 3. 明确不做

- 不回流 Chat、设置、工作区、Debug 或设计语言页面的其他候选。
- 不将场景切换器、源码路径、实验标记、滑块或隔离 fixture 写入正式 UI。
- 不将生成头像、住所、旅行、默认套装或文化样张自动写入角色资料；正式默认内容须来自已确认 Role Pack / 默认世界。
- 不编造人物经历、首次相识日期、观后感、笔记、旅行时间或住所；缺失可选资料不创建假栏目。
- 不自动在打开页面、切分类或刷新时生图；保留明确触发、费用边界和真实失败状态。
- 不实现地图、室内平面图、实时定位、全天行程日志、播放器或通讯录增改删入口。
- 不修改 Agent Loop、生产人格 Prompt 或删除底层召唤能力；若需要 Agent 写入新事实，另列明确工具 / 服务契约并确认。
- 不清空当前开发数据，也不覆盖其他 Agent 未提交改动。DEC-042 不构成本轮批量重置授权。

### 4.2 数据与接口要求

先复用现有 `companion_assets`、事件关联、受控图片读取、生图归属与备份链；不得为方便展示建第二套生活事实库。以下是所需语义，不代表现有接口已支持：

- 穿搭：角色归属、稳定套装 ID、分类槽位与衣物 ID 引用；换整套一次提交，失效 / 跨角色引用拒绝，失败不改变当前穿着。配图绑定穿搭内容版本，不沿用不匹配的旧图。
- 文化：作品稳定 ID、分类与状态；笔记各自拥有 ID、作品引用、正文与可选日期 / 页码。列表摘要从详情同一数据推导；缺省作者或状态不伪造。
- 家居：住所 / 空间稳定 ID、总览与空间图引用；物件有可空空间引用和展示依据。无归属物件不冒充某个房间内物件。
- 通讯录：人物与伙伴关系分离；介绍、如何认识与相处方式可选；共同经历按双方 ID 与稳定经历 ID 隔离，不能用召唤会话历史冒充生活经历。
- 旅行：稳定旅行 ID、标题、目的地、可选起止日期、计划 / 进行中 / 完成 / 取消状态、故事与独立停留记录。只有已出发的进行中 / 完成记录进入足迹；日常咖啡店访问不自动转为旅行。
- 关联：朋友圈、旅行和共同经历引用目标稳定 ID；从当前角色作用域解析，缺失或跨角色引用不提供死链接；正文不复制维护。

新增或修改 IPC 时同步 `src/shared/types.ts`、preload、主进程 handler、`src/vite-env.d.ts`。落库前补结构校验、角色归属校验、引用存在性校验；载入失败、写入失败、重复点击、切换角色和过期异步响应均须有明确处理。

用户已通过“启动目标模式，把这个人物世界回流了”确认本合同。字段实现统一在 `src/shared/world-records.ts` 登记：衣柜沿用 `wardrobe` kind，以 recordType 区分衣物 / 套装 / 当前穿搭，slots 引用衣物 ID；文化沿用 culture / bookshelf，readingNotes 数组保留稳定 ID、正文和可选日期 / 页码；家居沿用 home / furniture，登记空间引用与展示依据；旅行沿用 footprint，以 recordType=trip 区分地点记录，登记起止日期、状态、目的地、故事与 stops 数组。现有短字段和媒体元数据不被复制为另一套事实源，新增字段通过共享校验后才能保存；跨实体引用与换衣原子操作仍须在服务层验证，字段校验本身不能替代它们。

新增 IPC 名称、Agent 维护入口及其他新字段在施工时记录具体差异；本合同不授权自动扩写人物事实。

衣柜换装具体接口（2026-10-08）：`companion:change-wardrobe` / `changeWardrobe` 输入 `CompanionWardrobeChangeInput`（roleId、assetId、expectedVersion），输出 `CompanionWardrobeChangeResult`。当前穿搭复用 wardrobe / wear-state 资产，单件按分类替换，整套一次替换 slots；同角色引用、分类、完整套装与版本在同步 SQL 写入前校验。通用创建 / 编辑不能绕过当前穿搭入口。套装槽位变化提升版本并删除不匹配旧图；真实生图在请求前捕获穿搭版本，`attachWorldAssetImage` 绑定时同步重读核验，迟到结果不覆盖新穿搭，不扩展生图 Prompt 或工具参数。接口已四处同步，页面接线和完整换装 UI 验收继续施工。

通讯录只读接口具体接线（2026-10-08）：`companion:get-contacts` / `getContacts` 返回 shared `CompanionContactsData`，人物浅层介绍、关系 note 和共同经历分开。共同经历复用现有 published 事件与 event_links：cast / coframe 或 person / participant 明确关联且人物在当前名册中才纳入，稳定经历 ID 为事件 ID + 人物 ID，朋友圈 / 旅行引用按同角色真实目标过滤。不新增关系数据库，不读取召唤会话、不改生产 Prompt、不自动补造相识故事或头像。IPC 四处同步并在读取后复核 activeRoleId；新 Agent 写入协议不在本轮接口内。
