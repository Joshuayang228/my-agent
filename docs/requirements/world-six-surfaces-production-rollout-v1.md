## 1. 背景与授权（Why）

用户已逐面确认 Playground 的人物世界体验，并明确要求“不是只是通讯录的，人物世界要全部回流”。本轮对象是朋友圈、衣柜、文化角、家居、通讯录、足迹及其共同壳层，不是单独替换通讯录，也不是整个 Playground 回流。

当前正式页面已有资产、生活事件、朋友圈、名册、真实生图和备份链，但部分候选交互只在隔离内存中存在。仅复制样式或注入样张无法满足正式使用，因此需要同时补齐必要的数据契约、持久化与失败恢复。

旧 `companion-world-model-v1.md` 是冻结快照，不作为这轮候选已正式采用的证据。本合同以当前调用链审计为准，不重写该历史快照。

## 2. 完整交付范围（What）

| 页面 | 已确认体验与正式交付目标 | 当前落差 / 施工边界 |
|---|---|---|
| 共同壳层 | 当前伙伴身份区；六个固定入口；带图标与边框的分类；共享边距、限宽、返回和形态 | `WorldHub` 正式分类仍走 underline；候选通过显式 props 和实验作用域呈现，需在人物世界内明确采用，不修改其他页面默认值 |
| 朋友圈 | 社交流、纯文字和多图网格、预览、点赞评论；hover 保留蒙版不显示放大镜；无“最近的生活动态”尾注 | 对照 `MomentsPanel` 的真实加载和互动链与候选差异，保留事件 / 生活切片入口，不以样张替换真实动态 |
| 衣柜 | 同行“正在穿着”、全部、套装、上装、下装、外套、鞋子；当前整套展示；库存和套装网格；单件 / 整套换上；图片预览 | `AssetsPanel` 的 gallery 与换上逻辑当前依赖 preview 数据，正式需要穿搭槽位、套装引用、原子更新、重载恢复和配图归属 |
| 文化角 | 书籍、影视、音乐、摄影，无全部；人物元信息与状态标签区分；详情与列表取同一感想；书籍多条笔记 | `WorldCultureContent` gallery 当前受 preview 开关限制，多条读书笔记由候选注入；需正式读取作品与笔记，不复制两份感想 |
| 家居 | 总览只放鸟瞰图；其后为真实空间；空间图下展示有意义物件；物件详情与图片预览 | 正式 `WorldHomeContent` 仍展示通用住所 / 物件列表；需空间引用及展示判断依据，不用当前活动冒充住所 |
| 通讯录 | 两列人物卡，窄宽一列；头像、姓名、关系与简介；整卡进入介绍 / 关系 / 共同经历详情；移除开聊、忙闲与召唤说明 | `getRoster` 只有关系短句与浅层人物资料；如何认识、相处方式和共同经历无完整正式契约，需要生产改造；不删除底层召唤服务 |
| 足迹 | 只记已出发旅行，一段旅行一条；进行中优先；详情展示故事与停留经历；返回恢复位置与焦点 | 正式 `WorldFootprintsContent` 仍以地点资产和动态为主；候选 `TravelPreview` 尚未进入正式存储，需旅行实体与事件关联 |

形态引用已确认语义 token：控件 / 输入 10px、卡片 16px、弹层 22px、胶囊全圆。人物世界应用共享内容边距与阅读限宽；返回沿内容区左边缘，不跟随居中正文偏移。分类图标沿用已确认的 lucide / Phosphor 组合，不保留图标实验选择器。

家居只展示有故事、有意义或能体现习惯的物件，由 Agent 根据真实资料与证据判断；不维护“某类家具永远展示 / 永远排除”的硬名单。未经判断的普通布置不能自动填满物件网格。

## 3. 明确不做

- 不回流 Chat、设置、工作区、Debug 或设计语言页面的其他候选。
- 不将场景切换器、源码路径、实验标记、滑块或隔离 fixture 写入正式 UI。
- 不将生成头像、住所、旅行、默认套装或文化样张自动写入角色资料；正式默认内容须来自已确认 Role Pack / 默认世界。
- 不编造人物经历、首次相识日期、观后感、笔记、旅行时间或住所；缺失可选资料不创建假栏目。
- 不自动在打开页面、切分类或刷新时生图；保留明确触发、费用边界和真实失败状态。
- 不实现地图、室内平面图、实时定位、全天行程日志、播放器或通讯录增改删入口。
- 不修改 Agent Loop、生产人格 Prompt 或删除底层召唤能力；若需要 Agent 写入新事实，另列明确工具 / 服务契约并确认。
- 不清空当前开发数据，也不覆盖其他 Agent 未提交改动。DEC-042 不构成本轮批量重置授权。

## 4. 技术方案（How）

### 4.1 回流映射与隔离

| 候选来源 | 正式落点 | 真实来源 | 迁移分类 |
|---|---|---|---|
| `SurfaceBaselinePanel.WorldSurface` | `App` 当前角色输入、`WorldHub` | activeRole 与当前角色资料 | 共享壳层直接回流 |
| `MomentsExperienceCandidate` / 朋友圈样张 | `MomentsPanel` | `getMoments`、互动与生活切片服务 | 保留真实链，回流展示差异 |
| `WardrobeCandidate` | `AssetsPanel` 与可复用衣柜展示组件 | 角色资产与真实穿搭状态 | 生产改造后回流 |
| `CultureExperienceCandidate` | `WorldCultureGallery` / `WorldDetailsPanel` | 文化资产、书目及笔记 | 生产改造后回流 |
| `HomeExperienceCandidate` | `WorldHomeGallery` / `WorldDetailsPanel` | 默认住所、空间与物件资产 | 生产改造后回流 |
| `ContactsExperienceCandidate` | 共享通讯录展示与正式加载层 | Role Pack、关系资料、角色限定事件关联 | 生产改造后回流 |
| `FootprintsExperienceCandidate` | 共享旅行展示与正式加载层 | 旅行记录、停留记录、事件关联 | 生产改造后回流 |

正式组件不得 import Playground。候选拆成共享纯展示、正式加载 / 写入层、Playground fixture wrapper 三层；两端复用显示逻辑，不复制一套皮肤。资产注册表的 adopted 状态只在正式调用、测试与文档成立后更新。

### 4.2 数据与接口要求

先复用现有 `companion_assets`、事件关联、受控图片读取、生图归属与备份链；不得为方便展示建第二套生活事实库。以下是所需语义，不代表现有接口已支持：

- 穿搭：角色归属、稳定套装 ID、分类槽位与衣物 ID 引用；换整套一次提交，失效 / 跨角色引用拒绝，失败不改变当前穿着。配图绑定穿搭内容版本，不沿用不匹配的旧图。
- 文化：作品稳定 ID、分类与状态；笔记各自拥有 ID、作品引用、正文与可选日期 / 页码。列表摘要从详情同一数据推导；缺省作者或状态不伪造。
- 家居：住所 / 空间稳定 ID、总览与空间图引用；物件有可空空间引用和展示依据。无归属物件不冒充某个房间内物件。
- 通讯录：人物与伙伴关系分离；介绍、如何认识与相处方式可选；共同经历按双方 ID 与稳定经历 ID 隔离，不能用召唤会话历史冒充生活经历。
- 旅行：稳定旅行 ID、标题、目的地、可选起止日期、计划 / 进行中 / 完成 / 取消状态、故事与独立停留记录。只有已出发的进行中 / 完成记录进入足迹；日常咖啡店访问不自动转为旅行。
- 关联：朋友圈、旅行和共同经历引用目标稳定 ID；从当前角色作用域解析，缺失或跨角色引用不提供死链接；正文不复制维护。

新增或修改 IPC 时同步 `src/shared/types.ts`、preload、主进程 handler、`src/vite-env.d.ts`。落库前补结构校验、角色归属校验、引用存在性校验；载入失败、写入失败、重复点击、切换角色和过期异步响应均须有明确处理。

具体 Schema、IPC 名称、Agent 维护入口及所需新文件，在实施前根据现有资产接口形成差异清单并确认；本合同不授权把可选新字段悄悄塞进任意 payload，也不授权自动扩写人物事实。

### 4.3 文件归属与影响

允许施工目录：`src/components/shell/WorldHub.tsx`、六面正式组件与 `src/components/world/`、对应 Playground wrappers、`src/shared/` 中相关类型 / 布局 / 注册表、`electron/main/companion/` 的生活资产与关系数据边界、companion IPC 四处、对应 Unit / E2E 和文档。

`App` 只调整人物世界 props / 入口接线，`src/index.css` 只调整人物世界 scoped 采用，不扩改全产品默认。数据库 schema / 备份若确需变化，必须列出具体受影响表、读写路径和恢复测试后确认。

当前这些目录存在大量未提交存量改动。施工前逐文件核对归属、最新版本和差异；无法区分归属时暂停该文件，不 stash、覆盖或混入本轮提交。

## 5. 实施步骤与验收

1. 逐面审计正式定义、调用方、真实数据、实际渲染和测试；冻结 Schema / IPC 差异清单并确认。不满足数据门禁的页面不宣称已回流。
2. 抽出共享纯展示，Playground 继续保留既有候选及边缘态；对照候选验收，偏离已确认设计时重新展示。
3. 完成真实数据读取、必要写入、角色隔离、图片归属与重载恢复；使用测试 fixture 验证，不播种样张到正式资料。
4. 在正式 `WorldHub` 接通全部六面，保留现有生图 / 生活切片 / 保存链；清理本轮明确替代的旧展示入口，不删除无关能力。
5. 深浅主题、窄宽正式入口验收；同时验证 Playground 无生产副作用，以及正式端不存在 fixture / 实验控制器。
6. 自审后按顺序运行 Unit、类型检查、定向及全量 UI E2E、build、资产与文档门禁；更新模块卡、质量、进度和 changelog，按独立可回滚范围提交推送。

必测：六入口与当前角色一致；读取失败可重试；切换角色无串数据；多图预览；点赞评论失败；单件 / 整套换上成功、失败和重载；作品摘要 / 详情一致及多笔记；总览 / 空间 / 有意义物件过滤；通讯录缺字段与失败头像；旅行进行中 / 完成过滤；跨面关联失效；详情返回焦点 / 滚动恢复；生图失败不破坏原记录；备份恢复包含新增事实与图片关联。

几何验收：分类、标题、详情与返回共享边界，偏差不超过 2px；hover / focus / 加载文案不改卡片或操作槽尺寸；长名称、长文、图片失败与空态不产生横向溢出或重叠。

## 6. 风险与当前审计结论

- 授权门禁通过：用户明确授权六面整体回流，不限通讯录。
- 候选证据需逐面复核：既有 Playground 测试不替代正式端持久化和 Electron 验收。
- 隔离门禁待逐文件确认：工作区存量变更覆盖正式组件、共享类型、IPC 和文档，不能作为本轮已完成实现。
- 契约门禁未完全满足：穿搭组合、多笔记、空间物件、旅行和共同经历需要明确生产语义及接口。
- 当前阶段仅完成回流审计与合同草案，不标记 adopted，不宣称六面正式回流完成。用户确认本方案及具体数据差异后进入生产施工。
