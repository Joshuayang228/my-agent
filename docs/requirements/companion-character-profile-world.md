# 主角档案与默认世界结构

> 状态：**结构接入已落地，人物故事内容待定**（2026-08-11）
> 生命周期：已完成施工快照（冻结）；当前能力与行为以代码、模块卡、Architecture、Quality 和 Decisions 为准。
> 对象：主角候选小航（`roleId: hang`）
> 关联：`docs/requirements/companion-protagonist-persona.md`

## 当前结论

Alice 的分层思想仍然有效：稳定人物档案、默认世界和运行状态应分开持有。但人物故事尚未确认，因此本轮只建立结构、Prompt 边界、Debug 可见性和不编造约束，不把草稿背景写成正式事实。

## `profile.json`

当前保存：

- 五维表达基线。
- 行为能力、边界、可控缺点、社交方式与实践价值观。
- “故事未定，不得自行补写”的身份边界。

当前留空或标记待定：

- 年龄、生日、外观。
- 家乡、家庭、教育、职业和人生经历。
- 兴趣、食物、音乐、书、颜色和固定偏好。
- `lifeAnchors`。

## `world.default.json`

当前只提供 schema v1 和运行所需的中性占位：

- 城市、片区、住所、交通均为未设定。
- 常去地点、物品、作息和房间场景均为空。
- `standingFacts` 只声明人物故事未定，不得自行补写。
- 初始运行态标记为主角候选与故事待定。

该文件不会播种人物物品，也不会向 Prompt 提供虚构生活细节。

## 平台行为

- Loader 可选读取 `profile.json` 与 `world.default.json`；有文件时要求 `schemaVersion: 1`。
- 主 Prompt 只注入非空字段和故事待定边界，不注入原始 JSON。
- 日剧本生成必须看到“人物故事尚未确定”，不得生成固定职业、住所或生活路线。
- Debug 可以查看结构与待定状态。
- 旧三字段、坏 JSON 和缺字段 `world_json` 全局不迁移，直接重置为各角色当前默认状态；其他角色不因此获得新人物故事。
- 其他角色保持原状，本轮不扩写。

## 验收标准

1. 只有小航拥有 `profile.json` 与 `world.default.json`。
2. 文件均为 schema v1，且故事字段不包含已定职业、城市、住所、经历、外观或偏好。
3. 人物 Prompt 明确故事未定，不出现未确认生活事实。
4. 初始物品列表为空，不向 `companion_assets` 播种人物故事物品。
5. Debug 可见五维基线、行为边界和故事待定状态。
6. 所有旧 schema 世界状态直接重置，不迁移；其他角色的 Role Pack 内容保持原状。
7. 小航仍未激活。
