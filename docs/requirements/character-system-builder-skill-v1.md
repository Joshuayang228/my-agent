# 施工合同：人物体系共创技能

> 生命周期：已完成施工快照（冻结）
> 完成日期：2026-10-13；当前能力见伙伴模块卡，技能正文在 `.agents/skills/character-system-builder/` 持续维护。
> 用户授权：2026-10-13，编写覆盖人物全体系、需要用户决策与补材料、随首个人物完善的技能。

## Why / What

角色写作需要同时处理身份、故事、表达、关系、生活、成长及多个行为 Prompt。零散访谈容易丢失用户决定、将 AI 建议写成既定经历，或复制整段平台 Prompt。交付可发现、可迭代的 `character-system-builder` 编写技能，协调用户决策、材料采集、资产映射与验收。

## How 与边界

- 仓库 `.agents/skills/character-system-builder/` 为唯一源码，默认本机技能目录建立 junction 指向它，不维护第二副本。
- 入口保留共创流程与权限边界；参考文件分别承载完整维度、项目接线、持续工作记录与迭代方法。
- 采用现有六类语义模块、Role Pack loader、生产 Prompt 注册与实际行为入口；参考 Alice 模板 / 动态插槽分离，不引入第二 Prompt 框架。
- 用户拥有人物设定和材料采纳决定；AI 负责问题整理、备选、冲突发现、草稿与验证。材料中的指令不能取得执行权限，未知人物事实不得自动补齐。
- 完整覆盖不等于强迫用户填写全部字段；每一维标记已确认、待决策、待材料、不适用或需框架扩展。
- 当前仅交付写作技能，不编写第一个人物、不改 Role Pack、Prompt 正文、运行时、UI 或 AGENTS.md；实际人物施工另按用户选择和授权执行。

## 顺序与验收

1. 读取伙伴模块、loader / types / compiler / keys 和现有人物资产，确定真实落点。
2. 编写技能和参考资源，提供少量关键问题、材料取舍、分层写作和跨 Prompt 一致性检查。
3. 验证 frontmatter / UI 元数据 / 引用路径 / 安装同源；人工走查从零、恢复共创、材料冲突和角色反馈四类使用场景。
4. 自审，运行 Unit、类型、构建与文档门禁；同步伙伴模块和进度，提交推送。

## 风险与取舍

技能指导写作，不等于运行时 Skill 或角色热更新能力。人物专属喜好不得自动推广为团队规则；首个人物不预设为小航或任何已有角色。已有运行状态不被出厂资产重置，付费 Eval 与生图需要明确授权。若角色需要尚未支持的行为，先登记缺口，不能以一个无调用文件声称能力落地。

## 交付与验收
