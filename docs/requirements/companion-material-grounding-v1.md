# 人物材料依据与阅读感想闭环 v1

> 状态：进行中
> 日期：2026-11-07

## 1. 需求背景

人物可以保存带来源的阅读笔记，但当前笔记正文同时承载材料原文依据和人物解释。这样无法区分“材料明确出现了什么”和“人物从材料得出了什么”，也无法在图片识别或模型失败时证明没有伪造生活事实。

## 2. 功能目标

- 所有新的人物自主阅读记录都保留明确材料来源。
- 材料中的观察与人物推断分开保存；推断不得替代观察。
- 用户或人物都是明确记录者，记录者就是本次写回的确认主体。
- 每次写回保存确认主体和确认时间，Debug 可以追溯谁确认了生活事实。
- 模型失败、材料不足或校验失败时保留失败原因，不写入阅读笔记。
- 图片观察的开始、成功、失败和拒绝尝试只保存有界脱敏证据，不保存图片二进制。
- 反思只消费已确认写回的笔记，不把聊天中的看图或书名自动当作阅读事实。

## 3. 技术方案

阅读笔记继续存入现有 `bookshelf` 资产的 `readingNotes`，新增可选的结构化 `grounding`：

- `source`：材料来源范围；
- `grounding.observation`：材料中可直接核对的内容；
- `grounding.inference`：人物基于观察形成的解释，可省略；
- `author`：`user` 或 `companion`，同时作为本次写回确认主体。

旧笔记继续可读；新的人物自主笔记必须提供 `source` 和 `grounding.observation`。写回仍经过当前人物、资产类型、长度和数组唯一 ID 校验。

## 4. 影响范围

- 共享生活资产 schema 与读模型；
- `companion_add_reading_note` 工具及其单元测试；
- 人物模块卡和质量文档；
- 后续视觉识别 / 自动感想服务复用该契约，不另建第二套阅读事实源。

## 5. 当前批次实施步骤

1. 固化 `grounding` 结构和人物自主写回的强校验。
2. 补来源、观察、推断、失败和旧数据兼容测试。
3. 让 Debug / 反思读取同一结构化笔记，并更新模块文档。
4. `companion_observe_material` 只观察当前会话图片并返回候选，不自动写回；失败只产生可解释结果。
5. 后续接入更完整的材料感想生成时，继续复用该结构，不新增第二套生活事实源。

## 6. 风险与权衡

- 旧笔记缺少观察字段，保留兼容读取，不能反向补造观察内容。
- 观察和推断增加字段，但能避免把模型猜测伪装成阅读事实。
- 本合同不把聊天附件自动写入人物世界；必须经过明确来源和记录者写回。
