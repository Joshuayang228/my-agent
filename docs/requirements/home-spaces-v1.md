## 1. 背景与现状（Why）

家居回答“伙伴住在怎样的地方，各个空间里有哪些物件”，不是家具管理后台或实时空间模拟。用户已确认以空间组织物件：增加总览，随后切换各个实际存在的空间；总览只展示鸟瞰图，各空间展示环境图与物件。

当前 WorldHomeContent 展示 home 资产的住所文字与生活物件列表，尚无显式住所 / 空间 / 物件关联。WorldDetailsPanel 仍有维护表单；这些是现状，不代表本合同方案已经生效。已有资产按主角隔离，图片可复用受控媒体存储与 Foundation ImageViewer；无 Role Pack 来源的住所保持空态，不能用样张补成真实人物事实。

本方案先复用现有资产、媒体服务与基础组件，不新增装修引擎。本地 Alice 的 query 与 prompts-novel 代码把住所资料与长期持有物分开处理，但没有可直接照搬的房间网格证据；参考实体分离，不复制其分类或人物事实。

## 2. 已确认目标（What）

- 家居内部为“总览 | 各空间”单行导航，默认总览；客厅、卧室、书房、玄关是候选示例，不是所有角色的必备房间。
- 总览只展示整个住所的鸟瞰图片，可预览；不显示物件卡片、统计、说明面板或交互热点。加载 / 失败 / 空态属于必要反馈，不算额外内容模块。
- 空间内容依次为场景图片、可选的一句描述、所属物件网格。图片与名称是物件卡片主要信息，完整信息进入详情。
- 允许真实生图，不使用假生图成功状态。Playground 生成结果只属于隔离样张，不写正式人物资产，不代表住所设定已确认。
- 不因打开页面、切换标签、聊天或短期活动变化自动生图；图片生成后保存并复用。
- 不做交互平面图、3D、坐标定位、热点或家具拖放。鸟瞰图是视觉总览，不承诺建筑精度或逐件对应库存。
- 正式回流仍需用户明确许可；本轮只交付 Playground 组合、真实生成的隔离图片及状态夹具，不改生产 UI、数据库或 Prompt。

## 3. 页面与交互

### 3.1 导航与图片

标签、按钮、图片预览、空态、错误反馈和详情容器复用已有 Foundation。总览固定在首位，空间按显式 sortOrder 排列；多空间时导航沿基础标签的窄宽滚动策略，不挤成多行业务按钮。

总览图片保留完整画面，不裁掉房间边缘；空间图采用克制的横向内容框。具体比例在 Playground 验收后固化，不把大图强制铺满视口。加载 / 生成中 / 失败与成功采用相同图片槽位尺寸，hover 蒙版或辅助动作不能改变占位。点击图片只打开共享 ImageViewer，不兼作空间切换。

空间名称已有标签承载，不在内容区重复标题。描述缺失直接隐藏，不编造生活气氛；没有值得展示的物件时只保留空间场景与已有描述，不强制补齐卡片或数量。物件名称最多两行，缺图也预留固定图片位置。

### 3.2 物件与详情

**展示原则**：只展示与人物故事、特殊意义或长期习惯有可追溯关联的物件，由 Agent 根据事实判断；登记在数据库、出现在场景图或属于某种家具类别，都不足以自动展示。不得写“哪些一定展示 / 一定隐藏”的名单，不设房间配额。窗边沙发只是有故事的示例，不是固定展示类别；同类物件可以因不同事实得到不同决定。

家具、日常用品、包、相机和雨伞均属于家居物件；衣物归衣柜，书籍与摄影作品归文化角。相机设备与摄影作品是不同实体，不重复复制作品记录到家居。

物件拥有一个常驻收纳空间，不因伙伴把相机带出去就改写家中的收纳归属；短期携带状态与长期位置分离。没有明确位置的物件不猜测房间，提供仅在确有记录时出现的“未归置”收纳入口，使用物件网格，不虚构场景图。此入口为拟实施的边缘处理，需随候选确认。

点击物件名称进入页内详情，图片仍独立预览；详情显示图片、名称、描述以及实际存在的空间 / 来源信息，长文内部滚动，返回恢复焦点和列表位置。不默认展示价格、次数和时间统计。

普通家居页拟沿用衣柜 / 文化角的 Agent 维护边界，不提供添加、字段编辑、删除或生图表单；用户通过对话表达改变，Agent 经过世界服务校验执行。Playground 的状态 / 生图实验控制器明确属于展厅，不回流产品。

## 4. 拟实施数据合同（How）

以下是设计字段，不宣称当前 Schema 或后端已支持。优先沿用 companion_assets：home 承载住所 / 空间，furniture 承载家居物件，以 payload.schemaVersion 与 entityType 明确语义；最终共享类型和写入校验须在真实数据步骤统一落实，禁止仅在 JSX 中推断关联。

### 4.1 公共字段

| 字段 | 值 / 默认 | 含义与约束 |
|---|---|---|
| id / roleId | 必填稳定 ID | 资产与主角归属；名称不是关联键，同名不可合并 |
| kind | home / furniture | 不把衣物、文化作品混入家居资产 |
| schemaVersion | 1 | 本合同结构版本，位于 payload |
| entityType | residence / space / object | 住所 / 空间用 home；物件用 furniture |
| name | 必填，1–120 UTF-16 代码单元 | 展示名称；写入不静默截断 |
| description | 可空，最多 4000 代码单元 | 完整描述；列表仅短摘录 |
| lifecycle | active / archived，默认 active | 归档保留历史与来源，非硬删除 |
| sourceEventId | 可空 ID | 沿现有事件事实链校验，不把生成图片当作生活事件 |
| createdAt / updatedAt | 毫秒时间戳 | 服务写入；不得冒充购入、搬家或使用日期 |

### 4.2 住所、空间与物件字段

| 实体 | 字段 | 值 / 默认与含义 |
|---|---|---|
| residence | isCurrent | 布尔；同主角最多一个 active 当前住所，变更事务内执行 |
| residence | locality | 可空，最多 240 代码单元；已有城市 / 区域描述，不要求详细地址 |
| residence | overviewImage | 可空的受控图片引用；总览鸟瞰图 |
| space | residenceId | 必填；同主角有效住所 ID，跨角色关联拒绝 |
| space | spaceType | living_room / bedroom / study / kitchen / bathroom / entryway / balcony / other；分类不强制全部出现 |
| space | sortOrder | 非负安全整数，默认 0；相同顺序按稳定 ID 排列 |
| space | sceneImage | 可空的受控图片引用；本空间场景图 |
| object | residenceId | 必填；同主角有效住所 ID |
| object | spaceId | 可空；为空即未归置；非空须属于同一住所与主角 |
| object | objectType | furniture / daily_item / portable_item / other；数据分类，不要求第一版增加分类导航 |
| object | originNote | 可空，最多 4000 代码单元；有来源的来历 / 纪念意义 |
| object | acquiredAt | 可空毫秒时间戳；明确获得时间，不能用 createdAt 填充 |
| object | image | 可空的受控图片引用；物件独立图片 |
| object | displayInHome | 布尔，默认 false；Agent 明确选择是否在家居展示，不从类别自动推导 |
| object | displayReason | 可空，最多 240 代码单元；展示时必填，说明故事、意义或习惯关联 |
| object | displayEvidence | 事实 / 事件引用 ID 数组，最多 20 项；展示时至少一项有效同角色引用，不允许从图片臆造依据 |

空间迁移和归档必须事务校验；仍有物件时先明确重归置或改为未归置，不产生悬空 spaceId。搬家不自动迁走所有物件或复制旧房间，由明确动作提供变更清单。历史引用与图片归属沿现有事件 / 媒体服务处理。

### 4.3 物件操作接口

保留完整、可验证的操作服务，不以“前端不展示维护按钮”为由删掉增改能力。以下名称为服务语义合同，最终 Tool / IPC 名称按现有注册规范确定；正式 Agent 工具与受控 IPC 复用同一服务，不各写一套 CRUD。

| 操作 | 关键输入 | 行为与返回 |
|---|---|---|
| listObjects / getObject | roleId、residenceId，可选 spaceId / lifecycle；详情用 objectId | 按角色与住所过滤，支持分页；返回完整结构化记录及 version，不只返回卡片展示字段 |
| createObject | roleId、residenceId、可空 spaceId、name、objectType、可选 description / originNote / acquiredAt、requestId | 校验后添加；返回完整物件、version 与变更 ID，重试不重复添加；不附带隐式生图 |
| updateObject | roleId、objectId、expectedVersion、requestId、字段白名单 patch | 编辑名称、类型、描述、来历和明确获得时间；未传字段不变，可空字段用 null 显式清除；不能修改 ID / 归属 / 系统时间或任意图片路径 |
| placeObject | roleId、objectId、expectedVersion、requestId、residenceId、可空 spaceId | 原子更新住所与常驻收纳空间；null 表示未归置，跨住所移动须明确提供目标住所，跨角色拒绝 |
| archiveObject / restoreObject | roleId、objectId、expectedVersion、requestId、可选原因 | 移出展示 / 恢复，保留来源、历史和媒体引用；恢复前再次校验住所与空间，不能产生悬空关联 |
| requestObjectImage / cancelImageRequest | roleId、objectId、expectedVersion、requestId、明确生成意图；取消用任务 ID | 复用真实生图服务；返回可追踪任务及状态，图片成功后由受控服务绑定，不由 Agent 提交自由路径；失败不撤销物件 |

共同约束：写入前校验调用来源、权限、角色、字段边界及关联；expectedVersion 冲突明确返回，不覆盖他人新版本。requestId 在角色与操作作用域内幂等，同一 ID 不同载荷拒绝。动作记录用户意图来源、执行 Agent / 调用者和可选关联事件，不能把 Agent 推断伪装成用户确认。

展示决定由受控 Agent 动作更新，统一验证 displayInHome / displayReason / displayEvidence；普通列表只消费校验后的决定，不能按名称、类别或房间自行选物件。P0 使用 fixture 引用验证展示边界；同角色引用存在性和真实 Agent 决策在真实数据链步骤落实，当前不宣称已支持。

结果统一表达成功记录 / 任务与可定位的变更信息；错误区分非法字段、无权访问、记录不存在、关联失效、版本冲突与生图失败，用户提示不泄露内部路径或堆栈。真实写入成功但界面刷新失败时只重读，不重新添加。

第一版“删除”对应 archiveObject，不把库存维护映射为不可恢复的数据库硬删除；整个角色的数据清除仍走已有隐私 / 数据服务。住所与空间也须保留受校验的新增、编辑、排序、设为当前、归档服务，并遵守第 4 节的关联事务，不在本合同中交付空函数接口。

验收增加：添加后重载保留、重复请求幂等、编辑可空字段清除、未知字段拒绝、并发版本冲突、物件归置 / 未归置、移出与恢复、跨角色 / 住所越权拒绝、归档时在途图片不能复活记录，以及刷新失败不重复添加。

## 5. 生图与保存

- 复用现有真实生图服务与模型配置工厂，不在页面手拼 Provider、凭据或另一套调用协议。没有可用模型时明确报错，不返回伪图片。
- Playground 真实生成必须由用户明确触发，有生成中、取消、失败与重试反馈；取消不承诺撤回已发生的上游费用。只保存到隔离媒体范围，不写正式 companion_assets；正式生成绑定真实角色、目标资产和图像用途。
- overview / scene / object 分别拥有独立图片任务。打开、切换和普通物件增减均不触发任务；后续 Agent 可根据明确搬家或重要布置变更请求更新，但不能静默重生成整个家。
- 生成任务状态为 idle / pending / generating / ready / failed / cancelled；已有成功图片在新任务失败时继续保留，不把旧图抹空。
- 请求携带 requestId、目标资产 ID、用途、世界版本和输入指纹；同目标同版本去重。晚到结果不得覆盖新版本、换角色后的目标或已归档资产。
- 图片字节使用现有受控媒体存储；引用记录 MIME、尺寸、字节数和内容指纹，并遵守路径 / 角色校验、读取、预览、备份恢复和清理流程。Prompt key / version / 输入指纹作为生成来源记录，不在 UI 或合同维护第二份生产 Prompt 正文。
- 住所设定尚未确定：候选真实图片须标记为设计样张，不能播种成默认人物生活事实。正式住所来源仍是明确的 Role Pack、用户确认或可追溯事件。

## 6. 架构与影响范围

Renderer 负责纯展示与状态交互；IPC 只桥接校验后的动作；companion 世界服务负责角色 / 关联 / 版本校验和事务；现有生图服务负责外部调用，storage 管理资产与媒体。不得反向依赖 IPC，工具不绕过世界服务直写数据。

候选优先复用 WorldHomeContent / WorldDetailsPanel，通过显式 props 或隔离 wrapper 表达变化，不修改生产默认布局。新增组件登记 Experience 及真实 Foundation 依赖，不为家居复制基础控件。

预计影响：家居组合、隔离夹具、共享资产类型及校验、真实生图目标关联、Role Pack 加载和测试。若增改 IPC，必须同步共享类型、preload、handler、vite-env 四处。字段与页面不要求兼容旧开发数据，但不能擅自清理整个开发库或破坏其他生活面的资产。

## 7. 施工步骤与验收

| 步骤 | 完整交付边界 | 可验证结果 |
|---|---|---|
| 1. 合同审阅 | 确认字段、未归置入口、维护边界及图片职责；核对本地 Alice 可用空间展示证据 | 用户明确确认详细方案；无 UI / 数据变更 |
| 2. Playground 候选 | 总览与多个空间、只读物件详情、真实生成并固化的隔离图片、显式展示决定；统一控制切换状态夹具 | 用户可检查布局、预览和缺图 / 失败样张；生成中是模拟状态，不提供假生成按钮，不写正式人物事实 |
| 3. 真实数据链 | 类型、校验、事务、空间关联、版本化媒体绑定和 Agent 动作统一落实 | Unit / 集成覆盖真实保存、重载、读取及失败路径；不提前切换正式 UI |
| 4. 正式回流 | 获明确许可后使用已验收组合与真实数据，移除正式维护表单 | Electron 走通角色隔离、空间浏览、物件详情与真实图片，故事同步 |
| 5. 收工 | 对照用户旅程复核，事实进入模块卡 / 架构 / 质量，冻结合同 | 门禁通过，独立提交推送；未完成项不冒充已落地 |

每步完整可验证，不用假返回值、无逻辑按钮或 TODO 交付替代；候选只是隔离设计交付，不代表后端或正式 UI 完工。

必测：总览只含图片与必要反馈；空间过滤与未归置；多 / 少 / 空物件；长名称与长描述；无图、生成中、失败、取消、重试、过期结果；图片预览返回；深浅主题、宽窄、多标签滚动、hover 不改尺寸；跨角色 / 跨住所 ID 拒绝；归档无悬空关联；媒体重载与备份恢复；浏览不触发费用；候选不写生产资产。

## 8. 风险与权衡

鸟瞰与房间生图可能在布局、物件细节上不一致，因此不作为建筑图或库存证据；共享住所设定可提高一致性，但不承诺图像模型输出严格拓扑。数据事实由结构化资产决定，不能从图片自动反推住所或新增物件。

空间主图过大可能挤走物件；在候选验收中以有限高度与首屏可见物件内容控制比例。真实生图涉及费用和失败，明确触发、版本去重与旧图保留比自动实时更新更符合本版目标。

本合同只定义家居体验与流程，不编写角色住所设定，不新增 Prompt 多语言、装修系统或资产购买经济系统。
