# 施工合同：设置体系信息架构与体验候选 v1

> 状态：进行中
> 生命周期：进行中
> 范围：P0 Playground 候选；取得用户明确回流许可前，不修改正式 Settings、IPC、存储或真实设置。
> 关联：`docs/requirements/frontend-visual-language.md`、`docs/requirements/product-experience-map-v1.md`、`docs/requirements/playground-memory-information-architecture-v1.md`、`docs/modules/companion.md`、`docs/modules/memory.md`、`docs/modules/permission.md`

## 1. 需求背景（Why）

设置已从少量偏好项发展为 Agent 的控制面：既包含外观和相处方式，也包含模型连接、权限、MCP、数据备份与开发工具。现有界面沿用 11 个平级 Tab，普通偏好、低频高级项、内部调校和高风险外部连接并列，造成三个问题：

1. 用户无法快速判断「这项会改变什么、是否安全、是否需要我理解」。
2. 伙伴页把生活提醒、主角切换、MUTABLE、反思和 Prompt 注入堆叠在一起，混淆日常相处与生产调校。
3. 现有 Playground 仅复用正式 `SettingsPanel`，不能独立验证新的 IA、风险披露、窄宽布局与真实副作用隔离。

本轮目标不是为了显得完整而补假设置，也不是复制 Alice 的页面；而是按**用户任务、风险边界、真实代码归属**重组已有能力，让设置成为清楚、有节制、可信赖的决策界面。

## 2. 功能目标（What）

### 2.1 目标信息架构

P0 候选按以下七个设置入口组织：

| 分层 | 入口 | 面向用户的任务 | 已有真实能力 |
|---|---|---|---|
| 日常 | 外观与界面 | 调整使用感受 | 主题、字号、当前语言状态 |
| 日常 | 伙伴与相处 | 调整陪伴方式 | 角色架入口、生活动态提醒、勿扰、每日上限、主动问候、相处补充说明 |
| 日常 | 模型 | 连接并检查聊天模型 | Provider 入口、Key 状态、Base URL、主/辅助模型、连接测试 |
| 日常 | 记忆与相处 | 调整解释习惯、管理记忆 | 专家度、跳转记忆页 |
| 日常 | 数据与隐私 | 迁移和理解本地数据 | 导入、导出、备份边界 |
| 高级 | 权限与自动化 | 控制 Agent 默认审批与规则 | executionMode、权限规则 |
| 高级 | 扩展与工具 | 管理 Skills 与外部能力 | Skills、MCP 连接 / 启停 / 删除 |

低频入口不再占一级 Tab：

- 「关于 My Agent」放在导航底部；展示版本与运行说明。
- Debug 与 Playground 只作为开发工具快捷入口，不再成为 Settings 主设置项。
- 模型采样与预算收进「模型 → 高级控制」。

### 2.2 明确不在普通设置暴露的内容

- MUTABLE 原文、版本历史、立即反思、强制反思：属于伙伴调校和运行诊断，后续放入 Debug / 明确的伙伴调校入口；本轮候选不把它们放入普通用户设置。
- PROTECTED、L3、Prompt 注入等实现术语：不进入产品设置文案。
- 工作目录：Chat 输入区是唯一选择入口；设置不得制造第二个可写入口。
- API Key 原文、MCP 环境变量与命令秘密、真实权限规则的内部细节：不能在 Playground fixture 或普通摘要中泄漏。
- 当前没有真实实现的账号、云同步、多语言、减少动效、全量删除、检查更新等能力：禁止伪造 UI。

### 2.3 本轮补充范围：页面内部能力与作用范围

一级导航保持不变，本轮只补齐三个容易让用户产生误解的页面内部能力：

1. **模型 → 运行预算**：展示会话预算与每日预算的用户语言样张，说明“0 表示不限制”；不展示内部 token 计算、压缩策略或费用估算。
2. **扩展与工具 → Skills 管理**：展示启用状态、版本、校验结果和隔离试跑入口的管理层级；不把 Skill 正文复制到设置，也不触发真实 Skill 管理 IPC。
3. **作用范围提示**：在已有关键卡片或设置行上以轻量标签标明“本机 / 伙伴 / 全局”，帮助用户判断改动影响面；“当前会话”仍由 Chat / 工作区承载，不进入设置。

补充后的内部结构：

```text
模型
├── 连接状态
├── Provider 与模型
├── API Key 状态
├── 高级模型控制
└── 运行预算
    ├── 会话预算
    └── 每日预算

扩展与工具
├── Skills
│   ├── 启用状态
│   ├── 版本与校验状态
│   └── 管理 / 隔离试跑入口
└── 外部能力（MCP）
```

以下内容明确不补为普通设置：通知、网络 / 代理、账户 / 云同步、可编辑快捷键、心情指数、自定义 System Prompt、向量召回阈值和记忆保留策略。这些要么尚无真实用户能力，要么属于 Debug / 会话级运行策略。

### 2.4 参考结论：借鉴结构，不复制产品语义

本轮复核了仓库内 Alice 方法论与 Alice 构建产物中可确认的配置边界，并对照 Codex 类工具的“按作用域 / 风险 / 任务组织配置”思路，形成以下约束：

- **配置分层**：全局默认、系统配置、用户设置、当前会话是不同层级；设置只承载用户可长期控制的部分，临时任务状态回到 Chat / 工作区。
- **模型分场景**：主对话模型与辅助模型可以分开；预算是用户对本机使用边界的控制，不与 Provider 或具体模型 ID 混为一谈。
- **能力与权限分离**：Skills / MCP 负责“有什么能力”，权限与自动化负责“什么时候允许执行”；两者都应能解释影响范围。
- **渐进披露**：普通用户先看到状态和结果，高级控制通过折叠或管理入口展开；内部 Prompt、召回、沙箱和密钥细节继续留在 Debug 或主进程边界。

因此本轮只补页面内部能力和作用范围提示，不新增一级设置入口，也不把 Alice / Codex 的内部术语直接搬进产品文案。

## 3. 体验与视觉规则（How）

### 3.1 页面骨架

- 宽屏使用左侧设置导航与右侧内容区；日常与高级是**语义分组**，不是两套平级产品。
- 窄宽切换为顶部横向可滚动 Tab；内容宽度优先给表单与规则，不压缩为狭窄卡片。
- 内容切换使用短距离淡入与水平位移，使用 `var(--motion-*)`，不出现生硬整页切换。
- 每页只保留「标题 + 一句用户语言说明 + 必要状态」；不在说明中混入 Alice、架构章节或实现名词。

### 3.2 控件层级

- 普通偏好采用紧凑的「标签 / 说明 / 控件」行；不把所有区域包成同重量的大白卡。
- 主题、模型 Provider、MCP 服务等有比较需要的项使用选项卡或清单卡。
- 二元状态使用 Switch；开关关闭时隐藏依赖的次级控制，避免不必要的表单噪音。
- 危险或外部影响动作用说明与二次确认语义表达，不依赖装饰性红色或炫光。
- 仅在 MCP 添加、导入等需要聚焦的步骤使用遮罩 / Dialog；普通设置页不加蒙版。

### 3.3 关键页面候选

1. **外观与界面**：静态语言状态行、主题预览、字号选择；语言不伪装成多选。
2. **伙伴与相处**：当前伙伴与角色架入口、生活提醒 Switch、开启后显示静默时段和每日上限、主动问候 Switch、相处补充说明。
3. **模型**：首次配置 / 已配置、Provider、API Key 已保存状态、主/辅助模型、连接成功 / 失败、高级参数折叠。
4. **记忆与相处**：解释粒度和前往记忆管理的明确路径。
5. **数据与隐私**：导入 / 导出动作与「包含 / 不包含」数据范围。
6. **权限与自动化**：默认审批方式、规则空态 / 已配置态、JSON 高级编辑折叠。
7. **扩展与工具**：Skills 入口、MCP 空态 / 已连接态 / 添加引导；外部服务标出风险，不展示秘密。

## 4. 真实边界与数据流

### 4.1 保持不变的生产事实

- `SettingsPanel` 的真实设置仍从 `settings:get` / `settings:set` 读取和自动保存。
- `llmApiKey`、`mcpServers` 的加密、Renderer 脱敏和 MCP 秘密合并规则不改。
- `executionMode=full-access` 与新增 / 变更启用的 MCP 继续由主进程二次确认。
- 数据导出继续排除 API Key、MCP、权限规则、执行模式与本机项目路径。
- Provider 预设只填 Provider 端点；模型 ID 仍由用户实际账户决定。

### 4.2 P0 隔离实现

- Settings Playground 不再直接拿正式 `SettingsPanel` 作为唯一候选；建立专用的候选容器与静态 fixture。
- 所有 Switch、Tab、折叠面板、连接状态与 MCP 步骤仅更新 Renderer 内存 state。
- P0 不调用 `window.electronAPI`、不读取真实 API Key / MCP / 权限规则 / 项目路径、不触发测试连接或导入导出。
- Playground 只复用已有 Foundation token、图标与通用视觉类，不将候选数据写回注册表或生产资产。

## 5. 影响范围评估

| 范围 | P0 处理 | P1 回流后处理 |
|---|---|---|
| Playground Settings 场景 | 新候选布局与 fixture | 与正式样式持续同轮维护 |
| 正式 SettingsPanel | 不改 | 拆分为分区组件，替换 IA |
| App / IPC / storage | 不改 | 保持接口和安全规则，按需接入组件 |
| Debug / 伙伴调校 | 不改 | 单独设计 MUTABLE / 反思归位，不能夹带本合同偷改 |
| E2E | 新增 Playground 候选覆盖 | 补正式导航、窄宽、实际写入和安全回归 |
| 模块卡 / 架构文档 | 本轮仅合同 + 进度 | 回流后更新稳定能力事实 |

## 6. 实施步骤与验收

### P0-1：合同与候选模型

1. 写入本施工合同、更新合同索引。
2. 复核 Settings 现有真实能力和 Playground 路径。
3. 定义只含展示安全字段的 fixture 与候选导航。

**验收**：候选项与真实能力一一对应；不出现尚未实现的选项。

### P0-2：隔离 Settings 页面候选

1. 完成七个入口 + 底部关于的 Playground-only 信息架构。
2. 实现宽屏导航、窄宽 Tab 条和内容切换。
3. 实现开关、折叠、MCP 添加步骤、模型连接状态等本地交互。
4. 补充模型运行预算样张、Skills 管理层级和关键设置的作用范围标签；预算输入、Skill 启用和隔离试跑仍只存在于 Renderer 内存。

**验收**：所有候选交互可操作，但不会写入或读取生产设置；用户可以从页面结构看懂每项设置的影响范围。

### P0-3：验证与人工验收

1. 添加 / 更新 E2E，验证主要 Tab、开关披露、模型状态、高级折叠、MCP 风险提示与窄宽导航。
2. 浏览器检查浅色、深色、宽屏、窄宽；确认文本截断、焦点、滚动和切换连续性。
3. 用户在 Playground 逐项验收、打备注。

**当前进度**：自动化验收已补齐宽屏 / 窄宽导航、键盘切换、`tabpanel` 关联、文本截断和内容滚动；仍等待用户对候选视觉与信息架构做人工确认。

**验收**：用户明确许可前，正式 `SettingsPanel` 的导航、默认区块和行为均不变化。

### P1：正式回流（需单独取得用户许可）

1. 将已确认的候选规则回流正式 Settings。
2. 保留 IPC、加密、脱敏、权限确认、导入导出边界。
3. 补充正式行为测试和模块卡 / changelog / progress 文档收口。

## 7. 风险与权衡

| 风险 | 控制方式 |
|---|---|
| 候选 UI 偷读写真实设置 | 用静态 fixture 与明确 `preview` 边界；E2E 断言不触发 Electron API |
| 为了 IA 重排丢失现有能力 | 用现有 11 Tab → 7 入口的映射表逐项核对 |
| 普通用户页泄漏工程术语 | 产品文案仅讲影响；内部策略、资产、日志留在 Debug |
| MCP 被当作普通偏好 | 以「外部能力 / 风险提示 / 启停状态」展示，仍保留生产二次确认 |
| 覆盖范围太大而提前回流 | P0 / P1 分阶段，P1 以用户的明确回流许可为闸门 |

## 8. 完成判定

P0 完成不代表正式设置已更新；只有以下条件同时满足才可称为 P0 候选完成：

- Playground 可浏览七个设置入口及底部关于入口；
- 宽屏与窄宽导航均可正常操作；
- 模型、伙伴、权限、MCP、数据等高频与高风险状态均有真实可交互的隔离样张；
- 模型页能看到运行预算，扩展页能看懂 Skills 的管理状态与入口，关键设置能看到作用范围；
- 不读取、写入、测试、导入、导出或连接任何生产数据；
- 测试、类型检查、构建与浏览器视觉验收通过；
- 用户明确确认候选可以回流后，才进入 P1。
