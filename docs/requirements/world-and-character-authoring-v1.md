# 世界观套装与人物生成施工合同 v1

> 状态：进行中
> 日期：2026-10-31
> 目标：把人物、朋友角色、世界观套装和用户生成人物能力组织成可切换、可审阅、可扩展的完整体系。

## 1. 为什么做

当前默认《海贼王》世界已经有路飞主角、索隆 / 娜美 / 乌索普 / 山治朋友角色和关系资料，但 Debug 主要按资产目录展示，用户不容易看出谁是主角、谁是卡司成员、哪些人物属于同一个世界。运行时也已有 `universeId`，但还没有面向用户的整套世界观切换入口和安全的用户生成人物流程。

继续增加第二套世界观时，如果只增加几个 Role Pack，容易把人物、关系、Prompt、生活数据和当前主角混在一起。本合同把世界观作为第一层边界，把主角与朋友分开，把用户创作流程与开发者内置资产流程分开。

## 2. 功能目标

1. Debug 提示词管理器按“世界观 → 主角 / 朋友 → 功能组 → Prompt 条目”呈现，并显示人物适配状态。
2. 世界观套装具备稳定 ID、名称、版本、默认主角、主角列表、朋友列表和关系来源；切换时原子更新当前世界与主角，禁止跨世界混读或写入。
3. 默认《海贼王》套装明确：路飞是唯一当前主角，索隆 / 娜美 / 乌索普 / 山治是朋友角色；朋友可进入名册、关系和召唤，但不能自动成为活跃主角。
4. 用户可以通过运行时人物制作 Skill 创建世界观草稿、人物草稿和关系草稿；模型只负责提案与整理，用户确认后才写入用户资产目录。
5. 开发者仍可维护内置 Role Pack 和世界观资产；用户生成资产与内置资产分离，不能覆盖内置文件或平台规则。

## 3. 技术方案

### 3.1 世界观边界

- `UniverseManifest` 作为套装根索引，声明 `id`、名称、版本、`protagonistIds`、`castIds`、默认主角和来源 / 所有权。
- Role Pack 继续声明 `canBeProtagonist`，但运行时只有 manifest 的 `protagonistIds` 可以切换为活跃主角。
- 关系、生活资产、记忆、Prompt 人物适配和 Debug 读取都必须携带 `universeId` 与 `roleId`；切换采用先校验、再更新设置、再刷新会话的顺序。
- 内置套装来自生产目录；用户套装存放在用户数据目录，先经过 schema、来源、引用和路径校验。

### 3.2 Debug 信息架构

- 顶层筛选：全部世界观、当前世界观；世界观内再筛选全部人物、主角、朋友。
- 功能分组：主对话、朋友圈、日程、生图、记忆、工具协作等。
- 条目标签：通用协议、人物适配、人物无关、动态组装、已注册、待补齐。
- 详情优先展示功能目的、适配状态、四层组合关系、人物来源和最近使用；变量、完整正文、来源和指纹按需展开。
- 目录只读；实验副本仍沿现有隔离 Playground 入口，不直接修改生产资产。

### 3.3 用户生成人物

- 新增运行时 `character-system-builder` Skill，使用现有 Skill Registry 和受限工具白名单。
- Skill 负责收集用户目标、世界观、人物身份、表达、关系、生活、视觉和功能适配材料，生成结构化草稿，不直接写生产 Role Pack。
- 草稿保存到用户数据目录的独立 draft 记录；用户确认后才发布为 user-owned universe / role pack。
- 发布前必须通过 schema、引用完整性、主角唯一性、关系同世界、Prompt 适配覆盖和敏感内容检查；失败不写入半成品。
- 用户资产不能修改平台约束、权限策略、内置世界观或其他用户资产；删除、发布和切换需要明确确认并保留版本。

## 4. 影响范围

- 共享类型、Universe loader、设置 / Companion IPC、Debug Prompt 目录、Skill Registry、用户资产存储、人物制作 Skill、测试和文档。
- 现有默认世界和路飞数据保持可读取；朋友角色不再被误计为主角。
- 需要补充跨世界隔离、切换失败、用户草稿失败、发布回滚和权限边界测试。

## 5. 实施步骤

1. 补齐世界观 manifest 的主角 / 卡司 / 所有权与 Debug 投影，先验证默认《海贼王》范围。
2. 为 Prompt 资产增加世界观、人物、功能分组和适配状态，完成 Debug 标签 / 筛选 / 详情展示。
3. 建立世界观切换服务与 IPC，验证原子切换、当前主角校验和跨世界隔离。
4. 建立用户人物生成草稿、校验、确认发布和版本回滚链路。
5. 将人物制作 Skill 接入运行时工具，使用路飞和一套隔离测试世界完成正反例。
6. 更新模块卡、质量门禁、进度和变更日志，运行类型、测试、构建、资产和文档检查。

## 6. 风险与权衡

- 用户生成需要持久化和发布边界，不能直接把开发者 Skill 原文暴露成任意文件写入能力。
- 世界观切换会影响当前会话和生活数据；宁可阻止不完整切换，也不能用默认世界回填缺失资料。
- Debug 信息增加世界观与人物标签，但默认仍保持摘要优先，详细层级按需展开，避免重现 Alice 目录的过载问题。

## 7. 完成条件

- Debug 能清楚区分世界观、主角、朋友和人物适配状态。
- 默认《海贼王》世界的路飞主角与四位朋友角色通过真实 loader、关系和 Debug 证据验证。
- 至少两套隔离世界观可切换，数据、Prompt、关系和生活事实不串世界。
- 用户可以通过受限 Skill 完成“草稿 → 审阅 → 发布 → 使用”的人物生成流程。
- 内置资产与用户资产来源、版本、权限、回滚边界清晰，所有门禁通过后再冻结合同。
