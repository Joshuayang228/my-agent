## 1. 背景与现状（Why）

文化角展示伙伴在读、在看、在听，以及自己的摄影作品，不做作品资料库或所有生图的相册。书籍、影视、音乐、摄影的图片比例和内容语义不同，混在“全部”里会失去清晰的浏览路径。

现有代码已支持 `culture` 的 `reading / film / music / photography`，并把 `bookshelf` 归入阅读；`WorldCultureContent` 目前将四类放在混合网格，展开全部正文和独立读书笔记，`WorldDetailsPanel` 仍允许用户维护资产。这些都是现状，不等于新方案已落地。

数据已有按主角隔离的 `companion_assets`、生成图片引用、读取与备份链路。现有 `payload` 为开放对象：大部分字符串按短标签截断，仅部分正文支持 4000 UTF-16 代码单元；不能直接用现有写入规则承接新的完整字段。

已核对本地 Alice 生活资产参考章；没有从该章取得可直接复用的四类文化角字段设计证据。本方案复用项目已有资产、图片预览与事件服务，不为对齐 Alice 删除文化角，也不复制衣柜的穿着语义。

## 2. 已确认目标（What）

- 仅四个标签：书籍、影视、音乐、摄影；不设“全部”，默认书籍。
- 书籍使用竖版封面，影视使用竖版海报，音乐使用方形封面，摄影保留原图比例。
- 卡片只呈现主要信息；完整感受、笔记和进展进入作品详情，不在列表全文铺开。
- 摄影是伙伴自己的作品集；朋友圈配图、衣物图和其他生成图片不自动进入。
- Agent 负责新增、更新与移出展示；用户浏览、查看详情、预览图片，通过对话参与，不提供增删改表单。
- 所有控件、详情容器与图片预览复用 Foundation。设计先进入 Playground，用户明确许可后才回流正式页。

## 3. 页面与交互

### 3.1 列表

四类共享标签样式、内容边界、间距和焦点行为，但不强行共用同一种图片裁剪。分类切换不改变标签行占位，也不触发生成或生产写入。

| 分类 | 列表内容 | 图片规则 |
|---|---|---|
| 书籍 | 书名、弱化作者、阅读状态徽标；独立展示最新笔记短摘录 | 封面框 2:3；不裁掉封面文字 |
| 影视 | 片名、观看状态、最多两行感受摘要 | 海报框 2:3；电影、剧集语义保留在数据中 |
| 音乐 | 名称、歌手；听感摘要按需显示 | 封面框 1:1；不在第一版添加播放控件 |
| 摄影 | 照片、短标题；地点与作品时间可选 | 按存储的宽高预留空间，保留横竖比例；不强制瀑布流 |

空值不显示“未知作者”等假信息。名称最多两行，完整名称可查看。长感受只截展示摘要，原文不得截断保存。书籍也不把所有笔记再次复制到列表下方。

影视观后感与音乐听感的展示事实源统一为 `detail`；列表直接两行截显同一正文，不把独立 `summary` 当作另一条感受。若 `detail` 为空白而仅有 `summary`，列表与详情共同使用该摘要；两者都没有时隐藏。此规则仅落在候选，不改写原数据或书籍 / 摄影的展示语义。

### 3.2 详情与预览

点击标题或详情按钮打开作品详情；点击图片打开共享图片预览器，不能把两个动作混为一体。详情使用已有 Foundation 容器，固定合理的视口上限，正文内部滚动；长笔记不得拉长整页。关闭后恢复列表位置和触发点焦点。

详情按真实数据展示作者 / 创作者、状态与进度、完整感受、独立记录和图片来源；评分、播放次数、设备参数等保留字段不默认展示。`detail` 与 `note` 同时存在时都保留，不以其中一个覆盖另一个。

2026-10-07 用户确认的书籍修正：作者为普通弱化文本，阅读状态使用共享 Foundation Badge，不与笔记同样式。书籍列表不再展示整体感受摘要，只显示最新一条笔记的两行摘录，无笔记时不留空区。书籍详情顶部返回，书目区小封面在左、名称 / 作者 / 状态 / 已有进度在右；下方分开呈现整体感受与多条独立读书笔记，笔记逐条排列，时间与页码 / 章节弱化；长文在详情内滚动。当前仅候选，其他三类布局不变。

### 3.3 状态

2026-10-07 后续候选范围：影视列表展示片名、电影 / 剧集语义、观看徽标与可选观后感短摘；详情采用小海报与资料并排，已有剧集进度独立呈现。音乐列表展示名称、艺人、单曲 / 专辑语义、收听徽标与可选听感；详情采用小方封面与资料并排，不添加播放器。摄影列表保留横竖比例，地点 / 描绘日期为弱化元信息，不以“作品”徽标重复说明；详情以较大作品图开头，再展示标题、地点 / 日期和创作说明。缺失信息直接隐藏，不预留空白元信息或感受区；三类长正文内部滚动，图片仍使用基础预览。只调整 Playground，书籍既定布局和正式默认分支保持不变。

分类至少覆盖默认、空、读取失败、长名称、长笔记、无图、生成中与生成失败；摄影补横图、竖图和混合比例。图片加载、hover 与辅助按钮显隐不得改变占位。

列表打开、切换标签或查看详情均不自动产生生图费用。图片失败只影响展示，不撤销作品记录；重试与生成经明确的对话 / Agent 动作触发，不在作品页新增维护按钮。

## 4. 数据合同（How）

以下字段是拟实施合同，不宣称当前共享类型或数据库已支持。采用公共作品字段、类别扩展与独立生活记录，避免把不断增长的笔记塞进一个 payload 数组。

### 4.1 公共作品字段

| 字段 | 值 / 默认 | 含义与约束 |
|---|---|---|
| `id / roleId` | 必填稳定 ID | 作品及其主角归属；同名不同版本不能按名称合并 |
| `kind` | `culture` | 统一文化资产语义；书架读取见数据收口章节 |
| `schemaVersion` | `1` | 新结构版本，不以是否有图片判断版本 |
| `type` | `reading / film / music / photography` | 四类固定枚举，写入时拒绝未知值 |
| `name` | 必填，1–120 代码单元 | 作品名称；不得沿用通用资产 40 字上限或 24 字截断 |
| `creators` | 字符串数组，默认 `[]` | 作者、导演、艺人等；最多 20 项，每项不超过 120 代码单元 |
| `summary` | 可空，最多 240 代码单元 | 卡片感受摘要，不是作品百科介绍 |
| `detail / note` | 各可空，最多 4000 代码单元 | 完整感受与笔记，保留换行，超限拒绝整次写入 |
| `visibility` | `visible / archived`，默认 `visible` | 移出展示不删除关联事件与历史记录 |
| `origin` | `role_pack / agent / user_request / life_event` | 创建来源；用户对话提出意图不等于直接写库 |
| `sourceEventId` | 可空事件 ID | 创建事件来源；其他关联继续复用事件关联表 |
| `externalRef` | 可空 `{provider, id, url}` | 外部作品标识，不自动抓取或下载；URL 仅允许 http(s) |
| `createdAt / updatedAt / archivedAt` | UTC 毫秒；最后一项可空 | 系统记录时间，不能冒充阅读、观影或拍摄时间 |
| `revision` | 从 1 开始递增 | 防止迟到写入覆盖新状态 |
| `image` | 可空现有 `GeneratedImageReference` | 复用受控媒体引用，不在 payload 存字节或任意文件路径 |
| `imagePurpose` | `interpretation / photographic_work` | 文化示意配图或摄影作品；生成示意图不冒充官方封面 |
| `imageState` | `none / pending / ready / failed` | 图片状态与作品状态独立；ready 必须绑定有效引用 |
| `imageRequestId / imageSignature` | 可空 | 同作品最新请求与内容签名，迟到结果不得覆盖新图 |

`creators`、归档、revision 与来源在第一版真实服务中校验和保存；保留字段不是允许任意 JSON 绕过校验。图片引用的当前 mime / 路径限制继续遵守真实媒体服务，不靠合同放宽。

### 4.2 类别字段

可空表示没有证据，不自动补事实。枚举必须校验，数字有限且非负；比例范围为 0–1。资料字段没有来源时留空。

| 分类 | 字段与允许值 | 使用方式 |
|---|---|---|
| 书籍 | `readingStatus: planned / reading / paused / finished / abandoned`，默认 planned | 第一版状态；finished 不能仅由进度比例推断 |
| 书籍 | `currentPage / totalPages` 可空整数；`progressRatio` 可空 | 第一版详情可展示；页码不得大于已知总页数 |
| 书籍 | `isbn / edition / publisher / language / publicationYear` 可空 | 预留书目资料，第一版不要求补全或展示 |
| 影视 | `mediaKind: movie / series` 可空；`watchStatus: planned / watching / paused / finished / abandoned`，默认 planned | 第一版状态与媒体区别 |
| 影视 | `season / episode / totalEpisodes` 可空正整数；`positionSeconds / durationSeconds` 可空 | 第一版详情按已有记录展示，不伪造播放进度 |
| 影视 | `releaseYear / genres / originalTitle` 可空 | 资料字段保留，不要求联网拉取 |
| 音乐 | `musicKind: track / album` 可空；`listeningStatus: queued / listening / revisiting / paused`，默认 queued | 第一版状态；音乐不强设“听完” |
| 音乐 | `albumTitle / trackNumber / durationSeconds / releaseYear / genres` 可空 | 预留资料，不是播放引擎合同 |
| 摄影 | `workStatus: draft / published / archived`，默认 draft | 第一版作品发布；published 必须有可用图片 |
| 摄影 | `caption / locationName / depictedAt` 可空 | 作品故事、虚构地点与描绘时间；不叫真实拍摄证据 |
| 摄影 | `creationMode: generated` | 本版生成作品明确标识；不推断真实相机 / GPS / EXIF |
| 摄影 | `seriesId / seriesName / tags / compositionNote` 可空 | 预留系列与创作说明，第一版不增加系列导航 |

公共预留字段：`favorite`（默认 false）、`rating`（可空 0–5）、`firstEngagedAt / lastEngagedAt / completedAt`（可空业务时间）、`engagementCount`（默认 0，只有已提交的真实事件才能累加）。预留字段全部具备验证规则，但不新增评分、收藏或统计 UI，也不由样张冒充正式事实。

### 4.3 独立记录

新增 `companion_culture_entries`：`id`、`role_id`、`asset_id`、`entry_type`（`note / reflection / progress / creation`）、`text`（最多 4000 代码单元）、`occurred_at`（可空业务时间）、`created_at`、`source_event_id`（可空）、`idempotency_key`。外键约束同角色作品，幂等键在角色内唯一；按作品与时间索引。

读书笔记补可空 `page`（非负整数，不超过作品已知总页数）与 `chapter`（最多 120 代码单元），不推断缺失页码、章节或发生时间。整体感受保留作品 `detail`，笔记多条走独立记录，不覆盖旧记录或把感受当成笔记。最新笔记按 `occurred_at`，无业务时间时按 `created_at` 降序，稳定 ID 决定同一时间的稳定次序；详情同序展示。Playground 用独立 `previewReadingNotes` props 模拟这条链，不以 payload 数组冒充后端实现。

作品当前状态是投影，记录是历史；同一事务更新作品、追加记录及事件关联，失败不留下半份进度。退休 / 归档不清历史；角色整体删除和备份恢复按现有数据生命周期同步处理。

## 5. 服务、来源与安全

继续使用 `ipc → companion/life → storage / llm` 的分层，渲染组件只接收 props，不读数据库，不拼模型配置。新增写入走明确的文化字段白名单服务；禁止直接把新字段交给通用 `applyAssetPayloadPatch` 静默截断。

Agent 动作边界为登记作品、记录感受 / 进度、发布摄影作品与归档作品；实际 Tool schema 必须注册生产资产并回归。用户请求由 Agent 调用受校验服务，禁止用隐藏 UI 表单代替这条链。角色归属在服务端检查，不信任客户端 roleId；字段超限、未知枚举、revision 冲突、跨角色关联整体拒绝。

生图复用统一生成服务、用途配置与受控媒体读取。书籍 / 影视 / 音乐可使用明确的示意配图，不编造官方封面；摄影必须通过明确发布动作成为作品，朋友圈图片可在明确选择后复用合法引用，但绝不自动收录。引用共享时删除 / 归档不能误删其他作品仍在使用的媒体。

Role Pack 有明确作品来源时才初始化，按来源 key 幂等；无来源为空。Playground 的四类样张和生成图片始终隔离，不能播种生产书目、笔记或摄影经历。

书籍新写入统一为 `culture(type=reading)`；既有 `bookshelf` 需要实施前盘点来源和引用，提供一次可验证的开发数据收口，不维护长期双写。用户不要求历史兼容，但不能因名称相同静默删除记录；清理旧数据须有明确授权和验证。本轮不执行迁移。

## 6. 影响范围与实施顺序

### 6.1 本轮

合同已存档，用户许可继续；当前施工边界为 Playground 四分类与页内详情候选，补示意图片、边缘态和隔离测试。正式页面、工具、数据库、Prompt 和生产数据不变；正式回流仍须独立许可。

### 6.2 可独立验收的施工边界

1. Playground 候选：复用 `WorldCultureContent` 并以显式候选 props 隔离四分类、详情和图比例；补默认 / 空 / 错误 / 无图 / 长文故事。所有动作只改实验内存，完成候选 E2E 与深浅宽窄验收。
2. 真实数据链：落实共享类型、字段校验、独立记录、来源与幂等、Agent 工具、生成资产绑定、备份恢复。新增 IPC 时同步四处；通过 Unit、真实 Electron 与失败路径测试。不得交付空按钮或假后端。
3. 用户明确许可后正式回流：统一新 UI，移除普通文化页维护入口；仅删除文化范围，不影响家居 / 足迹编辑。补正式角色切换、详情焦点、真实图片与来源隔离回归。
4. 收工：将当前事实吸入模块卡、架构、质量与账本，冻结合同；每个可交付边界独立验证、提交推送。

拟涉及 `src/components/world/WorldLivingContent.tsx`、`WorldDetailsPanel.tsx`、Playground 组合、共享类型、`companion/life` 服务、storage、tools、IPC / preload 与对应测试。当前范围不改变人物世界六个主切面、衣柜合同、模型配置、RAG 或 MCP OAuth。

## 7. 验收与风险

- 四类 tab 不混排，没有“全部”；默认书籍，切换保留对应列表位置；键盘、200% 缩放、深浅主题与窄宽屏可用。
- 详情内滚动，长名称 / 长笔记不遮挡；图片预览共用 Foundation，关闭恢复焦点；图片状态和 hover 几何稳定。
- 主角切换清旧展示，旧读取与迟到写入回调不能覆盖新角色；存储和服务端同时验证归属。
- 同名不同作品可共存；进度与记录同事务；重复 Agent 事件不重复追加记录或累加次数。
- 无 Role Pack 来源为空；摄影只有明确发布才出现；生成图来源可辨，不冒充真实作品封面或实拍。
- 生成失败保留作品，迟到图不覆盖新版；媒体引用读取、归档、备份恢复不破坏共享使用者。
- Unit、tsc、build、资产与文档门禁通过，E2E 区分候选夹具与真实能力；没有独立 lint 脚本时明确披露。

主要权衡：四类共用字段与基础控件，但类别状态和图比例分别维护；字段预留增加校验成本，不等于必须展示全部。官方媒体获取、音乐播放、联网书目检索、真实摄影导入与系列浏览明确不在本版范围，登记到 wishlist；不影响本版记录、展示和 Agent 维护的完整链路。
