# 施工合同：Debug 正式页面与 Playground 对齐修复 v4

> 状态：进行中
> 授权：用户明确“正式界面一堆 bug，启动目标模式，对齐 playground”。范围承接已批准的整批 Debug 回流。

## 背景（Why）

v3 回流完成记录只证明导航接入、部分阅读结构及文字 token 回流，不能证明各正式页面已采用独立候选结构或全部真实接口验收。复查发现正式领域页仍共用通用证据卡，系统状态和技能工具共享完整面板，上下文复用了完整调用管理台；Playground 的跨页调用定位也存在断链。

## 目标（What）

按 `src/shared/debug-navigation.ts` 的实际页面逐项建立候选与生产映射，修复真实 bug 和已批准形态的回流缺口。默认事实优先、技术证据按需展开；读取失败、空记录、未支持分别表达。只有导航、布局、交互、真实数据和失败路径均验证后，才标记该页通过。

## 技术方案（How）

- Foundation 和共享文字 token 是唯一视觉基础。优先提取无夹具的阅读组件，由正式数据适配与 Playground fixture 分别供给；禁止生产 import Playground。
- 生产入口为 `DevPanel`；领域事实走 `companionEvidenceScope / companionEvidenceQuery`，调用记录走 `llmLogsQuery / llmLogGet / assetUsageQuery`，系统和工具走现有生产聚合器，验收走真实报告接口。
- 跨页跳转传稳定目标 ID；目标不存在时明确缺失，不自动选择其他记录。异步响应只可提交到对应的当前范围与选中项。
- 尚无来源的主动消息索引不补造；实时事件仍明确为当前运行快照。若需要新增持久化模型、历史接口或诊断动作，先补充本合同中的真实数据与权限设计，不以 UI 修复名义扩展。

## 影响范围

允许修改 `src/App.tsx` 的 Debug 一级壳挂载、`src/components/DevPanel.tsx`、`src/components/debug/`、Debug Playground 候选及 fixture、对应单元/E2E 测试、Electron 测试匹配配置与本次文档。共享类型、IPC 和生产聚合器仅在定位到确切契约缺陷后按四处同步规则修改并记录。

不修改生产 Prompt、权限、安全模型、人物世界和其他页面行为，不引入新依赖。工作区内 Terminal、sandbox、thinking、memory 等存量改动不归本任务，不覆盖、不混入提交。

## 实施与验收

1. 建立导航→候选组件→生产组件→接口→测试的映射；结合实际截图和复现记录问题。
2. 每次只修一个根因，立即跑对应回归；正式页和故事同步，保留领域数据及关键诊断能力。
3. 逐页检查默认、首次失败、刷新失败保留旧证据、空态、长文本、窄宽、深浅主题与字号缩放；跨页检查目标定位和返回。
4. 自审后通过单元测试、类型检查、相关 E2E、build、资产与文档门禁。真实 Electron 读取与测试替身证据分别记录。
5. 更新运行时模块卡、Quality 和进展；独立可回滚修复通过后提交推送。完整目标在全部页面与必要接口验收后关闭，不能以样式或导航覆盖代替完成。

## 风险与权衡

旧综合 E2E 仍有对已退役布局的预期；必须先区分真实交互断链与旧测试契约，不能只删断言使结果变绿。没有 Electron API 的普通网页只能验收环境边界和视觉，不能证明生产查询成功。
