# Foundation 布局与间距施工合同

> 状态：进行中（2026-10-07，施工方案已确认；布局与透明度 P0 候选待人工验收）
> 生命周期：Phase P0；正式回流另需明确许可，自动检查覆盖范围以质量总控为准。

## 背景与目标

人物世界足迹详情的返回按钮已移到内容区左边，但正文仍使用 `mx-auto max-w-2xl`，媒体按钮还叠加通用按钮 padding 与局部 `p-0`。因此“使用了基础控件”并不保证边界一致。需要把布局标准放到用户可查看的基础展厅，并让组件与检查从同一事实源派生。

在现有「基础 → 设计语言」新增「布局与间距」和用户追加确认的「透明度」Tab，顺序为颜色、主题对照、布局与间距、透明度、形态与动效。不新增一级导航，不顺带重做现有主题和动效内容。

## Alice 研究证据

- `_reference/framework-harness/repos/alice-source/_extract/page-playground.js` 的 `lN`：设计系统分完整色板、透明度演示、允许例外、收拢记录；当前快照未见独立布局与间距分类。
- 同文件 `nM`：展厅外壳使用限宽、统一 padding 与滚动区，但其展厅居中策略不等于我们的人物世界详情策略。
- `_reference/framework-harness/repos/alice-source/styles/globals.css`：组织顺序为基础变量、重置、布局、通用组件、业务模块。
- 借鉴规范、例外与收拢证据同页可查，不复制颜色值、下划线 Tab、居中布局或产品语义。结论仅适用于本地参考快照，不宣称其当前发布版也如此。

## 设计与实现边界

| 层 | 职责 |
|---|---|
| Token / 共享布局定义 | 间距、内容宽度、响应式策略的唯一数值来源 |
| Foundation | 内容容器、限宽与对齐、媒体内边距接口和控件命中区 |
| 设计语言样张 | 调用上述实现，展示默认、边缘和错误对照，读取真实数值 |
| 产品体验 | 数据、业务顺序与操作；不得再覆盖同一布局语义 |
| Skill / 测试 | 开发规程与可执行判据，不复制另一套视觉参数 |

四组样张：边距与对齐、内容宽度、滚动边界、布局稳定性。以真实中文长短内容、图片和控件展示，不用说明卡片替代可操作样张。错误对照只属于隔离 fixture，不能进入生产默认值。

透明度通过图片背景上的局部表面演示；滑块及预设值只影响本地样张，采用背景色混合而非整块 `opacity`。仅外层表面有底色，文字节点背景完全透明，不重复叠加小色块，文字本身保持不透明。移除重复的「表面透明度」标题；百分比表示表面颜色占比，不代表文字透明度，不修改生产主题变量。

基础展示边界（2026-10-07，用户确认）：布局与间距不按 Chat / 设置 / 人物世界 / 工作区分类，只展示通用页面边距、内容宽度、区块间距、卡片内边距及对齐 / 滚动样张。密度使用紧凑 / 标准 / 宽松，统一读取共享间距阶梯；产品场景映射留在产品体验，不删除其已有共享引用。

布局约束：同级列表 / 详情共享内容左边界；正文限宽但默认左对齐；返回按钮按外框对齐，内部图标保留命中区。空态、图片预览、模态框和固定格式画布有独立规则，不一刀切。媒体使用明确无内边距契约，不能依赖 Tailwind 类顺序碰巧覆盖。

候选数据流：共享定义 → Foundation 实现 → 设计语言与人物世界候选 → 源码及浏览器检查。无需 IPC、数据库、LLM 或新增依赖。布局数值在施工时从现有基线抽取并展示，未验收前不宣称为全产品已采用标准。

## 影响范围与明确不做

### 已确认扩展：产品体验间距收口（2026-10-07）

用户确认继续核查 Chat、设置、人物世界与工作区的页面边距、内容组间距、卡片内边距。共享定义按场景保留密度；展厅只读取同一来源，不复制另一份数值。允许修改 Playground 页面组合及共享设置 / 记忆 / 世界组件的显式布局变量消费点，正式调用未注入候选变量时须保留原值和行为。侧栏导航、图片网格、控件命中区、代码 / 终端画布属于独立尺寸契约，不能用通用内容间距覆盖。

本批独立验收边界：四类场景的布局参数、主要内容容器和设置共享卡片 / 内容组引用；浏览器验证不同场景、窄宽、深浅、交互与正式默认值。复杂业务控件的内部尺寸不批量替换，源码检查只声明实际受检节点，不宣称所有 CSS 裸值均被禁止。

- 可修改：`DesignSystemPanel.tsx`、必要的共享布局定义 / Foundation、对应故事与资产注册表、隔离测试、足迹候选，以及文化角 / 家居的显式候选接口。
- 不修改正式 App、Sidebar、世界页面默认布局，不自动回流；不改后端、人物数据、主题选择逻辑或图片预览布局。
- Foundation 新接口保持默认行为不变；若文化角 / 家居无法隔离候选差异，先回到方案讨论，不绕过 P0。
- 模块卡只登记实际落地能力；本合同不冒充完成记录。施工完成同步 UI 模块、质量与进度文档。

## 实施步骤与验收

1. 确认本合同；盘点现有 token、容器与调用方，选取唯一共享来源。
2. 建立共享布局接口及 Foundation 故事：默认态与长文本 / 窄宽边缘态；同步注册表一致性测试。
3. 新增设计语言 Tab，使用现有基础 Tab 控件；不新增下划线、不造独立皮肤。样张切换、键盘和尺寸稳定性均可验收。
4. 足迹、文化角、家居候选引用同一布局实现，检查返回、标题、正文和图片边界；返回恢复原列表焦点与滚动。
5. 自审后按序运行类型、单元、构建、浏览器和文档门禁；用户实际查看候选并授权后，才能开启 P1 正式回流。

验收要求（当前定向实现见 `docs/quality.md`，不代表全产品覆盖）：

- 源码规则检查真实 JSX 调用与禁止覆盖，带允许例外清单；正例通过、故意重复 padding / 居中的负例必须失败。不得以全仓字符串命中替代语义检查。
- 同级边界偏差 ≤ 2 CSS px；hover / 非 hover 外框尺寸及相邻位移 ≤ 1 CSS px；媒体加载前后保持约定尺寸。
- 深色与浅色，宽 1096 / 746 CSS px，并覆盖 200% 缩放：无非预期横向溢出；长详情在指定内容区滚动，不撑开壳层；窄屏限宽不超容器。
- 图片加载 / 失败、长名称与长正文、键盘切换、返回焦点及滚动恢复可达。几何测试检查结构边界而非字体字形；截图补充视觉验收。

## 风险与权衡

共享容器能减少漂移，但不可将全部页面强制成同一宽度或滚动模式。AST 检查只证明受检调用路径，必须与浏览器测量结合。现有无关存量修改不纳入本任务提交；若共享文件冲突，按具体差异隔离，禁止覆盖他人改动。

本合同补充 [设计语言 v2](./foundation-design-language-v2.md) 的布局部分，与 [基础复用工程化合同](./foundation-reuse-enforcement-v1.md) 共用复用目标，不替代其未完成范围。
