# 生图产品能力接入 v1

> 状态：已完成施工快照（冻结）
> 生命周期：已完成施工快照（冻结）。Playground 候选、正式 Chat / 人物世界回流、真实媒体链和备份恢复均已完成；提示词策略与自动朋友圈生图仍明确不在本快照范围。
> 施工范围：统一生图能力的产品接入，不修改生图提示词策略

## 需求背景（Why）

当前项目已经具备用户主动生图的真实后端链路：独立生图模型配置、权限审批、模型请求、图片归一化、项目落盘、会话引用、预览、定位、备份恢复均已存在。但这些能力主要以 Agent 工具为入口，人物世界仍只有文字生活资产，产品没有统一的视觉资产闭环。

Alice 的产品经验是：图片不是独立的“生成器页面”，而是人格、生活和对话中的可见资产。我们的实现必须复用同一套生图配置、安全边界、图片引用和读取契约，避免聊天、人物世界各自造一套图片系统。

## 功能目标（What）

1. 对话继续支持 Agent 通过 `image_generate` 生成真实图片，并把图片结果稳定显示在主聊天、侧聊和历史消息中。
2. 对话提供明确的用户主动生图入口；入口只负责提交用户意图，真实调用仍由 Agent / 权限链处理，不绕过审批和工作区边界。
3. 人物世界支持视觉资产：至少能为当前角色创建、读取、展示、删除一张与生活资产关联的图片；第一批覆盖家居、衣柜、文化角和足迹的图片引用能力。
4. 视觉资产与文字资产使用角色隔离、持久化、备份和恢复；Renderer 不接触任意路径，只通过主进程受控读取。
5. Playground 先验收统一的生成中、成功、读取失败、空态和删除状态，再回流正式 Chat / 人物世界。

## 明确不做（本合同范围外）

- 本轮不制定人物视觉 Prompt，不自动为已有角色补生成图片。
- 本轮不做图片理解、图片编辑、参考图编辑或多图合成。
- 本轮不做跨设备同步、云端媒体库、自动刷新、自动重试和跨供应商 fallback。
- 本轮不改变已有生图模型路由语义：生图仍只取独立 `image` 用途，不借用主对话凭据。

## 技术方案（How）

### 统一数据流

```text
用户主动生图 / Agent image_generate
  -> image 用途配置工厂
  -> 权限与工作区校验
  -> Images / Gemini 请求
  -> sharp 归一化
  -> 受控媒体存储与内容摘要
  -> GeneratedImageReference
  -> 会话消息或 companion_assets 图片引用
  -> 主进程校验后 data URL / 文件定位
```

### 数据与接口

- 扩展共享图片引用类型，区分会话图片与人物世界资产图片的归属，不让 `sessionId` 成为唯一读取入口。
- 新增 companion 图片 IPC，载荷只接受角色资产 ID / 图片 ID；主进程校验角色归属、真实路径、摘要、格式和大小。
- `companion_assets.payload` 保存结构化图片元数据，不保存 base64；图片字节由受控媒体目录管理。
- 备份继续复用现有 PNG 归一化、摘要和媒体限制，导出 / 导入与生活资产事务保持一致。
- Chat 主动入口复用 `sendMessage` 和 Agent 工具链，禁止 Renderer 直接调用远程生图服务。

### UI 边界

- Playground 的独立“生图实验”归入 Agent 实验，用于验证模型调用、读取、绑定和失败恢复；产品体验页只在 Chat 与人物世界各生活面嵌入隔离图片样张，不再把“生图”作为产品体验一级入口。候选只使用隔离 fixture，不写真实会话或角色资产。
- 正式回流必须通过用户验收；正式页面只引用共享 Foundation 图片预览和业务组件，不复制图片读取、错误、定位逻辑。
- 生成按钮、读取重试、定位、删除等操作固定尺寸，hover / loading 不改变布局。

## 实施步骤与验证

1. 固定共享图片引用、媒体存储和 companion IPC 契约；补 Unit，验证角色隔离、路径穿越、摘要变化、坏图和删除清理。
2. 接通人物世界视觉资产的真实生成 / 读取 / 删除链路；补 Electron 验证，覆盖家居、衣柜、文化角、足迹至少一类真实往返。
3. 在 Playground 建立 Chat 与人物世界的统一视觉候选，覆盖默认、生成中、失败、空态、窄宽和深浅主题。
4. 用户验收候选后，回流正式入口；补主聊天、侧聊、历史重载、备份恢复和无配置失败路径。
5. 按顺序执行自审、Unit、类型检查、build、UI / Electron、资产检查、文档门禁；更新伙伴模块卡、架构、进度和 changelog。

## 风险与权衡

- 复用现有会话图片目录可以减少协议重复，但人物世界图片不能依赖 session 生命周期，因此需要独立归属索引和清理策略。
- 直接让 Renderer 调用生图会绕过权限、费用和工作区校验，明确禁止；用户入口必须进入现有 Agent 权限链。
- 第一版不做自动生成，避免在打开人物世界时产生不可控费用；用户明确触发后才生成。
- 删除人物世界资产时是否物理删除共享图片，需要按引用计数验证；在完成引用索引前不得粗暴删除图片文件。
