## 全量收口施工方案（2026-10-27，待确认）

### 目标与本次边界

用户要求先出方案，再以目标模式完成提示词注册、集中展示和缺失提示词补齐，之后开始首个人物共创。本节是下一轮施工范围；前批次授权与证据保留，不把它当成本次新增产品流程的批准。

“全部”以当前六条用户旅程、人物世界六面、模型 / 工具出口和本合同已经发现的生成缺口为边界。已有功能需要生成但没有 Prompt 的必须补齐；缺消费链的同时补齐必要的触发、事实输入、输出校验、保存和失败处理。新增模板不能停在未消费状态。通用能力完成后，人物专属事实和风格仍由用户共创决定。

本轮沿用现有模型工厂、注册表、签发体系、生活事件、图片安全保存和防打扰机制；不更换技术栈，不新建另一套 YAML 引擎。Alice 的统一来源、按用途分组、模板变量发现和人物映射可复用；其多语言、可编辑 Debug 和全部独立子代理不直接移植。已核 DEC-034 / DEC-036 / DEC-038 / DEC-040，保留单活跃主角、身份 / 世界 / 表达分工、显式注册与全页只读 Debug。

### 工作一：注册与消费统一收口

- 从实际入口反查生产定义：Renderer 预填、主对话、后台生活、记忆、图片 / 识图、Skill / Tool 包装、MCP 和 Eval。登记固定指令与动态包装；用户资料、图片描述、外部返回和向量化原文保持运行时数据身份。
- 每项固定 key、真实定义符号、中文用途、责任归属、版本、指纹、依赖、输入变量、消费者、触发、输出协议、解析和回退。实际正文继续在生产常量或 Role Pack；注册元信息不能复制正文。
- “定义存在、登记存在、调用存在、验证存在”分别检查。新增来源、别名 / 间接调用、图片独立出口、错配资产和漏接消费者都有负例；注册与展示成功不替代行为验证。
- 生产注册表与加载器提供 Prompt 目录；旅程覆盖关系是元数据索引，引用真实 key / 消费者，不维护第二份 Prompt 清单或第二份功能总目录。

### 工作二：集中展示按开发者阅读目标收口

继续使用 Debug 提示词管理器的“用途目录 → 条目 → 完整正文”结构。默认只回答：有多少提示词、主要提示词在哪里、选中这条写了什么。数量按真实唯一 key 计算，Prompt 与其他资产分开，加载失败不补零。

建议目录顺序：主对话与人物表达 → 生活世界 → 朋友圈与互动 → 视觉与图片 → 记忆与成长 → 主动消息 → 工具与技能 → 平台与协议 → 验收。人物筛选保留实际继承的共用提示词；分类和顺序由登记用途派生，不在 UI 再手写完整目录。

详情默认仅名称、复制和完整正文。变量折叠后提供中文含义、事实来源、更新时机与缺值处理；有助于理解时展示明确标注的隔离示例，不把变量名当解释，不把演示值当实发值。模板、可执行配方和已保存调用各自标明；没有保存的历史输入不能重建。版本、指纹、源码符号和调用证据继续折叠。

字体、字号、行高、间距、边框和控件全部使用 Foundation。继续逐页核对，但所有候选验收后集中回流；前端 skill 只沉淀可复用规范，本次施工顺序写在合同。布局和新回复 / 确认交互先在 Playground 展示，用户实际查看并明确许可后再正式回流。

### 技术方案与文件范围

主要修改 `electron/main/prompts/`、`companion/identity` / `life` / `growth`、`memory/`、相关模型适配与已有 IPC / preload / shared 契约。数据迁移只为确需保存的评论线程、生成任务身份和来源提供兼容读取；不重置现有用户数据。涉及四处 IPC 必须同步，新增网络 / 模型路径继续使用统一工厂和受控出口。

展示改动限 Debug 阅读组件、对应 Playground 故事和 Foundation 复用；新产品回复或资料确认使用原生活面与基础组件。工具 / Skill / Provider 本身不因目录完善被整体重写。既有不属于本目标的工作区改动保持原状；同一文件确需修改时先核对差异并隔离本轮提交。

人物扩展最终落在 loader 支持的 Role Pack：稳定身份、档案、默认世界、表达、成长与各场景行为增量。新行为需同步 loader、资产 key 工厂、编译与测试，不能只新建一个无人读取的文件。完成后更新 `character-system-builder` 的项目映射和覆盖维度，让后续 skill / 人物团队扩展沿同一套契约消费；不在技能里复制生产 Prompt。

### 施工顺序与统一验收

1. 生成逐功能覆盖基线，锁定缺失 Prompt 和缺消费链；每项都有可验证的完成条件。
2. 完成注册契约、消费关系和防漏门禁，先让缺口能够被检查发现。
3. 补齐公共文本行为、社交回复、记忆和生活生成；再补视觉策划 / 识图与主动表达，各项带真实接线和失败路径。
4. 并行于实际数据契约演进制作集中展示与新增交互的 Playground 候选，逐页检查信息量和基础规范；统一取得回流许可后接入正式页。
5. 全量整体验收：类型、Unit、构建、资产、文档；浏览器覆盖深浅主题、宽窄、字号 / 行距、复制、搜索、变量 / 来源展开与错误恢复；独立 Electron 验证真实注册目录、回复 / 资料保存及重启幂等。
6. 冻结本合同前将稳定事实吸入模块卡和架构 / 质量，提交推送，列出人物共创所需决策和材料。此时才进入具体人物写作。

每个内部施工单元完整可验证，整体目标不因其中一个单元完成而结束。真实付费模型 / 生图效果验收须另有明确调用授权；本地协议和测试替身证明接线与边界，不证明人物表达或画面质量。

**结束条件**：范围内没有仅存在于目录、没有消费者的生产 Prompt；每个需要生成的当前功能都有注册定义、真实消费者、输入来源、输出校验、失败处理和测试；管理器能清楚阅读真实全量目录；新增人物不需要逐个修改功能里的硬编码人设。

### 风险与明确不做项

- 视觉、自动回复和记忆整理涉及费用、并发、归属及持久化，复杂度高于写模板；本轮按完整闭环施工，不以固定假结果或 TODO 交付。
- 范围不包含把 Alice 全部独立子代理照搬进来、群聊 / 多主角同时生活、新的旅行系统或多语言 Prompt 引擎；这些是独立产品 / 架构目标。当前旅程所需记忆能力在已有服务边界内补齐。
- 既有 Node 工程类型债与其他未提交修复不伪装成本目标完成成果；本轮新错误必须消除。

## 背景与授权边界

用户最初要求“把所有的提示词，包括记忆提炼那些都梳理清楚，看看 Alice 梳理了哪些，是怎么做注册的”。最初盘点阶段只读；其后用户明确授权按旅程补齐，当前生产施工边界与结果以下文“旅程补齐授权与施工边界”为准。提示词管理器已回流，不代表全部输入来源及语义质量已闭环。

以当前工作区为证据，基准提交 a481be60；既有 memory-store、工具权限、运行时等无关未提交修改保持原状，不属于本次变更。数量均为本次快照，不作为运行时永久常量。工具、用户 Skill 与 MCP 数量随加载变化，本轮不启动它们来补数。

## What：完成的定义

1. 每条会进入模型或生成系统的路径，能说明固定规则、包装、人物增量、运行时数据和输出协议分别来自哪里。
2. 固定指令及系统提供的请求预填有真实来源、稳定 key、版本与指纹；运行时用户文字、生成结果、记忆和图片描述不逐条伪装成内置资产。
3. 聊天、后台提炼、生图、Embedding、前端入口和 Eval 明确不同的调用边界，测试对边界外路径不能作全量承诺。
4. 模板占位符、登记的语义输入和实际展开值分别解释；不编造变量含义，不拿当前模板重建未保存历史。
5. “有注册 / 接入调用 / 内容已审阅 / 效果已验证”分别记录；共享规则审阅与人物写作分开。

### 记忆不是一个单独 Prompt

- 自动提炼：当前画像提取 Prompt 支持 identity / workflow / voice / preference / fact / feedback；输入包含用户与助手近期对话，并携带已知事实防重复。生产校验另限制类别、长度、数量和敏感内容。
- 显式记忆：remember / recall / forget 等工具及其 schema 从真实 ToolRegistry 进入目录；显式工具操作不等于后台自动采集。
- 六个策略 key：profile-extraction、semantic-deduplication、feedback-bucket、vector-recall、vector-lifecycle、citation-correction（均以 memory-strategy: 为前缀）。它们来源于真实代码，不都是 LLM Prompt：当前去重是文本相似度规则，纠错也有确定性计划。
- 召回：向量输入 / 索引 / 阈值属于数据与策略；给主对话的固定包装才是 Prompt。对话压缩服务上下文窗口，不自动等价于长期记忆写入。
- 与 Alice 不同：尚不能把“已有自动画像”说成“已有完整项目记忆子代理、情感提炼、记忆重整与迁移能力”。是否增加这些能力须按我们的旅程与数据边界决定。
