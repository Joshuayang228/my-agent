## 背景与目标

上轮已冻结合同仍留有重复运行态、过渡适配层和恢复边界漏洞。本合同以真实调用链和故障测试验收完成程度。保留模块化单体、状态快照与事件历史的设计，执行生命周期遵循 DEC-2026-11-13-01，Capability 遵循 DEC-2026-11-13-02。

## 技术方案

1. 修复数据库本地事务提交后的持久化、并发隔离及失败恢复，真实磁盘重开证明提交结果。
2. 命令重试重新领取执行所有权，记录 attempt，迟到执行不得覆盖新执行结果。
3. Companion Core 拥有正式运行态和生活持久化边界。删除旧运行态回填、world_json 镜像和仅转发的 legacy 适配，调用方与测试同步迁移。
4. 逐个核验赠礼、信物、文化体验、日记、动态、关系和评论的事实、事件与 Outbox 提交。查询投影采用同库事务同步提交，异步外部投递采用 Outbox 恢复。
5. 核验 Application、Runtime、Host、Scheduler 和 Headless 的生产入口、权限、取消及上下文，补充结构门禁防止旧依赖回流。
6. 核验主动行为跨入口策略和 Memory 配置边界，任何未完成项保留在本合同并继续施工。

## 影响范围

允许修改主进程 storage、companion、agent、agent-host、scheduler 及真实调用方、测试、共享契约和对应文档。现有生活表可作为正式领域存储保留，不以表名的新旧判断事实归属。删除旧状态镜像及转发文件的目的是消除双写与无意义间接层，全部调用方和测试随迁移更新。

不增加后向兼容迁移，不改变人物设定或未经批准的 UI 视觉。新增依赖需要说明用途。外部模型质量由真实授权配置验证，测试替身只能证明协议和失败恢复。

## 实施与验收

- 根因复现测试先失败，修复后验证正常、失败、重启、重复和并发路径。
- 所有生产调用方和测试完成迁移，结构扫描拒绝过渡状态存储和被删除模块。
- 自审后运行 Unit、双进程类型检查、构建、Eval、资产、文档和 Electron 回归。
- 稳定事实回流模块卡与架构文档，验证后冻结合同，提交推送并确认工作区干净。

## 风险与权衡

全面事件溯源会改变删除、备份和内容保留语义，本次沿用已确认的快照与历史设计。模型和网络等待必须位于事务外。兼容层删除会让旧开发数据库的旧状态不再回填，当前版本直接从 Role Pack 初始化缺失的 Core 状态。
