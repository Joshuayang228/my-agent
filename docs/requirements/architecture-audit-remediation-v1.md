## Why

基线 fa210bc3 的 WISH-050 审计包含 A01—A18。已有事务、权限和隔离部件尚未形成所有生产入口一致的执行契约，必须逐项以真实失败路径验证。

## What

完整关闭 A01—A18，保留模块化单体、状态快照与事件历史、既有 Loop / Permission / Tool Runtime。已冻结旧合同保留历史快照，新合同负责本次施工。

## How

1. A01 提交后的磁盘失败立即隔离已提交内存数据库，拒绝后续读写与保存；重启从成功磁盘快照恢复。不得允许失败事实被下一次 persist 夹带，也不得用恢复内存的假成功掩盖失败。
2. A02、A05、A12 以完整 Manifest 和会话 / run 上下文装配实际工具、模型、身份、Skill 与权限，移除重新创建宽权限默认 Manifest 的旁路，以及 Skill / task-plan 全局单值状态。
3. A03、A04、A15 传播稳定操作键、执行所有权、trace、signal 和 deadline；本地事实事务提交前 fencing，外部模型与网络保持事务外，超时和迟到执行不能继续提交副作用。
4. A06、A07、A13 将 Scheduler occurrence、后台任务关键状态、待投递终态和必须完成的后续动作纳入持久恢复。复用现有任务和 Outbox 的幂等键，避免创建平行执行框架。
5. A08 统一特权 IPC 注册和实际 sender 来源，测试省略事件只存在于测试适配层。异步诊断请求按 sender / request 绑定并取消。
6. A09 根据当前公告和真实调用升级锁定依赖并验证 MCP / 图片 / Markdown / 构建。声明升级清单，拒绝无依据强制降级。
7. A10、A14、A18 以已提交人物事实驱动关怀冷却、跨入口打扰预算及问候会话幂等，后台 run 在模型后、本地提交和投递前复核人物 / universe / 生命周期。
8. A11、A16 把 Electron / Host 调度和文件适配移到组合边界，Tool / Workflow 共用应用用例，只读查询不隐式创建事实。
9. A17 隔离测试文件目录，修正已确认界面的漂移断言，加入完整依赖和行为门禁，不提高超时或削弱断言来伪造通过。

## 影响范围与删除授权

允许修改 electron/main 下 agent、agent-host、companion、storage、services、scheduler、tools、skills、ipc、llm、memory、组合入口与对应共享类型、preload、测试、依赖及文档。删除对象限定为审计指出的全局 Skill / task-plan 默认会话状态、默认宽权限授权旁路、Domain 向 Electron / Host / Tool 的错误入口和失效夹具，所有真实调用方随迁移同步。当前开发阶段不建立向后兼容层。

保留现有产品视觉。本轮如需新的视觉 / IA 方案，按既有 Playground 验收链处理。修复测试选择器必须对照真实界面，不能借修复修改产品样式。

## 实施顺序与验收

- 先复现 A01—A05 / A10 的审计反例，改为正确行为回归，完成独立可回滚批次。
- 再收口 Host / Runtime 装配、任务恢复、领域持久补偿、IPC 和生命周期，按入口覆盖正常、失败、取消、重复、并发与重启。
- 更新依赖、结构门禁与漂移测试，完整执行 Unit、双进程类型检查、构建、资产、Eval、UI 和 Electron 测试；每次失败先定位实际输入与状态。
- 每个可交付批次完成自审、文档、提交与推送，目标保持开启，禁止把单批通过当作全目标完成。
- 全部 A01—A18 完成后再做一轮独立源码审计，复审新增问题继续施工。未验证范围、真实模型配置缺失和接受的外部边界明确记录，不伪造已验证结论。
- 最后同步当前模块卡 / Architecture / Quality / Wishlist / Progress，冻结合同，确认远端同步与工作区干净，再关闭目标。

## 风险与权衡

sql.js 的内存提交与原子文件替换分为两步，提交后的磁盘失败采用显式故障隔离，应用重启后恢复最后成功快照。外部副作用不能通过数据库回滚撤销，必须依靠取消、提交前复核、稳定操作键和明确终态协同。依赖升级与持久化边界需要真实 Electron 回归，不能只依靠结构检查。
