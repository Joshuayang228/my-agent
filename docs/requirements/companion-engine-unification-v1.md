# 人物世界引擎统一与旅程闭环施工合同 v1

> 状态：进行中
> 生命周期：进行中，指导 P0 可靠性与 P1 旅程闭环施工。

## 1. 需求背景

朋友圈、评论、聊天生活共振、日记、信物、主动消息和日内生活推进已经分别具备能力，但部分入口各自处理触发、持久化、通知和失败恢复。用户能看到功能存在，却不能稳定感受到同一人物世界在连续运行。

本合同把审查重点放在用户旅程和真实调用链。目标是让事件、人物状态和投影之间可追溯、可恢复、按人物隔离，并让主动行为遵守统一的打扰与投递边界。

## 2. 功能目标

- 用户明确行为、AI 工具行为和 LifeTicker 行为进入同一事件与状态边界。
- 事件投影失败可重试，不产生“事实已完成但用户看不到”的半状态。
- 人物切换、暂停、恢复和 Catch-up 具备回滚与角色隔离。
- 朋友圈发布、评论、聊天共振、日记、信物和主动消息都能说明来源、结果和后续消费者。
- 每条用户旅程都有默认、失败、重复、重启和切换人物的验收路径。

## 3. 审查范围

### 3.1 入口

- Chat 工具：朋友圈发布、朋友圈评论、生活资产和阅读笔记。
- 人物世界 IPC：朋友圈读取、点赞、评论、日记、信物和生活状态。
- LifeTicker：日剧本、事件发布、朋友圈投影、主动问候、主动搭话、日记、换装、旅行、脆弱时刻、深夜反思、重排和作息关怀。
- Chat Resonance：聊天内容进入文化资产、日程、感想和后续回访。

### 3.2 统一不变量

- `roleId` 是每次生活写入和读取的强制范围。
- `companion_events` 是发生事实，`companion_moments` 是用户可见投影。
- 事件必须在领域副作用和投影成功后进入 published，失败保持可重试状态。
- activeRole 变化后，旧角色不得继续启动新的主动写入。
- 主动行为必须遵守冷却、每日上限、勿扰、用户设置和统一回执。
- 重试、重启和并发不能重复创建事件、动态、资产、消息或关系记录。

## 4. 用户旅程验收

| 旅程 | 必须成立的结果 |
|---|---|
| 聊天推荐作品 | 心愿入库、日程吸收、文化完成、感想回写和后续聊天回访使用同一角色事实 |
| 朋友圈发布与评论 | 动态归属正确、评论落库、人物回复可追溯、后续聊天能引用这次互动 |
| 角色自主生活 | 事件、当前状态、朋友圈、日记和 Prompt 薄切片来源一致 |
| 角色切换 | 旧角色暂停，新角色 Catch-up 成功或完整回滚，页面和会话绑定一致 |
| 赠礼与信物 | 礼物、回应、关系里程碑和信物展示来自同一次事实，重试不重复赠送 |
| 长时间离线 | 最近生活细补有界，更早内容摘要，失败可恢复，不能用打开时间伪造发生时间 |

## 5. 实施批次

### P0 可靠性与隔离

1. 修复事件投影提交顺序和可恢复重试。
2. 修复人物切换 Catch-up 失败回滚。
3. 让 ticker 在每个主动动作前重新确认 activeRole。
4. 补并发、重复、失败、暂停和切换反证测试。

### P1 旅程闭环

1. 沿聊天推荐作品旅程追踪 Resonance → 资产 → 日程 → 完成 → 回访。
2. 沿朋友圈发布 → 评论 → 人物回复 → 主会话回访旅程追踪真实 ID 和投递状态。
3. 沿角色生活事件 → 状态 → Moment → 日记 / Prompt 薄片旅程追踪来源和失败边界。

### P2 统一投递与可观测性

1. 统一主动消息的预算、冷却、勿扰和回执。当前已先落地生活 tick 级单条主动消息预算，并保留各动作自身的跨 tick 冷却与每日上限。
2. 为事件、投影、消息、资产和关系变化补统一执行账本查询。
3. Debug 展示真实来源、执行结果、失败原因和重试状态。

## 6. 当前已发现并修复中的问题

- 事件发布先写 published，再生成 Moment。投影失败会丢失朋友圈重试机会。
- 切换人物先写 activeRole，再执行 Catch-up。Catch-up 失败会留下半切换状态。
- ticker 只在批次开始解析 activeRole。批次中切换人物可能继续执行旧角色主动行为。

## 7. 验证要求

- 相关 Unit 覆盖正常、重复、失败、重试、并发、暂停和跨角色负例。
- 关键用户旅程使用 UI E2E 或真实 Electron E2E 验证入口、持久化和回显。
- 通过类型检查、完整 Unit、构建、资产审计、文档门禁和必要的 Electron 验证后才收工。

## 8. 明确不做

- 新增人物世界一级 Tab。
- 用 Debug 或 Playground 夹具冒充生产事实。
- 重写最终人物 Prompt、Role Pack 或 Agent Loop。
- 把普通浏览、打开页面或每次 ticker 都转成高成本生图或主动消息。

## 9. 功能必要性结论（2026-11-11）

- 主会话、记忆、关系 / 人物状态、朋友圈、LifeTicker、设置与事件执行记录属于核心闭环。
- 日记、信物、文化角和足迹保留为人物事实的用户可见投影，不各自创建独立事实来源。
- 衣柜、家居和通讯录属于增强层，只能消费核心事实，不能阻塞主会话与关系闭环。
- 共同决策保留为生活因果内部能力，不提供独立人物世界或 Renderer IPC 入口。
- 日记只能由人物生活与反思引擎生成；收藏和手动创建日记不再作为 Renderer / IPC 能力暴露。
