## 背景与目标

现有正式入口是 `DevPanel` 挂载的 `RegisteredAssetWorkbench`，不是旧 `PromptManagerPanel`。目录从 `debug:model-context-assets` 读取，包含提示词、人物资料、工具、策略、模型配置定义和验收资产。当前统一资产总数不能直接回答“有多少提示词”，详情也没有充分展示已有用途与行为合同字段。

本次服务开发者的三个连续任务：数清定义、读懂正文、追溯实际使用。沿用已采用的左右目录与正文工作台，不重新设计整个 Debug，不增加统计仪表盘。

参考证据：Alice 本地 `_reference/framework-harness/repos/alice-source/_extract/index-ppRSWnkN.js` 中的目录分组、常量 / 模板数量、人物与搜索筛选，以及 `sM` 详情的标识、变量、参数、字符数和复制；方法论第 13、14、19 章用于核对调用证据、动态注入与信息层级。参考实现中的多语言、直接编辑、固定字号和产品专属分类不迁入本项目。

## 功能范围

### 用户复核后的精简调整

用户查看 P0 后要求先逐项判断信息用途，明确认可取消笼统的“审阅信息”，并要求人物和重要行为靠前、平台靠后。当前候选仅保留找、读、复制，以及用途明确的变量、来源、实际调用入口；不再以一个折叠区保留所有元数据。不构成正式回流许可。

Alice 实现核对：`persona:getAllPrompts` 调用 `yamlPromptEngine.getAllPromptEntries`，后者沿登记 Map 的 values 返回；前端沿来源分组并用 `Object.entries` 展示，没有通用重要性评分。借鉴其稳定分组，不声称 Alice 已实现我们的人物优先排序。

阅读排序：主对话与表达 → 人物身份 → 成长与关系 → 世界与生活 → 记忆 → 工具与技能 → 验收 → 模型配置 → 其他定义 → 平台规则与上下文。候选以显式用途元数据、已登记资产类型和角色关联排序，同组用显式顺位及稳定 key 破同分；不看名称、文件系统顺序、最近调用或推测正文。未知用途不自动提升。正式接入时需将此阅读用途映射到真实登记语义，不能把 demo key 当生产规则。排序不改变注册、编译、依赖或运行时注入优先级。

施工删除记录：移除候选的形态筛选、重复类型标签、常驻其他资产数、计数说明块、字符数和行为合同表格；原因是它们不直接支持当前的查找与正文阅读。生产资产元数据和其他目录范围仍保留，版本 / 指纹仅在来源的版本信息中可查；没有删除生产规则或接口。原隔离旅行模板里的解释性收尾句从样张正文移除，保留变量和虚构任务标记，不改生产 Prompt。

### 计数与目录

- 默认聚焦提示词审阅，同时保留统一生产资产目录的完整访问能力；不是从注册表删除其他类型。
- “提示词定义”严格按生产 `assetType === 'prompt'` 统计，按稳定 key 去重，不以文件数、调用次数、字符数或正文推测替代。
- Eval Judge、伙伴场景、子 Agent 角色、Skill 与工具描述等其他可能影响模型输入的来源，保留明确类型和可达入口；不得因其不是 `prompt` 类型而消失，也不混入提示词定义数。候选中明确这一计数范围，避免把注册分类误读为所有自然语言指令的数量。
- 模板骨架与其组合器如果各有独立注册 key，分别作为定义计数；不得称为互不重叠的运行时指令数。一次模板展开不生成新定义。
- 当前目录范围显示唯一总数；有搜索或人物筛选时才显示命中数 / 范围总数，默认不重复显示相同数字。未成功读取时数量未知，不补零。
- 人物筛选区分人物专属与平台共用来源，筛选不切换当前主角，也不证明某次调用实际注入。
- 搜索覆盖名称、用途、正文 / 模板、变量、稳定 key 与真实来源；保留提示词 / 其他资产 / 全部资产范围，不新增独立形态筛选。列表只在必要时标注模板 / 动态组装，不重复写“提示词”。
- 静态正文、动态模板与仅有组装定义的项目分别标注。不能仅因存在变量便把结构化资产改称提示词模板。

### 详情阅读顺序

1. 名称及复制图标，不再重复展示用途、类型徽标和正文标题。
2. 完整正文或模板；自然语言与结构内容使用已采用的对应阅读样式。动态无固定正文时直接说明，不能隐藏在折叠区。
3. 有变量时提供“变量”入口，解释含义与来源；隔离示例明确标注非实际值，不给未知来源编造解释。正式接口当前只有 name / source / lifecycle，没有含义与示例字段；P1 不从变量名猜含义、不从模型补写示例，如需正式示例字段再确认类型与注册来源范围。
4. “来源”保留源文件、定义符号和稳定 key；版本与指纹在其内部按需查看。明确含义的名称不再重复一段用途；用途仍可搜索及通过标题提示访问。不显示无当前判断价值的行为合同表格、生命周期及依赖清单。
5. “查看实际调用”只提供明确保存关联的调用入口；候选的当前范围可展开选择具体调用，不在本页复制完整调用详情。保留范围、读取失败和缺失证据说明；没有调用时不按相似时间推断关联。

当前定义、模板演示、运行时插槽与历史实发输入是不同证据。没有保存完整输入时明确说明，不以当前模板回填历史，不为此静默开启详细日志或扩大采集。

### 展示取舍

| 处理 | 内容与原因 |
|------|------------|
| 默认展示 | 目录准确计数；详情名称、复制图标、正文 / 模板：直接支持阅读 |
| 按需展开 | 变量含义 / 来源 / 明确示例、源文件与定义符号、版本信息及调用入口：仅保留有明确审阅用途的内容 |
| 不展示 | 重复页头 / 报错 / 刷新入口、空洞宣传说明、旧 L1–L4 命名、内部调试标签、无实际数据的空区块、生产页面中的样张控制与展厅采用说明 |
| 始终可达 | 失败、未知、截断、证据范围、缺失目标与恢复操作：不能为了简洁隐藏影响判断的事实 |

“不适合开发者审阅”指缺乏阅读价值的重复或展示层内容，不等于隐藏来源、异常、权限边界和其他模型输入来源。不得展示凭据或扩大现有用户数据暴露范围。

验收时开发者应能独立回答：

- 有多少条注册提示词定义？其他模型指令来源在哪里？当前筛选是哪部分？

- 哪些人物会关联它，哪些是平台共用，关联是否等于实际使用？
- 修改依据来自哪个源文件 / 符号？历史调用有何已保存证据和缺口？

## 风险、权衡与明确不做

- “提示词数”存在定义与组合器重叠：明确统计注册定义，不制造唯一语义规则数量。
- 精简可能损害排查：采用默认阅读与按需证据两层，异常和证据边界不隐藏。
- 自然语言正文易被代码展示压缩：沿用 Foundation 字体 / 行距 / 颜色 / 边界，结构字段再使用代码样式，不复制 Alice 像素值。
- 本合同不决定主人公、不补人物经历，不把共享规则审查直接变成生产 Prompt 改写。共享规则中的重复、情绪响应、关系阶段与记忆边界分别保留审查结论；改写或运行逻辑修复需明确范围与对应验证。
- 不引入任意编辑、模型试跑、导出原始用户数据、自动采集完整请求、版本回滚或新审阅工作流。
