# 记忆系统与人物世界边界 v2 施工合同

> 状态：进行中
> 生命周期：Phase P0 Playground 候选施工；先重建记忆概念、归属和模块关系，未取得逐项验收前不得回流正式 UI。
> 建立日期：2026-08-31
> 统一称呼：施工合同

## 1. 需求背景（Why）

当前项目已经有结构化用户记忆、朋友圈、衣柜、文化角、家居、通讯录、足迹、Chat、设置和 Debug，但它们与“记忆”的关系还没有被完整定义。若继续直接向 MemoryPanel 增加分类和样张，会把用户记忆、伙伴生活、关系历史、当前任务和内部运行记录混在一起。

这会造成四个问题：

1. 用户不知道“记忆”究竟是关于谁的；
2. 人物世界和记忆面板重复呈现同一份内容；
3. 正在执行的动作被误当成长期记忆；
4. Debug、生活世界和普通用户体验互相污染。

本合同从用户故事重新定义记忆系统：**人物世界负责让用户看见伙伴，记忆中心负责管理会影响未来的长期信息，Chat 负责关系发生，Debug 负责解释系统实际做过什么。**

参考 Alice 的分层思想，但不照搬其 UI：Alice 的用户记忆类型是 `identity / workflow / voice / instruction`，同时将用户画像、向量记忆、阅读记录、生活事件和内部运行机制分开。我们的差异化在于加入“关系记忆”，并把 Agent 的生活内容主要交给人物世界呈现。

## 2. 产品目标（What）

### 2.1 北极星

```text
用户认识伙伴 → 和伙伴发生关系 → 重要内容沉淀 → 未来行为有连续性
```

### 2.2 记忆系统只回答三个问题

```text
关于你：Agent 需要长期记住用户什么？
关于我们：用户与 Agent 之间形成了什么共同约定和历史？
当前进行中：现在正在做什么？——不进入长期记忆，交给 Chat / 工作区 / Debug。
```

### 2.3 人物世界只回答一个问题

```text
这个伙伴是谁？它如何生活、喜欢什么、经历过什么、和谁有关系？
```

人物世界不需要用户先进入记忆中心，才能认识伙伴。

## 3. 记忆类型拆解（What）

### 3.1 用户记忆

归属：`user`

用户故事：**“它不要每次都重新认识我。”**

内容包括：

- 身份与背景；
- 做事方式与稳定习惯；
- 沟通偏好与相处偏好；
- 用户明确要求长期遵守的约定。

用户界面建议使用「关于你」，不直接暴露内部分类数量。现有 `identity / preference / fact / workflow / voice / feedback` 先作为兼容的内部分类；展示层逐步收敛为：

```text
关于我 / 做事方式 / 相处方式 / 重要约定
```

其中 `feedback` 是来源或形成方式，不再作为用户必须理解的主要分类。

### 3.2 Agent 记忆

归属：`agent`

用户故事：**“它是同一个伙伴，不是一张会说话的设置表。”**

内容包括：

- 伙伴稳定的自我设定与偏好；
- 从生活事件中沉淀出的习惯；
- 文化兴趣和审美判断；
- 地点、物件、关系等长期连续性。

Agent 记忆不作为 MemoryPanel 的主要用户管理对象，而由人物世界中的朋友圈、衣柜、文化角、家居、通讯录、足迹呈现。后台可以保留结构化摘要，用于维持跨页面和跨会话连续性。

### 3.3 关系记忆

归属：`relationship`

用户故事：**“我们之间发生过的事，不应该每次重新开始。”**

内容包括：

- 用户与 Agent 的共同约定；
- 用户对 Agent 的重要纠正；
- 长期合作方式；
- 对关系有持续影响的共同经历。

关系记忆属于 MemoryPanel 的主要用户可见范围，展示为「关于我们」。

### 3.4 当前状态

归属：`working-state`

用户故事：**“它知道我们现在正在做什么。”**

内容包括：

- 当前会话和当前任务；
- 当前主角；
- 当前工具调用和确认状态；
- 当前工作区、计划、加载、失败和重试状态。

它不是长期记忆，不进入 MemoryPanel。普通用户在 Chat / 工作区中看到，开发者在 Debug 中看到完整运行证据。

### 3.5 配置与策略

归属：`system-policy`

包括记忆开关、保留策略、敏感项规则、模型和权限设置。它们属于 Settings，不属于记忆内容。

## 4. 生活模块与记忆关系（How）

| 模块 | 用户看到的内容 | 记忆关系 | 是否直接进入 MemoryPanel |
|---|---|---|---|
| Chat | 聊天、关系发生、任务和记忆引用 | 产生用户 / 关系记忆，调用长期记忆 | 只展示被引用或需要纠正的内容 |
| 朋友圈 | Agent 最近发生的生活事件 | Agent episodic event；重要模式可沉淀为 Agent 记忆 | 否，除非被提升为长期关系信息 |
| 衣柜 | 当前穿着、审美和穿衣习惯 | 当前状态 + Agent 稳定偏好 | 否 |
| 文化角 | 书、笔记、音乐、电影、摄影 | 文化资产 / 文化记录；稳定审美可沉淀为 Agent 记忆 | 否 |
| 家居 | 当前空间、桌面和生活物件 | 当前空间状态；稳定生活习惯可沉淀为 Agent 记忆 | 否 |
| 通讯录 | 联系人、关系摘要和互动 | 关系对象 + Agent 的关系记忆 | 否；共同关系约定可进入“关于我们” |
| 足迹 | 去过的地方、旅行和地点记忆 | Agent episodic event；稳定地点偏好可沉淀 | 否 |
| 设置 | 记忆策略、管理和保留控制 | system policy，不是记忆内容 | 否 |
| Debug | 提取、召回、注入、工具调用和任务轨迹 | 运行证据与诊断记录 | 否 |

### 4.1 生活事件如何成为 Agent 记忆

不是每条生活内容都自动变成长期记忆，必须经过“提升”判断：

```text
一次事件
  ↓ 重复出现 / 形成稳定偏好 / 对未来行为有帮助
长期 Agent 记忆
```

示例：

```text
朋友圈：今天下午泡了一杯乌龙茶
→ 不是长期记忆

多次生活事件：下午泡茶后更容易进入工作状态
→ 可以沉淀为 Agent 习惯
```

### 4.2 运行记录统一进入 Debug

以下内容不进入长期记忆，也不进入朋友圈：

- “刚刚调用了 file_write”；
- “用户拒绝了某次工具请求”；
- “任务重试了两次”；
- “向量召回命中 3 条”；
- “模型生成了某条生活动态”。

这些内容是 Debug 的运行证据。普通产品只呈现对用户有意义的结果，不展示内部动作日志。

## 5. Playground 候选方案（How）

本轮只修改 Playground 候选，不改正式生产 UI、Prompt、Runtime、IPC、数据模型和持久化。

### 5.1 记忆 Playground

MemorySurface 改为以“归属”而不是“技术分类”为主导航：

```text
关于你 / 关于我们
```

候选展示：

- 默认展示多条用户记忆，验证列表密度、换行、来源和关系影响；
- 切换「关于我们」展示共同约定和关系历史；
- 空态、敏感项、纠正记忆保留；
- “当前正在做什么”不作为记忆样张，改由 Debug / Chat 状态验收。

现有 MemoryPanel 的六个内部分类在 Playground 中不再作为顶部一级导航；可保留为卡片辅助标签或内部测试数据。

### 5.2 证据层

每条可见长期记忆使用用户语言说明：

```text
来自：明确对话 / 反复反馈 / 共同约定 / 生活事件沉淀
影响：之后会如何理解用户或保持关系连续性
```

不显示：

```text
向量、Prompt、召回分数、模型提取、内部任务 ID
```

### 5.3 伙伴生活的呈现

Agent 记忆不复制成“关于伙伴”记忆 Tab。人物世界继续承载伙伴的生活表达；未来若需要查看某条 Agent 长期状态，可从具体生活模块进入局部来源，而不是进入统一后台列表。

## 6. 技术边界

- 新增的归属信息优先使用 Playground 显式 fixture metadata，不立即扩展生产 `MemoryEntry` 数据模型。
- 生产 `MemoryCategory` 暂不删除或重命名，避免迁移和 IPC 契约漂移；用户展示收敛先在 Playground 验证。
- Playground 通过 `previewMemories` 和新的 preview metadata 传递夹具；编辑、删除只操作 Renderer 内存。
- Settings 仍只在显式 `preview` 下定位记忆分区；不触发真实设置读取或保存。
- Debug 仍是实际运行状态、工具动作和记忆策略的唯一诊断入口。

## 7. 影响范围评估

| 范围 | 处理 |
|---|---|
| Playground 记忆样张 | 修改，增加多条用户 / 关系记忆和归属切换 |
| MemoryPanel | 仅增加 Playground 预览元数据和归属呈现能力 |
| 人物世界正式入口 | 不修改 |
| 生产 MemoryEntry / IPC / store | 不修改 |
| Debug 运行记录 | 不新增生产能力；本轮只确认边界 |
| E2E | 增加多条记忆密度、归属切换、内部词隔离与旅程断言 |
| 文档 | 更新施工合同、memory 模块卡、质量门禁、progress、changelog |

## 8. 实施步骤与验收

1. 盘点并冻结“用户 / Agent / 关系 / 当前状态 / 配置”边界；合同先行。
2. 增加 12～16 条隔离记忆夹具，至少覆盖用户记忆与关系记忆，不把运行动作伪装成记忆。
3. 将 Playground 记忆导航改为「关于你 / 关于我们」，验证多条记录下的布局密度和筛选体验。
4. 保留纠正记忆、敏感项和空态，确认它们仍在正确归属下工作。
5. 更新 E2E：归属切换、数量、来源证据、无内部术语、编辑隔离、Debug 边界文案。
6. 执行自审、Unit、类型、build、E2E、资产和文档门禁。

## 9. 完成判定

- 用户不需要进入 MemoryPanel 才能认识 Agent；人物世界可独立表达伙伴生活。
- MemoryPanel 不再把 Agent 生活事件和当前任务混成长期记忆。
- Playground 至少能展示多条用户记忆和关系记忆，并在同一视觉骨架下保持可读。
- 用户可以理解每条关系记忆的来源与未来影响，并可在隔离夹具中纠正。
- “干了什么事情”只在 Debug / Chat / 工作区上下文出现，不进入长期记忆清单。
- 正式生产 UI、数据模型、Prompt、Runtime、IPC 和持久化行为未被改变。
