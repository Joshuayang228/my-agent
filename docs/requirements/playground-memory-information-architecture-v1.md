## 1. 需求背景（Why）

上一轮 Playground 以“关于你 / 关于我们”分开归属，并用两列记忆卡展示多条 fixture。该方案验证了边界，但无法解决长期使用时的两个问题：

1. “关于你”会同时容纳身份、协作和沟通信息，与“做事方式 / 相处方式”发生交叉；
2. 记忆持续累积后，大卡片会形成信息墙，来源与“之后会”又会抢占普通用户的阅读注意力。

用户需要一套能随着记忆增长仍保持可理解、可管理的结构：普通界面只呈现“它记住了什么”，来源只在 Debug 语境按需查看；系统对未来行为的解释不应作为记忆的常驻内容。

## 2. 产品目标（What）

### 2.1 顶层信息架构

Playground 记忆候选固定为四个用户语言 Tab：

```text
身份信息 / 协作习惯 / 沟通偏好 / 我们之间
```

- **身份信息**：稳定背景、角色、长期关注方向与兴趣；
- **协作习惯**：工作流、决策方式、验收与交付偏好；
- **沟通偏好**：语气、信息密度、提醒边界与体验偏好；
- **我们之间**：共同约定、重要纠正、长期合作规则与关系连续性。

不设置“全部”兜底 Tab，避免用户重新面对无边界的信息墙。

### 2.2 唯一归类规则

每条记忆只拥有一个展示主类，按以下顺序归类：

1. 共同确认、共同形成或具有关系连续性 → **我们之间**；
2. 规定如何推进工作、决策或交付 → **协作习惯**；
3. 规定如何表达、提醒或避免打扰 → **沟通偏好**；
4. 其余稳定背景、身份、兴趣或处境 → **身份信息**。

生产 `MemoryCategory` 保持原样；这套归类仅通过 Playground fixture metadata 表达，不能伪造生产迁移已完成。

### 2.3 信息密度与 Debug

- 每个 Tab 内展示紧凑的单列记忆列表，而不是大卡片墙；内容优先，日期弱化，编辑 / 删除仍按原有样张场景呈现；
- 移除“之后会”展示，不再作为普通用户或 Debug 的记忆字段；
- 普通模式不显示“来自”；
- Playground 的隔离 Debug 模式开启后，记忆右上角才显示「查看来源」开关；开关打开后，每条当前 Tab 记忆才显示 fixture 来源；
- 来源只显示用户语言摘要，不展示 Prompt、向量、召回分数、模型任务 ID 或其他运行内部细节；
- 正式生产若未来要提供来源，必须另立合同并接入真实 provenance，不能复用 Playground 文案冒充事实。

## 3. 技术方案（How）

1. `SurfaceBaselinePanel` 维护四类 Playground-only metadata：Tab 标题、说明、fixture、来源；不触发 memory IPC。
2. `MemoryPanel` 增加仅预览使用的紧凑列表 / 来源可见 props；正式调用不传时保持现有 header、分类筛选、CRUD 和 footer。
3. Debug 状态仅在 `MemorySurface` 夹具内存在：先显式开启“Debug 样张”，再出现右上角 `role="switch"` 的「查看来源」开关。复用 Foundation `behavior.switch` 的可访问语义与视觉规则，不新造通用控件。
4. 记忆类别芯片不作为 Playground 普通浏览主信息；敏感项保留暖色保护语义。空态、敏感项、纠正记忆继续为隔离场景。
5. Renderer E2E 验证四 Tab、唯一内容归属、普通模式来源隐藏、Debug / 来源开关、编辑隔离与正式路径不受影响。

## 5. 实施步骤与验收

1. 建立四类 Tab 元数据和 fixture 归类，确认每条 fixture 只归一类。
2. 将 Playground 预览改为紧凑列表，移除“之后会”。
3. 增加隔离 Debug 状态与「查看来源」开关，默认隐藏来源。
4. 更新空态、敏感项、纠正记忆并验证切换不会写入真实数据。
5. 更新 E2E：四类 Tab、来源隐藏 / 显示、来源不含内部术语、编辑隔离、正式默认路径保留。
6. 按顺序执行自审、类型、Unit、UI E2E、build、资产和文档门禁；经用户确认后才讨论正式回流。

## 6. 风险与权衡

- 四类 Tab 不是生产数据模型，不能借此隐式修改存储分类；用 fixture metadata 隔离验证。
- 来源是 Debug 辅助信息而非用户解释层；若普通界面默认展示，会重新制造视觉负担。
- 单列列表提升长期浏览密度，但需保持最小行高和焦点态，避免变成难以扫读的表格。
- 将来源开关放在 Playground Debug 样张，不等于正式 Debug 已支持跨模块 provenance；该能力需真实数据链路后再单独施工。
