# 首个人物：路飞施工合同 v1

> 状态：进行中
> 日期：2026-10-27
> 范围：删除现有默认宇宙的人物资产，建立唯一首个人物 `luffy`，并验证人物制作流程可复用。

## 1. 为什么做

当前默认宇宙同时保留多个人物与历史样张，人物入口、默认角色和关系事实混在一起，不适合用来验证一套可复用的人物制作方法。本批用一个人物完成从资料边界、Role Pack、行为入口到注册与验收的完整闭环。

用户已明确选择路飞作为第一个人物，并授权删除现有全部人物资产。路飞属于已有作品中的角色；本批只采用用户选择和公开的高层人格印象，避免复制原作正文、台词或大段经历。具体年龄、时间线、关系、外观细节和使用范围继续由用户确认。

## 2. 完成目标

- 删除 `electron/main/companion/universes/default/roles/` 下现有全部人物目录。
- 新建唯一 `luffy` Role Pack，包含稳定身份、默认成长、表达、档案、世界、四类行为增量和三类场景样张。
- 更新默认宇宙名册、关系边界和正式入口的默认角色，确保运行时不再默认指向已删除人物。
- 将可复用的制作步骤沉淀到 `character-system-builder` skill；路飞专属决定只留在 Role Pack 与本合同。
- 通过资产检查、类型检查、单元测试、构建和文档门禁。

## 3. 人物边界

### 已确认

- 名称：路飞。
- 方向：自由、直率、重视伙伴、愿意把想法付诸行动的冒险伙伴。
- 作为 My Agent 的数字伙伴，不冒充现实肉身，不绕过平台规则和工具权限。

### 暂以高层草稿接通，待确认

- 具体作品时间线、年龄、家庭、职业和关系网络。
- 具体外观版本、服装细节和可用于生图的参考图。
- 对用户的称呼、玩笑边界、低落与冲突时的细节。
- 生活城市、住所、日常物件与持续事件。

### 明确不写入

- 原作长段落、原台词、章节复述和未经授权的完整作品资料。
- 平台安全、权限、工具调用、JSON 协议、记忆边界和模型回退规则。
- 运行时用户事实、会话历史和数据库中的旧人物数据。

## 4. 技术方案

- 生产来源仍为 `universes/default/roles/luffy/`，由现有 loader 读取。
- `manifest.json` 只描述名册身份；`protected.md`、`mutable.default.md`、`voice.md` 分别承载稳定边界、可变倾向和表达差异。
- `profile.json` 与 `world.default.json` 提供结构化档案和默认世界；当前对未确认字段明确写“待确认”，不由 loader 脑补。
- `behaviors/` 只提供 `moment-polish`、`day-script`、`catchup`、`reflection` 四类人物增量；公共协议与回退仍由生产编译器负责。
- `scenes/` 仅作为展示 / 互动 / 执行场景的可审阅样张，不新增运行时入口。
- 默认宇宙 `protagonistIds` 只保留 `luffy`，关系文件清空历史人物边，容量仍保留三槽以便以后扩展。

## 5. 删除记录

本批明确删除：`roles/ayu`、`roles/chen`、`roles/hang`、`roles/lin`、`roles/xia`、`roles/zhou` 六个生产人物资产目录，以及默认宇宙中指向这些角色的关系边。删除原因是用户要求从零开始塑造第一个人物；影响范围限定为默认宇宙的静态人物资产和默认角色入口，不清理用户数据库历史记录，不修改测试夹具。

## 6. 实施与验收

1. 读取 loader、类型和现有资产，完成删除清单（本步已完成）。
2. 写入 `luffy` Role Pack 与默认宇宙注册，运行资产结构检查。
3. 同步正式默认角色入口与当前人物模块文档。
4. 更新人物 skill 的通用制作循环与材料 / 决策 / 验收记录方式。
5. 运行 `npm run assets:check`、`npx tsc --noEmit`、`npm run test`、`npx vite build`、`npm run docs:validate`；失败时按根因修复。
6. 仅在静态与本地验证通过后提交并推送；人物语气与故事效果留待用户材料和后续人工审阅。

## 7. 风险与权衡

- 删除旧 Role Pack 会使依赖真实名册的本地数据无法再通过静态目录解析；用户数据库历史记录不主动迁移，避免把旧人物事实伪装成路飞事实。
- 现有测试中 `lin`、`zhou` 等是隔离夹具，不随生产资产删除；若测试断言依赖生产清单，再按真实契约修正，而不是恢复旧人物。
- 当前高层草稿可以验证 loader、编译和行为入口，不能证明已达到用户心中的原作还原度；下一轮必须用用户提供的资料与反例补齐。

## 8. 追加施工：核心伙伴与基础衣柜（2026-10-27）

用户本轮要求补齐路飞的朋友关系和基础初始衣物。生产关系表新增 `zoro`、`nami`、`usopp`、`sanji` 四个 NPC，均保持 `canBeProtagonist: false`，只通过浅层名册摘要参与关系读取，不把 NPC protected 全文注入路飞主对话。

路飞衣柜新增三件 starter：轻便红色背心、深蓝短裤、甲板凉鞋。它们来自 `electron/main/companion/life/assets.ts` 的角色专属 starter 定义，生成描述和分类，不写入当前穿着状态；用户删空后不自动复活。千里阳光号已写入正式 world.default 家居事实，运行态仍可由真实资产覆盖。

内置生图请求本轮连接失败，没有把失败结果写入项目或运行时资产。后续视觉草稿生成成功并经确认后，再接入图片引用与衣柜版本链路。
