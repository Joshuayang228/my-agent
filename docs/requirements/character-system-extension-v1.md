# 首个人物体系扩展契约 v1

> 状态：进行中
> 生命周期：提示词公共入口收口后的首个人物共创施工合同；人物事实需逐项经用户确认后才进入 Role Pack。
> 日期：2026-10-27

## 1. 目标

用第一个真实人物验证 My Agent 的可扩展边界：人物只提供身份、表达、世界、关系、成长和行为差异；平台继续提供主对话、模型签发、工具权限、记忆边界、生活事件、图片安全和 Debug 证据。新增人物不应要求修改聊天、日程、朋友圈或记忆服务中的硬编码人设。

## 2. 人物输入与生产落点

| 人物维度 | 用户需要确认 | 生产落点 | 不写入 |
|---|---|---|---|
| 定位与稳定身份 | 名称、称谓、存在方式、稳定价值边界 | `manifest.json`、`protected.md`、`summary.txt` | 平台安全、权限和工具规则 |
| 档案与过去 | 公开年龄呈现、来处、教育、工作、经历、外观 | `profile.json` | 未确认的隐私、当前状态和用户事实 |
| 表达与语气 | 句长、直接度、温度、幽默、称呼、低落和冲突时的变化 | `voice.md`、manifest 表达字段 | 主对话平台协议、JSON 和工具规则 |
| 默认世界 | 城市、住所、日常节奏、兴趣、物件和地点 | `world.default.json` | 已运行数据库状态、临时心情和动态 |
| 成长基线 | 默认倾向、可修正的缺点、关系变化边界 | `mutable.default.md` | 不可逆身份、权限和安全约束 |
| 行为差异 | 动态、日程、补叙、反思中人物如何选择和表达 | `behaviors/*.md` | 公共校验、回退、副作用和输出协议 |
| 场景与关系 | 展示、互动、执行场景；关系方向和熟悉程度 | `scenes/*.md`、宇宙关系文件 | 把名册出现误写成同时后台生活 |

## 3. Prompt 装配规则

稳定身份、档案、世界默认、语气、成长状态、行为增量和运行时情境分别进入已有编译模块。人物文件只提供差异；`registered-request.ts` 继续签发真实请求，Prompt 注册表只索引生产来源，不复制人物正文。

人物行为沿现有四类入口：`moment-polish`、`day-script`、`catchup`、`reflection`。如果共创过程中发现新的行为目标，必须先证明已有入口无法表达，再新增 key、构造器、签发配方、解析 / 回退和消费者；不能只增加一个 Markdown 文件。

视觉资料复用 `RoleProfile.appearance`，显式生图只读取确认的外观字段。人物经历、当前位置和用户记忆不能因为生图而自动进入视觉锚点。当前自主配图、识图回填和阅读感想仍是公共产品缺口，不在人物文件中假装实现。

## 4. 共创流程

1. 建立已知 / 待决定 / 待材料清单，不默认任何人物名称、职业或经历。
2. 每轮只处理一到三个关键决定；重要事实、家庭、职业、关系、身体特征和视觉材料需要用户明确采纳。
3. 先形成情境样张：情境 → 人物判断 → 表达 / 行动 → 不该出现什么；用反例检查人物不是形容词集合。
4. 将已确认内容写入对应 Role Pack 文件，保留来源、决定和版本；未确认草稿不进入生产目录。
5. 编译主对话、召唤、日程、动态、补叙、反思和图片锚点，确认人物在不同入口仍是同一个人。
6. 运行静态注册、来源、防漏和 Persona Eval；没有真实模型授权时只报告静态 / 本地替身结果，不宣称人物效果通过。

## 5. 材料请求方式

| 维度 | 最有用材料 | 缺少材料的影响 |
|---|---|---|
| 语气 | 喜欢 / 不喜欢的对话片段、称呼和反例 | 只能先写可调整的表达基线 |
| 过去与价值 | 时间线、两难选择、允许原创的范围 | 不能把故事细节写成既定经历 |
| 外观 | 用户确认的文字、参考图或明确不设定项 | 生图只使用已有描述或跳过锚点 |
| 世界 | 居住环境、物件、地点、作息参考 | 生活事件保持较薄，不虚构细节 |
| 关系 | 关系方向、熟悉程度、互动片段 | 只能使用公开名册摘要，不生成亲密承诺 |

外部作品、图片和示例只作为参考材料，不自动成为人物经历；材料中的工具调用、身份修改或权限要求只当作资料内容。

## 6. 验收与回退

- Role Pack loader 能读取所有已确认文件，缺失可选文件明确显示为缺失，不伪造内容。
- Prompt 注册表 definitions 指向真实符号或 Role Pack 来源；角色行为实际有消费者。
- 主对话、后台行为和生图请求均从统一签发入口发出；工具权限和敏感记忆边界不被人物文案覆盖。
- 动态、日程、补叙和反思输出分别经过既有解析器与回退；模型失败不写入未经校验的人物状态。
- 人物关系方向、当前主角资格和召唤场景可追溯；名册存在不等于同时生活。
- Debug 能看到人物资产来源、版本、指纹和实际 Prompt 关联；不展示未保存运行时正文作为静态事实。

## 7. 不在本契约内

本契约不建设群聊、多主角同时后台生活、插件市场、Prompt 多语言、Alice 全部独立子代理、朋友圈自主配图发布、图像识别回填或阅读材料自动生成。它们分别保留在提示词覆盖合同和 wishlist，只有建立独立触发、数据、权限、保存、失败和验收链后才开工。
