# Foundation Design Language v2 施工合同

> 状态：进行中（2026-08-29）
> 生命周期：Phase P0 Playground 视觉语言重构；未完成人工验收前，不回流正式产品。
> 统一称呼：施工合同

## 1. 需求背景（Why）

我们之前对 Playground 的处理主要是局部减噪：收窄来源、减少胶囊、调整边框、替换几组主题色。这些改动没有建立一套能指导取舍的“高级感”方法，因此页面仍容易退化成变量目录和组件展厅：每个卡片都在争夺注意力，颜色漂亮但关系不漂亮，蒙版 / 阴影 / 圆角缺少使用边界，开发者无法从样张判断什么应该进入正式产品。

本合同不再把“高级”理解为更多装饰，而把它定义为一种可以反复验证的系统质量：**看起来安静、关系准确、主次清楚、材质有理由、细节经得起近看，并且在不同主题和窗口宽度下仍然成立。**

本轮允许重新设计 Playground 设计语言页的结构和样张，不受当前页面组合和旧 UR 的局部布局限制；但仍必须遵守 Playground 与生产 UI 的边界。

## 2. 研究范围与结论（Research）

本轮重新对照以下方法与公开设计系统资料：

- Radix Colors：颜色不是色板装饰，而是按低对比 / 高对比、表面、组件状态和语义角色组织的尺度。
- Ant Design：用 Seed → Map → Alias 的方式把基础色推导成可复用的语义和组件 token，避免页面各自挑颜色。
- Primer：基础色、功能色和组件色分层；产品代码使用语义 token，不直接依赖原始色值。
- Carbon：动效同时记录 duration 与 easing，并区分 standard、entrance、exit；动效应帮助理解状态变化。
- Material 3：主题不止是主色，还要协调 surface、on-surface、outline、形状、排版和 elevation。
- Apple Human Interface Guidelines：材质、模糊、层级和留白要服务内容与空间关系；半透明不应成为默认皮肤。
- shadcn/ui / Radix Primitive：拥有可审阅的组件实现和明确的状态契约，比安装一整套外部皮肤更适合本项目。
- Alice 参考实现：重点学习页面骨架、内容密度、伙伴气质和“先看真实样张再看实现证据”的顺序，不复制其品牌资产或产品语义。

### 2.1 “高级感”的判断标准

高级感不是贵、复杂或“看起来像设计系统”。本项目用下面六个问题验收：

1. **第一眼是否只有一个视觉重心**：用户先知道当前在看什么，而不是先看到一排边框、状态标签或来源路径。
2. **层级是否由关系建立**：位置、尺寸、字重、留白和表面先建立主次，颜色和阴影只做确认。
3. **重复元素是否有节奏**：同类项共享对齐线、间距和形态；差异只出现在有语义的地方。
4. **近看是否仍然精确**：文字基线、控件高度、圆角角色、边界对比和 hover / focus 不互相打架。
5. **效果是否有理由**：每一道阴影、蒙版、渐变和动效都能解释它在表达什么；解释不了就不加。
6. **换主题和缩窗口是否仍成立**：高级感来自结构，不能依赖某一组暖色或某一个宽度。

### 2.2 设计语言的八条原则

1. **先骨架，后皮肤**：先固定画布、内容宽度、列关系和间距节奏，再讨论色彩和材质。
2. **一屏一重心**：每个一级页面最多一个主样张；其他信息退到辅助层。
3. **表面少而明确**：默认只使用画布、面板、卡片、内凹四种表面；不为每个状态再造一层卡片。
4. **颜色有职责**：中性色负责结构，品牌色负责行动和选中，语义色只负责反馈；同一屏不出现多套竞争强调色。
5. **边界优先于阴影**：浅色主题用细边界建立形状，深色主题用明度差建立形状；阴影只表达浮起关系。
6. **形态服从角色**：控件、卡片、面板、浮层各有圆角角色，不用一个巨大圆角包住所有内容。
7. **材质克制使用**：普通内容默认纯面或柔面；蒙版只用于浮层与背景分离，不用玻璃效果装饰普通卡片。
8. **动效解释变化**：只在状态、层级或空间关系变化时动；关闭动效后信息仍完整。

## 2.5 本轮交互与体验页收口（2026-08-29）

- 主题卡的当前状态改为不可点击的状态标签，只有其他主题显示可执行的“设为比较”操作，避免出现点击无结果的假按钮。
- 动效样张从不可感知的 transform 运动改为在轨道内进行可见的 left 位移，并把演示时长放大到可观察范围；生产 token 数值仍保持真实显示。
- Foundation 的标签样张补齐真实 tab 状态、键盘语义和内容切换，所有标签都能在隔离样张内点击验证。
- 产品体验页统一使用带内画布的体验舞台，Chat、人物世界、记忆、设置和工作区共享外层材质与边界节奏；基础引用改为紧凑胶囊，并保持来源固定宽度省略 / hover。
- 以上调整只影响 Playground；正式组件仍由真实组件渲染，体验夹具不触发 IPC、会话写入或设置保存。

## 3. 具体视觉规范（What）

### 3.1 颜色怎么设计

**目标**：让颜色表达结构与行为，而不是让页面看起来“有颜色”。

- 每套主题先定义 `app / panel / card / inset / text / muted / accent / border` 八个结构角色，再派生 success / warning / danger 三个反馈角色。
- 主题必须有明确轴线：冷 / 暖、浅 / 深、自然 / 人工、静 / 活至少在两个维度上形成差异；禁止只把棕色换成另一种棕色。
- 主色面积遵守克制原则：大面积由中性色承担，强调色主要出现在主要操作、选中、焦点和必要的状态提示。
- 文字对比优先保证阅读：主文本、次文本、弱文本分别承担不同阅读频率；弱文本不能承担关键说明。
- 交互状态不新增随机颜色：默认、hover、pressed、focus、disabled 用表面、边界、字重和透明度组合表达。
- 生产 CSS 继续只消费语义变量；候选主题只在局部 fixture 中注入 CSS custom properties。

### 3.2 样式怎么设计

**目标**：把 Playground 从目录变成“可判断的产品样张”。

- 页面统一采用一个内容主列，主样张占据最多视觉面积；实现来源、采用状态和 key 只做渐进披露。
- 页头只保留标题、短说明和必要的来源证据；不再添加“故事 / 能力 / 目录 / 隔离实验”等解释层。
- 内容区以稳定的 4 / 8 间距节奏组织；同一组内部紧凑，不同组之间留出明显呼吸。
- 卡片内部先放真实内容预览，再放 token 或实现证据；开发者需要的是“具体长什么样”，不是卡片标题堆叠。
- 字体层级控制在标题、正文、说明、代码四级；中英文辅助名只在确有学习价值时出现。
- 来源路径固定宽度、超长省略、hover 查看；来源不允许撑开布局或制造新的信息行。
- 交互控件必须展示默认态和一个边缘态；静态装饰不能伪装成可点击。

### 3.3 圆角怎么设计

**目标**：圆角表达组件角色和交互边界，而不是统一“可爱化”。

- `sm` 用于控件内的局部元素；`md` 用于普通卡片；`lg` 用于组合面板；`xl` 只用于浮层或大型入口；`full` 只用于状态 / 筛选 / 胶囊。
- 同一容器内不混用三个以上圆角等级；小控件不能比承载它的卡片更圆。
- 圆角越大，内部留白和边界对比越要充足；否则会出现气泡化和廉价感。
- 自定义滑杆只改变隔离样张，不改变全局 token，不改变正式页面。

### 3.4 阴影、材质与蒙版怎么设计

**目标**：让用户理解哪些是表面，哪些是浮起层，哪些是背景遮罩。

- **纯面**是默认：适合画布、面板和普通卡片，依靠底色和细边界建立层级。
- **柔面**是轻量增强：允许极弱的渐变或内高光，适合需要从背景中分离但不应漂浮的内容。
- **浮起**只用于弹层、菜单、对话框和被拖起的面板；阴影要有统一的低 / 中 / 高三档，不为每个组件单独发明。
- **蒙版**只用于打开浮层时压低背景、或把浮层从复杂背景中分离；不用于普通卡片，不用于制造“玻璃拟态”氛围。
- `backdrop-filter` 不是视觉目标，只是蒙版可选实现；浏览器不支持时必须退化为不透明表面。
- 不使用大面积彩色光晕、霓虹边框、强渐变和持续漂浮动画作为高级感来源。

- [ ] 为 `prefers-reduced-motion` 和不支持 backdrop-filter 的环境保留静态退化。

### 3.5 动效与密度怎么设计

- fast 用于 hover / focus / 按钮反馈，normal 用于展开 / 切换，slow 只用于大范围空间变化。
- 动效必须有开关；关闭时停止持续动画，不影响状态表达。
- 不使用 bounce、stretch、无限循环装饰和突然停止的曲线。
- 页面初始不同时播放多个竞争动画；样张最多一个持续运动的焦点。
- 内容密度通过间距、列宽、字重和对齐控制，不通过缩小所有字体解决。

## 4. 技术方案（How）

### 4.1 页面与状态

- `DesignSystemPanel.tsx` 是本轮 Playground 视觉实验的唯一入口，内部通过轻量横向筛选切换颜色、主题、形态与动效。
- 主题候选由本文件内的隔离 fixture 提供，不写入 `src/shared/design-asset-registry.ts`，不改 `document.documentElement`，不触发设置保存。
- 样张统一使用 `var(--study-*)` 局部变量；生产页面仍使用全局语义 token。
- `PlaygroundLayout.tsx` 和 `StoryBlock.tsx` 提供共享页头与卡片层级，其他 Playground 面板只复用，不再自行发明第二套视觉壳。

### 4.2 允许修改的文件

- `src/components/playground/DesignSystemPanel.tsx`
- `src/components/playground/PlaygroundLayout.tsx`
- `src/components/playground/StoryBlock.tsx`
- `src/components/playground/PlaygroundShell.tsx`
- `src/index.css`
- 对应 Renderer E2E 与文档文件

### 4.3 明确不碰

- 正式 Chat、人物世界、记忆、设置的产品布局和默认行为。
- `src/shared/design-asset-registry.ts` 的生产主题事实。
- 用户设置、会话、LLM、IPC、真实工具和记忆数据。
- 外部 UI 框架和整套主题依赖。

## 7. 风险与权衡

- **高级感变成装饰竞赛**：用六个判断标准和“解释不了就不加”的规则阻断。
- **主题候选过多造成选择疲劳**：固定四个方向，每个使用同一套产品样张。
- **蒙版 / 玻璃效果在浅色主题中变脏**：默认纯面；蒙版只在专用样张展示并提供静态退化。
- **重做导致旧测试失效**：优先保留稳定 test id 和入口语义；测试变化必须同步 Quality。
- **研究结论与实际代码漂移**：每个 TODO 必须对应代码、测试或文档证据；合同完工时冻结为快照。
