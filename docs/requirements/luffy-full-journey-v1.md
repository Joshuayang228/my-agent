# 路飞全功能人物验收施工合同 v1

> 状态：进行中
> 日期：2026-10-27
> 关联合同：[首个人物：路飞施工合同 v1](./character-luffy-v1.md)

## 1. 为什么做

路飞已经完成首版 Role Pack、核心伙伴浅层关系和基础衣柜，但这些资产还没有成为全产品的验收人物。当前人物能力容易出现“聊天里像路飞、生活世界是空的、图片没有稳定锚点、Debug 看不到真实来源”的断裂。本合同把路飞作为一条完整用户旅程的贯穿人物，逐项验证现有功能是否真正消费同一套身份、关系、世界、生活资产和提示词来源。

## 2. 资料边界与来源

本轮资料优先使用用户明确选择、项目现有 Role Pack 和官方公开资料索引。官方资料只用于确认高层事实，不复制原作台词、章节正文或长段剧情：

- 官方人物页：<https://one-piece.com/character/luffy/index.html>
- 官方千里阳光号人物页：<https://one-piece.com/character/Thousand_Sunny/index.html>
- 官方弗兰奇人物页（千里阳光号建造背景）：<https://one-piece.com/character/franky/index.html>
- 官方艾尼艾斯大厅篇（千里阳光号登场背景）：<https://one-piece.com/story/enies_lobby/index.html>

已确认的高层事实：草帽是路飞的稳定象征物；千里阳光号是当前默认住所；索隆、娜美、乌索普、山治是首批核心伙伴。年龄、悬赏、能力细节、完整时间线、家族和具体称呼不自动写入运行态，除非用户采纳对应资料。

## 3. 本轮目标

- 让路飞的身份、草帽、千里阳光号、核心伙伴、衣柜、家居和足迹有一致的生产来源。
- 为主对话、召唤、日程、追赶、朋友圈、评论回复、主动问候、生图、记忆提炼、反思和 Debug 建立人物专属输入与验收场景。
- 把每个功能标为“已接入 / 只有通用规则 / 缺人物输入 / 缺产品闭环”，不把存在一个 Prompt 误判为功能完成。
- 让人物制作技能沉淀可复用方法，路飞专属事实留在 Role Pack、生活资产和本合同。

## 4. 当前审计发现

1. 关系表已能生成浅层名册，但 NPC 只有最小 Role Pack，尚未覆盖完整关系方向、共同经历、关系成长和冲突修复。
2. 世界默认、运行态生活资产和衣柜 starter 是三条链，草帽 / 千里阳光号此前没有明确归属；本轮已补入 world.default.json，仍需验证播种、Debug 和图片引用。
3. 人物视觉锚点已能进入显式生图；本批已把基础衣物视觉参考接入 Role Pack，并让绑定穿搭时的真实衣物槽位进入图片配方，衣柜版本竞态与失败清理已有路飞正例。朋友圈配图和真实外部模型效果仍待同一人物验收。
4. 后台行为已有通用 Prompt；本轮已补齐路飞日程、追赶、反思、评论回复、主动问候和画像提炼的输入 / 回退回归，压缩与长期成长仍需更长会话和真实用户材料验收。
5. Playground / Debug 的多数样张仍沿用历史人物夹具，无法证明路飞真实数据从生产来源进入页面；需要新增路飞隔离样张和正式只读验收。
6. 作品事实、用户事实、运行事件和 AI 草稿目前仍需要在人物共创材料流中持续标源，不能用一次性 Role Pack 文案替代事实证据。

## 5. 功能矩阵

| 功能 | 路飞本轮验收 | 必须使用的来源 | 主要缺口 |
|---|---|---|---|
| 主对话 | 语气、价值排序、用户称呼、拒绝边界 | protected / voice / profile / mutable | 反例与材料仍待补 |
| 召唤与名册 | 核心伙伴摘要、不泄露 NPC 全文 | relations + NPC summary | 关系成长与冲突 |
| 日程 / 日剧本 | 千里阳光号生活场景、行动节奏 | world + day-script | 真实事件与用户约束 |
| 追赶 / 反思 | 路飞式鼓励、承认冲动、可撤回行动 | catchup / reflection | 长期成长证据与真实材料 |
| 朋友圈 | 航海生活事件、伙伴同框 | moments + relations | 事件素材与配图闭环 |
| 评论 / 主角回复 | 直接、短、尊重用户评论 | moment-comment / moment-reply + role | 反例与失败样例 |
| 主动问候 | 有新动态才问候，不把呈现当已读 | proactive-greeting + world | 路飞专属触发样例 |
| 生图 | 草帽、基础衣物、千里阳光号环境锚点 | appearance + wardrobe + image recipe | 朋友圈配图与真实外部模型效果 |
| 记忆提炼 | 只提取用户事实，不把路飞设定写入用户记忆 | profile-extraction | 人物事实 / 用户事实反例 |
| 压缩与召回 | 用户约定进入关系最小集；草帽和千里阳光号只在相关人物上下文注入 | compact + relationship min set | 更长真实会话与召回验收 |
| Debug | 能看见来源、版本、关系、生活资产、真实调用 | model-context-assets + evidence | 路飞正式数据页 |
| 用户画像 / 记忆 | 路飞不污染用户画像；反馈按人物分桶 | memory-store / profile | 纠错与跨角色负例 |

## 6. 技术方案

- 稳定身份和行为仍由 `electron/main/companion/universes/default/roles/luffy/` 提供。
- 千里阳光号与草帽属于 `world.default.json` 的出厂世界与物件；衣物继续由角色 starter 工厂播种，运行态穿着、图片和用户修改独立保存。
- 伙伴关系继续由 `relations.json` 提供，NPC 只通过名册摘要和明确关系边进入主角上下文；共同经历必须来自同角色事件关联。
- 所有生图继续走独立图片配方和统一模型配置，外观锚点只注入 `appearance` 与已确认衣物字段；未成功生成的结果不写入资产。
- 每新增人物专属行为 Prompt，都登记真实来源、依赖和回退测试；通用平台规则不复制到 Role Pack。
- Debug 只读读取生产目录、运行态和真实调用证据；Playground 只用路飞隔离夹具展示边缘态，不写生产数据。

## 7. 实施顺序

1. **世界锚点**：补草帽物件、千里阳光号住所、房间 / 物件关系，验证 starter 与 Debug 来源。
2. **人物与关系**：补核心伙伴的 profile / voice / relation direction，补关系成长和共同经历反例。
3. **衣柜与生图**：为基础衣物生成项目资产，绑定图片引用和 outfit version，验证失败 / 重启 / 换装竞态。
4. **对话与后台行为**：逐入口补路飞正反例和材料来源，验证 Prompt 注册、编译、回退与记忆边界。
5. **生活旅程**：用路飞跑日程、事件、朋友圈、评论、主动问候、家居、足迹、文化角和通讯录。
6. **用户资料与记忆**：验证用户事实、路飞事实、运行事件和 AI 草稿的隔离，覆盖提炼、纠错、召回和压缩。
7. **Debug / Playground**：新增路飞真实目录页与隔离样张，按逐页、逐入口截图验收，再回流缺失能力。
8. **收口**：资产审计、类型检查、全量测试、构建、文档门禁和人物制作技能复盘。

## 8. 不做与风险

- 不复制原作长文本、台词、章节剧情或未经用户选择的完整人物资料。
- 不把千里阳光号、草帽、伙伴关系自动扩展成现实地址、现实联系人或用户记忆。
- 不用生图结果反向证明人物事实；图片生成失败时保留文字资产和可重试状态。
- 不把历史人物测试夹具当成路飞生产数据；不清理用户数据库旧历史。
