# 朋友圈自主配图与动态回写施工合同 v1

> 状态：已完成施工快照（冻结）
> 生命周期：已完成施工快照（冻结）
> 日期：2026-11-05
> 收口说明：自动配图事件级幂等、每日预算、受控媒体存储、世界态一致性与正式设置入口已验收，当前能力见 [伙伴模块卡](../modules/companion.md)；真实外部生图供应商效果按凭据条件单独验证。

## 1. 需求背景

生活 ticker 已能按人物关系、情绪、每日上限、冷却和勿扰时段选择一条朋友圈动态。现有生图工具只能由用户明确触发，并把图片保存到当前项目后绑定动态。自动生活路径没有媒体生成、归属、费用门闸或失败记录，不能直接复用用户会话的项目路径。

## 2. 功能目标

- 自动配图只对自动选中的一条动态生效，服从每日发帖和图片预算上限。
- 图片生成请求从统一生图配置和已登记 Prompt 配方发出，使用人物已确认的外观锚点与动态事实。
- 媒体保存到应用管理的受控目录，绑定 `roleId`、`eventId` 和 `momentId`，不依赖当前项目或聊天会话。
- 生成、落盘、绑定、跳过、失败和重启恢复均可查询，失败不伪造图片引用，重复 ticker 不重复扣费或覆盖已有媒体。
- 设置提供 `never`、`existing`、`generated` 三种策略。默认 `never`，`generated` 必须经过明确的费用确认或用户预授权。

## 3. 技术方案

### 数据流

`生活事件 → 自动发帖策略 → 图片预算 / 权限门闸 → 注册图片请求 → 生图服务 → 应用媒体存储 → moment image link → Debug 证据`

新增持久化记录至少包含 `id`、`role_id`、`event_id`、`moment_id`、`status`、`reason`、`image_id`、`attempted_at`、`completed_at` 和脱敏错误分类。图片字节与元数据分离保存，读取必须复用现有图片 codec 与路径安全校验。

### 关键约束

- ticker 不得把项目工作区路径、会话路径或用户 API Key 传入媒体存储。
- 同一事件最多一条自动生成记录，同一成功图片不得重复生成。
- 自动配图开始前按人物 / 事件读取最近持久化尝试；已有 started / skipped / failed 不自动重试，已有 stored 直接复用图片 ID，避免 ticker 重复触发或重启造成重复费用。
- `generated` 策略在没有有效生图配置、预算或授权时记录可解释跳过原因。
- 远程调用超时、取消和格式错误均写失败记录，不自动重试。
- 只有图片落盘、摘要校验和动态归属校验全部成功后才写入动态关联。

## 4. 影响范围

- 主进程：生活事件投影、图片请求、应用媒体存储、数据库迁移、Debug 查询。
- 共享类型与 IPC：图片策略、证据记录、读取结果。
- 设置与 Playground：策略和预算候选，正式设置页需单独回流验收。
- 测试：预算门闸、幂等、失败恢复、角色隔离、媒体读取和重启恢复。
- 文档：companion 模块卡、agent-runtime、quality、progress、changelog、wishlist。

## 5. 实施步骤

1. 建立自动配图记录表和受控应用媒体存储，补数据库迁移与恢复清理测试。
2. 将图片请求包装成自动生活专用服务，接入统一图片 Prompt、配置和取消边界。
3. 在朋友圈投影中接入 `never / existing / generated` 策略、预算、幂等和失败记录。
4. 补 Debug 只读证据、按人物 / 日期分页和图片来源详情。
5. 补 Playground 设置候选、单元 / Electron 回归和文档门禁。
6. 通过完整测试、类型检查、生产构建、资产检查和文档检查后提交推送。

## 6. 风险与权衡

- 自动生图会产生真实费用，默认关闭，且每人每天独立限额。
- 生成服务失败时保留文字动态，不能因为图片失败回滚已确认的生活事实。
- 应用媒体不与项目图片混存，增加备份范围和迁移工作，但能避免 ticker 依赖当前工作区。
- 正式设置回流必须经过 Playground 视觉与交互确认，候选阶段不改变正式设置默认入口。
