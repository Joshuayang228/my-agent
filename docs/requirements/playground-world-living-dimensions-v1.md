# Playground 人物世界生活维度 v1 施工合同

> 状态：进行中
> 生命周期：Phase P0 Playground 候选施工；只用于确认人物世界的信息架构、内容边界与视觉组合，正式 UI 仍需逐项验收后再回流。
> 统一称呼：施工合同

## 1. 需求背景（Why）

人物世界已经有朋友圈、资产和关系卡的基础样张，但“物什”把穿着、读物、生活物品混在同一个入口里，无法表达一个真正热爱生活的人所拥有的不同生活维度。继续往现有页面里堆内容，会把人物世界做成资产数据库，而不是有时间、空间、兴趣、关系和移动轨迹的伙伴生活面。

本合同先建立一张完整但克制的生活维度地图，再选择适合成为并列入口的维度。目标不是展示所有能力，而是让用户能够从几个清楚的窗口感受到“这是一个在生活的人”。

本轮只修改 Playground 隔离候选，不读取或写入真实生活事件、资产、联系人、地点、媒体或生产 IPC。

## 2. 功能目标（What）

人物世界 Playground 采用六个并列入口，顺序固定为：

```text
朋友圈 / 衣柜 / 文化角 / 家居 / 通讯录 / 足迹
```

六个入口分别回答一个问题：

| 入口 | 生活维度 | 用户问题 | 第一版内容
|---|---|---|---|
| 朋友圈 | 时间与日常 | 她最近发生了什么？ | 动态、图片、地点、心情、互动
| 衣柜 | 外在形象 | 她今天如何呈现自己？ | 当前穿着、最近常穿、配饰
| 文化角 | 文化、兴趣与表达 | 她喜欢什么、被什么打动？ | 书、读书笔记、音乐、电影、摄影
| 家居 | 居所与生活空间 | 她在哪里生活？ | 当前空间、桌面、设备、生活物件
| 通讯录 | 人际关系 | 她和谁有联系？ | 联系人、关系摘要、最近互动
| 足迹 | 移动与地点 | 她去过哪里、想去哪里？ | 旅行、常去地点、散步路线、地点记忆

## 3. 内容边界（What not）

### 3.1 作为一级入口的六个维度

- 六个入口必须在同一行导航中并列；窄宽时允许横向滚动，但不得出现“物什”再进入衣柜 / 文化角 / 家居的二级导航。
- `足迹`固定放在最右侧，表达生活的移动与地点连续性。
- `文化角`不是书籍管理器；它是角色的文化生活空间，至少能同时表达阅读、音乐、电影、摄影和笔记。
- `家居`不是家电控制面板；设备只是空间生活的一种内容类型。
- `通讯录`不是角色切换入口；角色架继续归入设置。

### 3.2 暂不做一级入口的维度

以下内容有价值，但第一版先作为六个入口中的内容类型或交叉关联，不新增导航：

- 餐桌 / 饮食：先进入朋友圈或家居；内容密度稳定后再评估是否成为独立生活面。
- 音乐、电影、摄影：统一进入文化角，不拆成多个 Tab。
- 日记：日常日记进入朋友圈，旅行日记进入足迹。
- 创作 / 工作：由 Chat 与工作区承载，作品可以在朋友圈或文化角出现。
- 运动 / 睡眠 / 健康：通过动态和生活节奏自然表达，详细健康数据不进入人物世界默认导航。
- 记忆：仍由设置管理，可从人物世界上下文进入，不新增人物世界 Tab。

## 4. 技术方案（How）

### 4.1 通讯录候选细化（2026-10-08，字段方案已确认，候选待人工验收）

头像补充（2026-10-08）：用户授权真实生图，阿遥与许叔分别生成同风格方形头像，列表示例和详情复用本地资产；保留无头像和加载失败场景，不回写 Role Pack，不以阿遥头像冒充其他人物。

背景：现有 Playground 通讯录复用 CastPanel 的名册 / 召唤语义，包含开聊、忙闲、召唤会话与技术说明，不符合已确认的伙伴人际关系展示定位。Alice 朋友卡的人物介绍与生活关联可参考，但模型 / 语音状态和聊天能力不迁移。

目标：两列人物卡网格，窄容器一列；头像、姓名、关系标签与一句身份介绍。整卡进入详情，不再有独立查看摘要、开聊、忙闲、在线或增改删入口。关系标签始终指人物与伙伴的关系，而非用户关系。第一版无分类和搜索，不使用大幅背景图片。

详情复用 Foundation 返回、共享内容边距与限宽契约，依次自然展示人物介绍、如何认识与平时相处、共同经历；不层层嵌套卡片、不显示亲密度分数。缺失可选信息不造空栏目。关联朋友圈或旅行记录存在时才提供真实隔离跳转；无目标时仅显示经历，不提供死链接。返回恢复原卡焦点与列表位置。

候选字段契约（只定义隔离类型，不修改生产共享类型或存储）：

| 对象 | 字段 | 值与含义 |
|---|---|---|
| 人物 | id | 必填稳定人物标识，不以姓名或数组位置作关联 key |
| 人物 | name | 必填展示姓名；长名字换行，不挤占头像 |
| 人物 | avatarSrc | 可选图片来源；缺失或加载失败使用姓名占位，尺寸保持稳定 |
| 人物 | introduction | 必填一句身份介绍，不混入关系历史 |
| 人物 | city | 可选城市，仅详情有值时展示 |
| 关系 | ownerRoleId / personId | 必填伙伴 ID 与人物 ID；限定归属，切换伙伴不得串数据 |
| 关系 | relationLabel | 必填自然语言关系，例如大学同学、邻居；不强制全部为朋友 |
| 关系 | firstMetStory | 可选如何认识的叙述；不得自动伪造首次认识日期 |
| 关系 | interactionSummary | 可选平时相处方式，与具体共同经历分开 |
| 经历 | id / personId / ownerRoleId | 必填稳定经历 ID 与双方引用 |
| 经历 | date | 可选 YYYY-MM-DD；未知不填，不使用展示时刻补造日期 |
| 经历 | title / story | 必填名称与简短故事，多条经历独立保存 |
| 经历 | references | 可选关联数组，kind 为 moment 或 trip，targetId 为目标稳定 ID |

数据流：人物和关系 fixture 按当前 persona 派生；点击卡片只变内存选中 ID；详情使用同一人物、关系与经历源。关联 resolver 按 kind / targetId 查现有隔离记录，正文不复制另一份；关联页返回回到人物详情。未来正式资料由 Agent 维护，此轮不接 Agent 写入、IPC、召唤或数据库。

允许修改：Playground-only 通讯录候选、SurfaceBaselinePanel 的 cast preview 注入、隔离 fixture / resolver、对应 Unit / E2E 与文档。CastPanel 正式默认、App、Role Pack、生产关系和会话逻辑不改。只替换候选注入，不删除底层召唤能力。

实施顺序：字段方案确认 → 候选与 fixture → 列表 / 详情 / 关联返回测试 → 深浅主题及窄宽浏览器验收 → 人工验收。至少覆盖默认、长姓名、多条经历、缺失及失败头像、无经历、空通讯录；验证整卡点击、键盘进入与返回、关联缺失无入口、伙伴切换隔离、无生产 IPC。圆角引用已确认 token，卡片 16px、控件 10px；列表与详情边界偏差不超过 2px，hover / focus 不改尺寸。

风险与权衡：人物经历不等同召唤聊天历史；不能用 session 数据冒充生活经历。候选字段不代表生产 Schema 已支持，生产迁移、Agent 工具及正式回流另行确认；边界样张完整可用，不增加假保存 / 假聊天按钮。

本轮候选交付边界：头像默认使用姓名占位，另覆盖头像加载失败；实现人物清单、长姓名、无共同经历、头像失败、空通讯录五种场景。旅行引用使用足迹同一记录，含关联详情返回与基础图片预览；没有可解析朋友圈目标时不显示入口。本轮不建立朋友圈跨面引用路由，该生产能力在 wishlist 登记，不能将可选 references 字段视作所有关联已实现。

- `WorldHub` 保持正式页面既有默认入口不变；增加可选的 Playground Tab 定义能力，候选通过显式 `tabs` 传入六个生活入口。
- Playground 使用稳定的内部 key 区分 `moments`、`wardrobe`、`culture`、`home`、`cast`、`footprints`；用户可见标签由候选定义提供，正式 `assets` / `cast` 入口不被隐式改名。
- `WorldSurface` 继续复用正式 `WorldHub`、人物头图、朋友圈、衣柜和详情面板；衣柜、文化角、家居、通讯录、足迹仍使用隔离 fixture，通过 `previewPanels` 注入。衣柜 / 文化 / 家居 / 足迹可在内存中预览增改删，不调用生产数据或 IPC；通讯录保持静态夹具。
- 文化角至少展示读书、音乐、电影、摄影四类内容，并展示一条读书笔记；它们是同一生活空间内的内容卡，不新增页面层级。
- 家居先用“当前空间 + 空间物件”表达，不实现设备控制；足迹先用“最近去过 + 常去 / 想去”表达，不接入地图服务。
- 当前主角继续由既有 `PlaygroundPersona` 驱动，六个入口都必须显示同一 `data-persona-id`。

## 5. 影响范围评估

- 修改：Playground 人物世界组合、WorldHub 的显式候选 Tab 扩展、Renderer E2E、人物世界施工合同、质量 / 进度 / 变更记录。
- 不改：正式人物世界默认入口与生产文案、生产资产模型、生活事件 / 联系人 / 地点数据、Prompt、Runtime、IPC、地图、媒体服务和角色切换逻辑。
- 风险：六个入口在窄宽下可能挤压内容；通过单行横向滚动、固定顺序和统一 Tab 尺寸控制。
- 风险：文化角范围过宽后可能变成收藏夹；通过要求每项内容都体现“角色喜欢 / 感受 / 笔记 / 作品”的语义，而不是只列资源。
- 风险：家居与旧“物什”概念混淆；通过从“资产列表”改为“当前空间”叙事，并禁止用户可见的物什入口。

## 6. 实施步骤

1. 更新人物世界信息架构和生活维度合同，冻结六入口、顺序与内容边界。
2. 为 `WorldHub` 增加仅在显式传入时生效的候选 Tab 定义，不改变正式默认 Tab。
3. 在 Playground 建立衣柜、文化角、家居、通讯录、足迹五个隔离样张，朋友圈沿用已有样张。
4. 补齐六入口切换、窄宽滚动、当前主角连续性和内容存在性的 Renderer E2E。
5. 用浏览器检查浅色 / 深色、标准宽度 / 窄宽、标签溢出和页面内容层级。
6. 完成自审、测试、构建、文档校验并提交；等待用户验收后再决定是否回流正式人物世界。

## 7. 风险与权衡

- 入口数量从三个增加到六个，但它们是不同生活维度，不是同一资产列表的拆分；如果某个维度未来内容不足，可以在候选验收后再合并，不能提前用抽象“其他”兜底。
- “文化角”选择清楚而可扩展的命名，不追求晦涩的高级感；内容高级感由选择、叙事和视觉密度体现。
- “足迹”优先表达地点和移动，不承诺完整旅行产品；旅行日记是其中一种内容形态。
- Playground 的新入口不代表正式产品立即增加六个入口；正式回流必须另有用户确认和生产边界验收。

## 8. 验收标准

- 人物世界 Playground 只显示 `朋友圈 / 衣柜 / 文化角 / 家居 / 通讯录 / 足迹` 六个并列 Tab，`足迹` 在最后。
- 点击每个 Tab 都能切换到对应内容，当前 Tab 有明确选中态，窄宽下导航不换行、不遮挡内容。
- 衣柜显示当前穿着与最近常穿；文化角同时出现书、读书笔记、音乐、电影和摄影；家居显示当前空间与空间物件；通讯录显示联系人与关系；足迹显示最近去过、常去或想去的地点。
- 六个入口都与当前 Playground 主角一致；切换主角后，头图、朋友圈和六个生活面使用同一 fixture 主角。
- 不显示“物什”“名册”“角色架”用户入口；角色架仍在设置样张。
- 不读取真实生产生活数据、不写入设置或会话、不触发生产 IPC；Playground 编辑只改内存预览。正式 WorldHub 不传 `tabs` 时行为不变。
- 通过类型检查、单元测试、Renderer E2E、构建、资产检查和文档校验。
