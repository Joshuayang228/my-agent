# 伙伴世界（Companion）

## Agent Host 能力接入（2026-11-13）

Companion 首个 Agent Host Domain Definition 已注册，提供 `companion.runtime.read` 查询能力和 `companion.runtime-context` Context Provider。两者只读取核心 Runtime Read Model，沿用角色作用域和现有权限边界，不复制人物状态或 Prompt 正文。

朋友圈发布新增 `companion.moment.publish` Workflow Capability，复用既有 `companion_post_moment` Tool 的执行实现。固定 Workflow 与自然语言 Tool 共享角色校验、命令网关、领域事件和 Moment 投影链路。

日记生成新增 `companion.diary.generate` Workflow Capability，复用 `triggerInnerThought` 的生活引擎实现，AI 触发与生活时钟触发共享日记持久化和 Outbox 链路。

生活推进新增 `companion.life.tick` Workflow Capability，复用 `tickActiveRole` 的日剧本、到期事件、投影和 Outbox 链路。

LifeTicker 通过 `runCompanionLifeTickWorkflow` 进入 Agent Host Application，固定调度入口与受控 Workflow 共用同一生活引擎。Agent Host 只保存能力定义和授权结果，人物运行态仍由 Companion Core 与既有存储、事件和投影链路维护。

内容完整性现在由共享 `ContentProvenance` 和领域事件校验器收口。朋友圈、关系、生活资产和通知事件沿既有来源 ID / `sourceEventId` 追踪，日记记录额外保存来源类型、来源 ID 和调用链；模型生成的内容先经过 Application / Domain 校验，再进入事实、事件和 Outbox。

Memory 反思和 Prompt 动态上下文也沿同一来源协议记录。深夜反思写入反馈记忆时保留来源，主会话只接收带作用域和长度证据的动态切片。

Companion Core 迁移期间，Runtime 组装器和 Debug 世界快照通过 `core/read-models/legacy-companion-read-model.ts` 读取旧日程、事件、关系和情绪表。该适配层只读，新的事实写入仍必须经过 Core Command / Domain Event。

Core Runtime State 现在保存暂停时间、追赶摘要和最近推进时间，pause、resume、catch-up、tick 会同步核心快照，旧角色状态表只承担迁移期镜像。通讯录、卡司可用性、生活信号、穿搭、旅行推进、日程时间线、反思、事件切片、生活时钟和世界体征刷新的旧表读取统一经过 Core 只读迁移适配层。
用户赠礼的礼物事实、主会话消息、领域事件、体征更新和通知 Outbox 通过同一 Unit of Work 提交，提交前不做窗口或会话外部投递。
专属信物沿用同一事务边界，信物记录、主会话消息、`keepsake_gifted` 事件和通知 Outbox 一起提交。
文化心愿完成、朋友圈投影和自动回复也沿本地事务提交，模型调用结束后才落 Core 事件与旧读模型投影。

主会话角色组装由 Conversation Application Service 作为入口，Companion 负责提供人物资料和生活 Read Model，Runtime 不再直接拥有角色组装业务流程。

## 核心一致性与恢复（2026-11-13）

- `withCompanionUnitOfWork` 将人物世界领域事件和 Outbox 写入置于同一数据库事务，建表初始化不参与业务回滚。
- Outbox 记录带处理租约、重试时间和最大尝试次数。进程在 processing 阶段崩溃后，过期租约可恢复，失败投递按退避时间再次领取。
- 主会话通知通过 `main-session-message` Outbox 进入 session store，窗口通知与会话落盘分离，二者都能在重启后按幂等键恢复。

## 核心引擎重构进行中

人物世界正在迁移到模块化单体内的领域核心。当前核心层统一保存人物运行态、领域事件、执行账本、幂等投影回执和通知 Outbox，文化体验、赠礼、信物、主动搭话、脆弱心境、日记、深夜反思、换装、旅行、重排、评论回复、宿主关怀和朋友圈轻提示完成链路已接入核心记录。命令网关统一 active role 校验、执行账本和 retryable 失败状态，窗口通知统一经过 Outbox 投递适配器。人物入口、Debug 世界态和自动配图读取核心运行态。朋友圈、关系和 Prompt 读模型按施工合同逐步迁移，旧生活表在迁移期间作为镜像读模型使用。
主要人物世界 IPC 写入入口也通过命令网关进入核心执行账本，避免 Renderer handler 直接调用生活服务形成旁路。
窗口暂不可用时通知保持在 Outbox 中，恢复后由适配器继续投递。
Chat Tool 与 IPC 共用人物世界命令网关，生活写入的角色校验、执行状态和失败语义保持一致。
日程事件在生成朋友圈投影前先登记核心领域事件，朋友圈、关系、情绪和关联导航读取同一条投影链。
运行态状态变化采用版本校验，过期生活推进不会覆盖最新人物状态。
生活时钟动作通过命令网关进入执行账本，再调用各领域服务。
生活服务产生的主会话消息通过独立 Outbox 适配器写入，窗口通知和会话留痕分开重试。
命令网关保存幂等键与第一次结果，重复提交直接复用结果。
人物入口、Prompt、Debug 和自动配图共用运行态 Read Model。
人物世界核心引擎施工合同已完成，后续扩展沿命令、事件、投影、执行账本和 Outbox 边界接入。

- **全场景高频触点贯通（Omni-Touchpoint Avatar Integration）**：彻底取代冰冷的 `<Bot />` 机器人图标与单调单字方块：
  1. **Chat 欢迎屏（`ChatWelcome`）**：居中展示主角大尺寸专属头像与人设光晕；
  2. **Chat 消息气泡（`ChatMessageFrame`）**：各角色（含主对话伙伴与被召唤 NPC）回复气泡带专属圆形头像；
  3. **人物世界顶部（`WorldProfileHeader`）**：大尺寸圆角专属头像半浮于封面横幅边缘；
  4. **主侧栏顶栏（`PrimarySidebar`）**：专属头像彰显当前同行伙伴身份；
  5. **朋友圈动态（`MomentsPanel`）**：动态卡片展示作者头像。
- **优雅降级（Graceful Fallbacks）**：统一封装 `CompanionAvatar` 组件，支持图片未配置或加载失败时优雅平滑回退至角色首字艺术字与人设主题色渐变。

- **Chat 会话区弱场景氛围壁纸（Ambient Chat Scene Wallpaper）**：`CompanionSceneBackdrop` 支持弱场景壁纸层（透光度 ~9%、轻度微模糊与暗角），在不干扰气泡对比度与文本可读性的前提下营造伙伴所在场景的陪伴空间感。
- **IPC 同步与单测覆盖**：`companion:get-role-visuals` 通道四处同步；新增 `companion-role-visuals.test.ts` 5 项单测，门禁全绿。

## 已落地能力：用户人物体系草稿与世界观切换

运行时 `character-system-builder` Skill 通过 `companion_character_draft` 把世界观、身份、关系、外观、行为和材料保存为用户数据目录中的分区草稿。模型只能整理和提交审阅，不能直接发布 Role Pack、覆盖内置资产或切换世界观。

审阅草稿可由受控工具发布为用户 Universe / Role Pack；发布生成带世界观前缀的内部人物 ID，避免现有按 `roleId` 分桶的生活数据碰撞。切换世界观只允许在已加载且默认主角有效的套装上执行，流式会话期间拒绝，设置写入失败时尽力恢复旧组合。

草稿标识由世界观前缀、时间片和随机后缀组成，快速连续创建不会覆盖待审阅草稿，发布仍只接受当前草稿文件中的 `review` 状态。

手动与 ticker 生活服务在模型生成后再次确认 activeRole，信物、脆弱安慰、宿主关怀、日内重排和旅行推进不会在切角竞态中写入旧人物。

赠礼、信物和脆弱安慰把主会话留痕作为用户可见完成条件，留痕失败时回滚核心记录，不广播完成事件。

主动搭话把主会话消息与主动行为历史视为同一结果，历史写入失败时回滚消息并停止广播。

角色架正式入口读取 `companion:list-universes`，显示当前世界观并通过 `companion:switch-universe` 切换；切换成功后同步更新宿主活跃主角、刷新主角列表并保持跨世界生活资产隔离，重载后保留当前世界观与主角。

## 已落地能力：会话到生活的因果反哺（Chat to Life Resonance）

- **对话生活心愿识别**：
  - 主对话结束时异步启动 `settleChatResonance`，由受控小模型分析近轮对话；
  - 识别用户推荐的具体文化作品（书/影/音）、美食、地点或行动向往；无明确意向或寻常闲聊时返回 `hasResonance: false`，绝不凭空编造；

- **文化资产自动播种与状态联通**：
  - 若为文化心愿（书/影/音），自动调用 `createAsset` 在文化角创建 `planned`（待读/待看）或 `queued`（待听）资产，并附带引用用户对话出处的摘要与动机；
  - 用户推荐的书籍直接进入书架想读列表，打通“聊天 → 角色生活物什”真实路径。
- **次日剧本吸收（因果闭环）**：
  - `collectDayScriptLifeContext` 在生成次日剧本时，自动拉取活跃生活心愿作为日程提示词输入，并标记为 `absorbed_in_script`；
  - 角色次日的一日活动与朋友圈自然提及昨天聊到的美食或约定，形成真实可感的活人感。
- **实时反馈与跳转**：
  - 心愿产生时向桌面窗口广播 `companion:life-resonance-created`，桌面端弹出温馨通知横幅，点击一键跳转至人物世界文化角。
- **文化心愿体验闭环与主动反馈（Culture Progression & Review Loop）**：
  - 角色将用户推荐的书籍/影视/音乐记录为文化资产并被日剧本吸收（`absorbed_in_script`）后，在体验时间达到（或由后台动态生活时钟唤醒）时，自动触发 `completeCultureResonance`；
  - 受控模型以第一人称人设口吻生成专属评语（`reviewText`），文化资产状态推进为 `finished`，评语沉淀为第一人称感悟笔记追加进 `readingNotes`；
  - 同步生成下次对话的话头引子（`chatOpener`）与可选朋友圈文案（`shouldPostMoment`）；
  - 主对话装配管线在 `formatConversationImpulseForPrompt` 中注入 `【重要回访心愿反馈】`，角色在后续对话或打招呼中会主动向用户倾诉体验感悟；
  - 心愿反馈在主会话中带出后立即自动标记为已投递（`markResonanceFeedbackDelivered`），避免重复纠缠；
  - 心愿完成时广播 `companion:resonance-completed`，桌面端弹出通知横幅，点击支持一键直达文化角。

## 已落地能力：突发生活意图与主动找聊（Spontaneous Impulse & Outreach）

- **即兴生活表达冲动**：
  - 角色不再仅仅是被动等待提问或发朋友圈后的单一问候；当处于特定生活状态、生命体征高涨（`socialNeed >= 70` 或 `energy >= 80`）或正在进行特别的活动时，生命调度器（`ticker.ts`）自动触发突发找聊意向评估；
  - 具有严格的防打扰与频次约束：每日上限 2 次、触发间隔至少 3 小时，且严格遵守夜间勿扰时段（安静时间段不打扰）；
- **第一人称生活化即兴搭话**：
  - 由受控模型配方 `compileSpontaneousImpulseRequest`（或规则保底）生成生动的第一人称即兴话头，话题自然围绕当前活动（`activity`）、身体状况（`vitals`）、探险所见（`adventure`）或日常随想（`casual`）；
  - 路飞会热情直接地喊“喂！我刚在甲板上发现了一只超大的海鸥，你要不要来看看！”或者碎碎念山治的烤肉与大海上的风浪；
- **主会话直接落盘与桌面即时呈现**：
  - 角色主动发起的消息直接写入该角色的专属主会话（`sessionKind: 'main'`），并广播 `companion:spontaneous-impulse`；
  - 桌面端 Toast 提醒点击可一键切换至该会话并聚焦输入框；若用户当前正处于该聊天页面，新消息无感平滑推入，让用户真切体验到“伙伴忽然发来了一条消息”的真人伙伴陪伴感。

人物草稿支持戏剧驱动力、决策规则、连续性、首次冷启与证据分区；审阅发布时会保留首次冷启场景和连续性材料。Role Pack 的 Debug 目录登记这些来源，首次冷启使用人物自己的自我介绍与名言，普通功能 Prompt 仍按平台约束 → 功能协议 → 人物适配 → 运行时资料 → 输出协议装配。通用方法与边界见已冻结的 [施工合同](../requirements/character-design-method-v1.md) 和 [人物设计参考](../../.agents/skills/character-system-builder/references/character-design-method.md)。

## 已落地能力：材料依据、图片观察与阅读感想闭环

人物阅读笔记在 `bookshelf` 资产的 `readingNotes` 中支持结构化 `grounding`（`observation` 可直接核对的材料观察与 `inference` 人物推断分离）以及 `confirmation`（记录 `user` 或 `companion` 确认主体与确认时间）。旧笔记保持兼容可读；新的人物自主阅读笔记必须提供 `source` 和 `grounding.observation`，不得仅凭书名或无来源闲聊写回。

## 已落地能力：主对话生活事实切片与生命体征动态演化

- 主对话装配（`orchestrator.ts#loadRoleAssembleInput`）除原有书架摘要外，新增当前生活事实薄切片（`lifeAssetsSlice`）：将当前穿搭（衣柜 `wear-state` 槽位引用的衣物名）、文化角进行中的阅读 / 观影 / 听歌进度与笔记（`readingStatus: 'reading'`, `watchStatus: 'watching'`, `listeningStatus: in ['listening', 'revisiting']`），以及当前进行中的旅行（`status: 'active'` 的最新站点）压缩为有界切片并注入主对话，解决角色不知道自己穿什么、在看什么或正在哪段航线的问题。
- 角色生命体征（`world.mood`, `world.energy`, `world.socialNeed`）接入动态演化引擎（`world-vitals.ts`）：
  - 5 分钟心跳推进并发布生活事件时，以 `world.updatedAt` 为水位线，按事件活动内容结算生命体征（午睡小憩恢复精力、大宴会大烤肉涨心情并消耗精力、普通日常微耗精力并累加社交渴望），并向基准值自然回归，避免数值崩塌或长期死值。
  - 用户与主角主会话完成一轮交互后，触发 `settleVitalsAfterChat` 释放社交渴望（`socialNeed` 回落至健康区间并微升心情），且不改变结算水位线，实现「有人陪聊后得到满足」的自然呼吸感。

## 已落地能力：跨天因果日剧本、交谈冲动与主动问候入会话

- **跨天因果日剧本生成**：
  - 日剧本规划（`script-generator.ts#generateDayScriptViaLlm`）在提示词（`buildLlmPrompt`）中接入 `lifeContext`（近期生活与现实连续性线索）：包含前一日已发布生活事件、当前未完结的旅行路线与最新站点、当前生命体征（心情/精力/社交欲望），以及近 24 小时内用户在主会话中留下的聊天话题与诉求（`listRecentUserMessagesForRole`），使每日生活安排具备承上启下的因果连续性。
- **主对话交谈冲动（Conversation Impulse）**：
  - 主对话装配管线（`orchestrator.ts#loadRoleAssembleInput`）基于近期生活事件、旅行见闻、未决话题与高社交渴望，有界萃取一条角色自身的「交谈冲动」（`conversationImpulse`，插槽 31）；
  - 当本轮对话属于用户随口问候或闲聊开场时，提示词引导角色在回应之余自然引出自身当下的生活见闻或未决思考，打破「用户不问角色就不提生活」的纯被动问答模式；而在用户有明确严肃任务或指令时保持克制，不强行转移话题。
- **主动问候落地真实会话**：
  - 后台投递主动问候（`proactive-greeting.ts#dispatchProactiveGreeting`）时，通过 `ensureMainSessionForRole(roleId)` 确保角色专属的主会话存在，并将问候文案以 `assistant` 角色持久化写入该会话（`saveMessage`），并在投递事件载荷中携带 `sessionId`；
  - 前端主动问候 Toast 气泡绑定点击事件，用户点击 Toast 即可一键平滑跳转至对应角色的主会话并自动载入上下文，使主动问候真正成为一次可延续的对话起点，消除「气泡看完即消失」的割裂感。

## 边界

**做**：Role Pack / 单活跃门控 / MUTABLE 版本与自动反思 / LifeEngine（暂停·剧本·tick）/ Catch-up≤7×24h / Moments·Assets 截面 / 名册浅注入 / 冷启动在场 / 召唤子会话与忙闲婉拒。  
反思服务会读取当前人物已保存的书架阅读笔记薄信号，只作为反思输入，不自动创建书籍、补写阅读事实或直接改写成长状态；用户或人物可通过 `companion_add_reading_note` 在明确书架条目和来源范围后保存笔记，记录者与页码 / 章节进入 `readingNotes`，人物记录还必须提供 `grounding.observation`，可选 `grounding.inference` 将材料观察和人物推断分开保存，存储层最多读取六条记录。`companion_observe_material` 只读取当前会话已有图片，返回观察 / 推断 / 不确定性候选，不自动写入人物世界；旧笔记缺少 grounding 时只兼容读取，不补造观察内容。关系变化另有 `companion_relationship_events` 历史表，情绪事件按来源事件幂等记录，重复生活投影不会重复污染状态摘要；当前快照仍由 `companion_relationship_state` 提供。
每条新笔记还保存 `confirmation.by / at`，表示用户或人物作为本次写回确认主体；图片观察尝试另存 started / succeeded / failed 的有界记录，Debug 只展示状态和原因，不展示图片二进制。
自主配图施工已接入自动路径：仅当策略值为 `generated` 时，生活 ticker 才调用统一生图配置，生成结果写入应用管理媒体表并绑定人物 / 事件 / 动态；每日默认最多生成一张，预算按本地日历日计算并在跨日后重置，缺配置、超出预算、生成失败或绑定失败均保留文字动态并记录终态尝试原因。相同人物 / 事件已有 `started`、`skipped`、`failed` 或 `stored` 尝试时不再重复调用，成功图片直接复用 ID；默认策略仍为关闭。
**不做**：会话中途换角；非活跃后台养成；多宇宙并行；自动生成朋友圈内容（视觉资产生图已接入，但不自动替动态生成内容）。自动发布的执行账本现在将未选中事件记为 `not-selected`，不借用获选事件的限流原因。人物行为 Skill 的发现、激活和权限治理属于能力扩展边界，不由 Role Pack 静默切换。

## 已落地能力：语义 Prompt 编译与人物行为扩展

主对话由 `electron/main/prompts/compiler.ts` 按平台规则、人物定义、人物成长、行为定义、情境上下文和输出契约编译。Moment 润色、日程剧本、生活补叙和人格反思通过同一行为编译入口共享人物基线，各自保留事实输入、解析校验、回退和副作用。Role Pack 可增加 `behaviors/<behavior>.md` 行为增量；增量只能影响指定行为的表达与选择，不能覆盖稳定身份、平台规则或输出校验。后续扩展团队成员时只需新增 Role Pack 资产和明确的行为入口，不复制完整主 Prompt。

扩展人物的写作流程可以封装为 Skill：先确定稳定身份 / 档案 / 默认世界，再分别写 voice 与已有四种 `behaviors/` 增量；当前世界状态和用户偏好由运行时注入。新增人物使用 loader 已支持的文件形状并通过 Role Pack 防漏检查；新增行为则同步 typed key、纯正文构造器、注册 `definitions`、真实调用、解析 / 回退及行为 Eval。Skill 只组织写作与验证步骤，不获得覆盖稳定身份、绕过权限或直接改生产资产的特殊权限。

## 短 Why

只有 Prompt 换皮是工具；有暂停的生活世界与派生截面，才是「同一个人」的伙伴感。

### Prompt / 召回组装管线（聊天一轮）

主路径：`AgentRuntime` → `loadRoleAssembleInput` → `buildSystemPrompt` → Loop。

```text
用户发消息
  → assertSessionRole(session.role_id)          # 禁止偷换人设
  → loadRoleAssembleInput(roleId)               # Pack + MUTABLE + catchup + worldSlice + recentMoments + roster
  → detectReplyStance(lastUser)                 # M27-G1 问/做/安慰/推回 hint
  → resolveToneControl(stance, mode, text)      # M27-G3 紧/软/中性 + aside 策略
  → resolveRelationshipStageForRole(...)        # M28-G1/G2 阶段 + 交心/干活 lean
  → memory.buildUserProfile()                   # 结构化画像
  → safeVectorSearch(lastUser)                  # 向量语义召回 → 情境上下文 memories
  → yield memory_citations                      # M29-G1 UI 芯片
  → buildSystemPrompt({
        L1: PROTECTED + MUTABLE
        L2: 工具/aside/stance/tone/relationship/skill 摘要
        L3: 画像 + memories + catchup + worldSlice + recentMoments + roster
        L4: 动态（时间等）
     })
  → Agent Loop（流式）
  → 后台：profile-extract / smart-title / vector-index-user
  → scheduleReflectionAfterChat（召唤会话跳过）
```

召唤差异：装载对方完整 Pack；**不**改 `activeRoleId`；**不** tick / catchup 对方生活；Prompt 可带忙闲情境（`describeCastPresence`）。

| 衣柜、文化角、家居、足迹 | 统一使用按 `role_id` 隔离的 `companion_assets`；图片只保存结构化引用，字节走受控媒体存储；事件多对多关联使用 `companion_event_links` | 图片归属、读取、删除、备份恢复和事件关联按角色隔离；视觉资产由真实生图明确触发 |
| 通讯录 | 角色架与 roster 提供关系摘要；召唤会话不切换主角，也不推进被召唤角色生活 | 关系是 Role Pack 静态资料、独立运行时关系状态，还是二者叠加；哪些变化需要用户确认 |
| 运行时世界 | LifeEngine、planned / published 事件、Catch-up 和 presence 已存在，Prompt 只消费组装后的切片 | 静态属性与动态状态的分层、更新来源、版本化和冲突处理 |

暂定的数据流表达为：

```text
Role Pack / 用户确认的稳定资料
  ↓
稳定身份与静态世界
  ↓
planned event / 用户行动 / Agent 工具 / tick
  ↓
published event（事件事实）
  ├─ 更新短期世界状态
  ├─ 投影 Moments
  ├─ 关联生活资产、地点和关系线索
  ├─ 形成 Catch-up
  └─ 供 Chat Prompt 组装消费
```

静态不等于永不变化，而是变化频率低、需要更高确认门槛；动态不等于临时文案，而是必须有来源、时间和生命周期的运行时事实。Prompt 是消费层，不反向充当人物世界数据库真相。
