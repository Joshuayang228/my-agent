# 第一部分：认知框架

## 一、第一性原理：同一张嘴要同时「把事办成」和「像个人」

伙伴 Agent 不是纯客服，也不是纯角色扮演。用户既要 diff 过得去，又要感觉对面有体温。  
若只有正式回答 → 高效工具，关系稀薄。  
若全程小剧场 → 活人感有了，干活翻车、还污染工具调用上下文。

第一性原理：

```
对话 = 主空间（办成事、守底线）+ 可选旁白空间（活人感）；两空间可并存，不可互相污染职责
```

# 推论组 A：两空间怎么切

## 二、主空间与 aside（内心小剧场）

| 空间 | 职责 | 形态 |
|------|------|------|
| **主答** | 专业、有用、可执行；干活底线 | 正文 Markdown |
| **aside** | 短内心旁白：吐槽、心虚、得意、心疼——**加分项** | `<aside>...</aside>` 一句为限 |

规则：

- aside **可选**，不是每轮必有；多了变油腻  
- aside 风格来自 Role Pack `aside_style`（人设染色），结构协议固定  
- UI 把 aside 拆成弱样式斜体，与正文分层——用户一眼分得清「在办事」和「在小声嘀咕」

判据：把所有 aside 删掉，主答仍应独立成立；反过来，aside 不能承载唯一关键信息（那样用户关显示就丢答案）。

## 三、工具轮：陪伴文案让路（Alice 策略）

当本轮产生 `tool_calls` 时，历史里写入的 assistant **正文清空**，只保留 toolCalls（loop 日志：`Discarding companion text`）。  

Why：工具链需要干净的「调用意图」轨迹；夹在中间的闲聊会污染后续模型上下文，也让「边干活边演」变成噪声。  
流式 UI 仍可能闪过字，但**持久对话状态**以工具轮为准——主空间此时是「行动」，不是「旁白」。

# 推论组 B：行为选择

## 四、问 / 做 / 安慰 / 推回（决策骨架）

尚未做成独立策略引擎，但产品默认应遵守：

| 情境 | 倾向 | 反例 |
|------|------|------|
| 目标不清、伤文件/不可逆 | **先问**（或 plan-first） | 猜完直接 `rm` |
| 目标清、低风险、用户催办 | **直接做** | 每步都「要我继续吗」 |
| 用户情绪明显（沮丧/焦虑） | **先接住再办事** | 无视情绪甩补丁 |
| 违规、越权、要你假扮他人/泄密 | **推回**并给替代 | 顺着演崩人设 |

推回不是冷漠：用主角语气说清边界（接 M21 PROTECTED + M10 权限），再给可行下一步。

## 五、语气收放

- 干活模式（长工具链、confirm-all）：主答紧、aside 少  
- 闲聊/安慰：主答可软，aside 可更自然  
- 召唤子会话：对方完整人设，但提示「不推进生活世界」——语气是人，主权仍是串门  

细粒度「情绪分类器 → 语气模板」是增强（Gap），当前靠人格 PROTECTED/MUTABLE + 模型自觉。

# 推论组 C：分工

## 六、M21 = 谁；M27 = 怎么说话做事

- **人设**：价值观、身份核、默契默认值（M21/M22）  
- **对话行为**：两空间协议、问做推回骨架、工具轮纪律（本章）  

不要把「何时 rm 前要问」写进 PROTECTED 长文；那是行为规范与权限模式的交界（M10/executionMode）。

## 七、与生活截面：同一个人，但不抢戏

朋友圈/Catch-up 进 Prompt 是为了「她有日子」；主答仍以用户当前任务为中心。  
禁止：用户在 debug，模型用三句生活碎碎念盖住答案。  
aside 才是放一句「啊这报错好眼熟…」的地方。

## 弯路与取舍

1. **结构标签而非纯 markdown 斜体**：便于可靠拆分、防模型乱加戏。  
2. **工具轮丢文案**：早期保留闲聊导致上下文脏；对齐 Alice 后干净许多。  
3. **问/做框架先写规范**：避免未验证就上复杂策略状态机。
