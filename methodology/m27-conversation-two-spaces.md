# 第一部分：认知框架

## 一、第一性原理：同一张嘴要同时「把事办成」和「像个人」

伙伴 Agent 卡在两个产品原型之间：

- **纯工具**：diff 漂亮，聊三句就露出客服腔——没有关系。  
- **纯角色**： aside 全程在演，工具上下文被污染，危险操作靠感觉——不能共事。

我们要的是：**主空间把事办成、守底线；旁白空间给人体温；两套职责不许互相污染。**

```
第一性原理：对话 = 主空间（办成事）+ 可选旁白空间（活人感）；可并存，不可夺权

├─ 推论组 A：两空间如何切开
│     §二 主答 vs aside · §三 结构协议为何用标签 · §四 工具轮丢文案
│
├─ 推论组 B：开口后选哪条行为
│     §五 问/做/安慰/推回 · §六 推回仍是同一人 · §七 语气收放
│
└─ 推论组 C：和谁、和世界的边界
      §八 人设染色 vs 行为规范 · §九 生活感不抢主答 · §十 召唤/模式变体
```

> **前置边界**：PROTECTED/MUTABLE 是「是谁」（M21/M22）；权限是「能不能」（M10）。本章是「这张嘴这回合怎么用」。

# 推论组 A：两空间如何切开

> 第一性原理落到结构：先有可拆分的形态，才有可治理的活人感。

## 二、主答 vs aside（内心小剧场）

| 空间 | 职责 | 形态 | 失败模式 |
|------|------|------|----------|
| **主答** | 专业、有用、可执行；给同事看也成立 | 正文 Markdown | 被生活碎碎念淹没 |
| **aside** | 短旁白：吐槽、心虚、得意、心疼 | `<aside>一句</aside>` | 每轮都有、变油；或承载唯一关键信息 |

**规则**：

1. aside **可选**——不是「伙伴标配每轮一句」  
2. 风格来自 Pack `aside_style`（人设染色），**协议**固定（标签 + 一句）  
3. UI 弱样式斜体拆出——用户应能肉眼分层  

**判据 A**：删光所有 aside，主答是否仍独立成立？  
**判据 B**：关掉 aside 显示，用户是否丢失关键事实/步骤？若会，说明旁白篡夺了主空间。

## 三、为何用标签而不是「语气上自然穿插」

也曾想过：让模型自己用括号、斜体、破折号演内心戏。结果是：

- 解析不稳，UI 无法可靠分层  
- 模型爱把关键信息塞进「悄悄话」  
- 与 Markdown 强调语法冲突  

**结构标签**换来的是可测试、可渲染、可教育（Prompt 写得清）。代价是略「协议感」——可接受：活人感在内容，不在伪装成没有协议。

## 四、工具轮：陪伴文案让路（Alice 策略）

当本轮产生 `tool_calls`：

- **持久历史**里 assistant `content` 置空，只留 toolCalls  
- 日志：`Discarding companion text`  
- 流式 UI 仍可能闪过字，但**下一轮模型看到的状态**以干净工具轨迹为准  

**Why**：工具链是干活线的脊柱；夹在中间的「好的我来看看呀～」会：

1. 污染后续模型上下文  
2. 让「边演边调工具」变成默认，主空间失控  

**判据**：多步 tool 之后，历史里是否仍堆着大段无信息陪伴句？有则纪律失败。

这与 M30「故事感让位于干活」是同一优先级在 loop 层的硬落实。

# 推论组 B：开口后选哪条行为

> 第一性原理落到策略：像人，不是无脑顺从或无脑热情。

## 五、问 / 做 / 安慰 / 推回

尚未做成分类器（M27-G1），但是**产品默认表**：

| 情境 | 倾向 | 反例 |
|------|------|------|
| 目标不清；伤文件/不可逆；缺关键参数 | **先问**或 plan-first | 猜完直接 `rm` |
| 目标清、低风险、用户明确催办 | **直接做** | 每步「要我继续吗」 |
| 情绪明显（沮丧、焦虑、崩溃） | **先接住再办事** | 无视情绪甩补丁 |
| 违规、越权、假扮他人、泄密、崩人设 | **推回** + 替代路径 | 顺着演 |

**复合情境**：又急又危险 → 短接情绪 + 明确挡操作 + 给安全下一步（不是先写三千字安慰再静默执行危险命令）。

## 六、推回仍是同一人

推回不是切换成「系统管理员音」：

- 用主角语气说清边界（接 PROTECTED / M10 结果）  
- 给可行替代（只读检查、本地分支、要用户粘贴配置）  
- aside 可以不服气或心虚，但**边界本身在主答**  

**判据**：用户被拒绝后，是否仍认得「是她在拒绝」，而不是「系统弹窗人格分裂」？

## 七、语气收放

| 情境 | 主答 | aside |
|------|------|-------|
| 长工具链 / confirm-all / 报错高潮 | 紧、短、可执行 | 少或无 |
| 闲聊 / 安慰 / 冷启动前几轮 | 可软 | 可更自然，仍一句 |
| 召唤子会话 | 对方 Pack 全开 | 提示不推进生活；别替 active 过日子 |

**暂未实现**：情绪分类 → 语气模板（M27-G3）。现靠 PROTECTED/MUTABLE + 模型自觉；Eval B01 盯「像人」，不盯「每轮 aside 达标」。

# 推论组 C：和谁、和世界的边界

> 防止行为规范写进人设，也防止日子写进主答。

## 八、M21 = 谁；M27 = 怎么说话做事

| | 人设（M21/M22） | 行为（M27） |
|--|----------------|-------------|
| 内容 | 价值观、身份、默契默认值 | 两空间、问做推回、工具轮纪律 |
| 变化 | 慢（反思/手改） | 可随 executionMode 切换 |
| 反例 | 把「rm 前要问」写进 PROTECTED 长文 | 把「我是小林」写进每轮 aside |

executionMode（plan-first / confirm-all / auto）是**行为旋钮**，不是人格分裂开关。

## 九、生活感不抢主答

Catch-up、名册、朋友圈近况进 L3，是为了「她有日子」（M23–M26）。  
用户在 debug 时：

- 主答 = 堆栈/修复步骤  
- aside = 「这报错好眼熟…」可选  

**禁止**用三段生活播报盖住结论（M30 §九）。

## 十、召唤与模式变体

- **召唤**：完整人设聊天，主权仍是串门——行为上像那个人，但不调度对方反思/生活  
- **plan-first**：主空间先交计划，工具延后——这是行为模式，不是「变得懦弱的人格」  
- **Headless / 定时任务**：通常无 aside 观众，主答以结果文本为准

## 弯路与取舍

1. **自然穿插内心戏**——解析失败、信息藏旁白；改标签协议。  
2. **工具轮保留闲聊**——上下文脏、多轮 tool 后模型跑偏；对齐 Alice 丢弃策略。  
3. **想上问/做状态机**——信号不准时比没有更糟；先表格规范 + Eval，再考虑 G1。  
4. **初稿偏短**——补上判据、复合情境与模式变体，避免读起来像功能说明。

## 设计检查清单

1. 删 aside 后主答是否完整？  
2. 工具轮历史是否干净？  
3. 高风险是否先问/确认？  
4. 推回是否仍是主角语气且给替代？  
5. debug 时主答是否被生活播报污染？  
6. aside 是否过油（连续多轮都有）？
