# 第一部分：认知框架

## 一、第一性原理：资产是「过期后仍在的物身份」，事件是「会沉没的发生」

朋友圈一条会滚出视野；那天穿的灰帽衫若只存在动态文案里，下次再也对不上「同一件」。  
伙伴世界要让物**可指认**：同一 `assetId`，在动态、（将来）生图 prompt、对话提及里是同一个东西。

第一性原理：

```
资产 = 按角色积累的持久物身份；事件可引用它，事件沉了物还在
```

# 推论组 A：边界

## 二、三层对照

| 层 | 寿命 | 例子 |
|----|------|------|
| Event | 发生记录，可沉 | 「傍晚发了条动态」 |
| Moment | 事件的可见投影 | 朋友圈那一行字 |
| Asset | 持久物 | 「灰色连帽衫」这件衣服 |

判据：动态删了，灰帽衫还在衣柜；灰帽衫删了，旧动态可降级为无着装描述，但**不该**反过来用朋友圈文案当衣柜真相源。

## 三、按 roleId 隔离

每个主角自己的衣柜；切换 active = 换一整柜。  
禁止跨角色共用 asset 行「凑合穿」——身份稳定包含「这是谁的东西」。

# 推论组 B：如何进入世界

## 四、获得路径：种子与入库

最小闭环：

1. **Starter 种子**：角色空柜时 `ensureStarterWardrobe` 幂等写入固定 id 的几件基础款  
2. **显式 addAsset**：购买/剧情获得（可挂 `source_event_id`）  
3. （未来）获得类事件自动入库——增强项  

资产有 `acquired_at`；版本需求弱于 MUTABLE——物更多是增删而非全文演化。用户编辑资产名/payload 是产品增强（记 Gap）。

## 五、事件引用，不拷贝物描述

剧本物化 moment 槽时 `pickWardrobeAssetId` → 写入 event.payload.assetId。  
Moments 投影时 `getAsset` 取 name 拼进文案。  

**禁止**把「穿着灰色连帽衫」只写进 moment.text 却不建 asset——下次无法指认同一件。  
引用断裂时（资产已删）：投影降级，不伪造新资产。

# 推论组 C：可见与扩展

## 六、仅 active 柜门打开

IPC `get-assets` / UI `AssetsPanel` 只暴露当前活跃主角。  
非活跃柜存在 DB 里，但不在后台因 tick 乱增——除非 Catch-up/显式逻辑触达该 role（与生活暂停一致）。

## 七、类型可扩展；本阶段衣柜最小集

`kind` 字段预留：`wardrobe` / 未来 `bookshelf` 等。  
W4 只做衣柜可演示闭环；书架、收藏品不阻塞方法论。  
生图 prompt 拼装：资产 payload（色/风格）是预留接口，生图本身非本阶段（见 M24-G3）。

## 弯路与取舍

1. **先衣柜、后万物**：证明「引用 + 分桶 + 截面」三件套，再扩 kind。  
2. **Starter 固定 id**：空库可幂等重入，避免每次换角复制一堆重复衣服。  
3. **tech-spec 称截面**：相对「朋友圈文案」是派生；相对「物本身」资产表才是物真相——用词上「截面」指 UI 呈现，勿与「无真相」混淆。
