# 第一部分：认知框架

## 一、第一性原理：先站稳，再长肉；换人是换视角，不是把用户当陌生人

三件容易搅在一起的事：

1. **体验冷启动**——空会话「嗨，我是谁」，降低第一次开口的尴尬  
2. **成长冷启动**——相处未满窗口前不改 MUTABLE，避免第一天拧歪人设  
3. **换角**——换一个「我」继续过日子（Catch-up），**不是**教程重开、进度清零  

若把 3 当成 1+2 的重置，多主角架构就变成「三个失忆的人轮流上岗」。


# 推论组 A：分清两种「冷」与阶段

> 立刻有人 ≠ 立刻改默契。阶段感可以先叙事，硬闸必须可测。

## 二、欢迎在场 ≠ 成长门闸

| | 欢迎冷启动（体验） | 成长冷启动（M22） |
|--|-------------------|------------------|
| 触发 | 空会话 / 见面 UI | `companionGrowthStartedAt` 起算 |
| 产出 | title / subtitle / hint | 72h 内拒绝自动反思 |
| 目标 | 「有人在」（M31 L1） | 「别太早改默契」 |
| 失败 | 空白输入框、文案与 active 不符 | 装机当天 MUTABLE 被拧歪 |

两者**互补**：UI 立刻有人；人格成长故意慢半拍。  
**禁止**用「欢迎很热情」当借口绕过成长门闸。

## 三、阶段叙事：陌生 / 熟悉 / 默契

| 阶段 | 体感 | 行为倾向（规范） | 工程硬边界 |
|------|------|------------------|------------|
| **陌生** | 刚认识 | 少假定、克制追问、aside 少 | 反思通常未过 72h |
| **熟悉** | 有共同语境 | 可更自然；记忆召回变多 | 仍受 24h 冷却与消息密度约束 |
| **默契** | 行为默认值已个人化 | MUTABLE 可微调；aside 更贴 | 仍可回滚；仍不碰 PROTECTED |

**现状诚实**：没有 `relationshipStage` 枚举驱动 Prompt（M28-G1）。阶段差异大量靠 Pack 语气与模型自觉；**可测硬边界**只有成长门闸 + 会话绑角。  
这不是偷懒到零——而是「空转状态机比没有更糟」：阶段判错会导致过度亲热或过度疏离。

## 四、数值为何对齐 Alice（72h / 24h / 5msgs）

| 旋钮 | 值 | 意图 |
|------|-----|------|
| 冷启动 | 72h | 至少过一个「周末尺度」再谈固化默契 |
| 冷却 | 24h | 防止一天内反复微扰人设 |
| 信号 | 近 7 日 ≥5 条用户消息 | 没相处密度别假装有默契 |

**判据**：改数必须产品确认 + 单测锁定；不可因「想快点看反思效果」在生产默认里改成 5 分钟。  
`force` 是调试/用户主动逃生口，不是日常旁路。

# 推论组 B：如何靠近而不冒犯

> 靠近靠分享与密度，不靠审讯与抢改人设。

## 五、初次信息采集：问什么、何时问

- **优先**：用户主动分享 → `remember` / 画像提取  
- **避免**：开场连珠炮（爱好、星座、前任、薪资）  
- **高敏**（健康、财务、隐私路径、公司秘密）：不挖；进了库也要可删（M29）  

**判据**：第一会话结束，用户觉得「认识了一个人」，还是「填完一张表」？后者是冷启动失败。

与 M27：陌生期主答可软，但**不要**用热情掩饰问卷。

## 六、熟悉度代理指标与反思启动

已实现条件是**工程代理**，不是情感评分：

```text
反思允许 ≈ 时钟≥72h ∧ 冷却≥24h ∧ 近7日该角色用户消息≥5
```

| 够用 | 不够用 |
|------|--------|
| 挡住「聊两句就改人设」 | 不区分交心夜谈 vs 纯敲代码刷消息数（M28-G2） |
| 可单测、可解释 | 成长时钟已 per-role（M22-G1） |

召唤会话：不计入「跟对方长默契」的反思调度——串门不是同居。

# 推论组 C：换角、会话、三线

> 多主角下，冷启动最容易在「换人」时被误用。

## 七、换角 ≠ 冷启动会话

| 动作 | 含义 | 不是 |
|------|------|------|
| 完整切换 | pause 旧 → active=新 → Catch-up≤7 日 | 清记忆、清成长时钟 |
| 中途换角 | **禁止**（流式中拒绝） | 「顶栏换人历史接着聊」 |
| 空会话欢迎 | 对当前 active 自我介绍 | 整档人生重开 |

换角后的「新奇感」来自新 Pack + 新空会话欢迎；可选微文案「再认识」是增强（M28-G3），**仍不重置时钟**。

## 八、会话绑角：防人格漂移的会话级锚

创建会话时写入 `role_id`，**不可 UPDATE**。  
组装时 `assertSessionRole`：历史是谁的嘴，就继续用谁——即使顶栏 active 已变，也提示错位而非偷换。

**判据**：会不会出现「设置里是小周，气泡里突然变成小林口吻」？出现即事故。

## 九、记忆 / 成长 / 生活三线并行

| 线 | 换角时 | 冷启动时 |
|----|--------|----------|
| 记忆（用户事实） | 通常跨角色保留 | 少挖敏感受 M28§五 |
| 成长（MUTABLE） | 分桶；不自动互抄 | 72h 门闸 |
| 生活（日子） | pause / Catch-up | ticker 只服务 active |

三线搞混的典型事故：用生活 Catch-up 当「重新自我介绍」；或用换角清空用户记忆「假装初次见面」。

# 第二部分：实战记录

## 做了什么

| 项 | 落点 |
|----|------|
| 欢迎文案 | `companion-presence.ts` shared |
| 72h/24h/5msgs | `reflection-gate.ts` + 单测 |
| 时钟打点 | `ensureGrowthStartedAt` |
| 禁中途换角 | orchestrator + streaming-gate |
| 会话绑角 | `sessions.role_id` + `assertSessionRole` |

## 弯路与取舍

1. **欢迎与成长曾混称「冷启动」**——文档与设置文案拆开后，减少「为什么欢迎了还不反思」的误解。  
2. **先硬门闸、后阶段枚举**——可测优先于精致叙事状态机。  
3. ~~**成长时钟全局**~~ → 已收 M22-G1（按 role 分桶）。  
4. **初稿偏对照表**——补上数值意图、会话绑角与三线表。

## 设计检查清单

1. 欢迎名是否等于当前 active？  
2. 装机 24h 内自动反思是否被拒？  
3. 换角是否误清 `companionGrowthStartedAt`？  
4. 流式中换角是否被拒？  
5. 旧会话 role 与 active 不一致时是否提示？  
6. 开场是否变成审讯问卷？
