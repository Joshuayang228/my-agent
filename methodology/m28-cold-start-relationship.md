# 第一部分：认知框架

## 一、第一性原理：关系要「先站稳，再长肉」，且换人不等于失忆重来

冷启动 simultaneous 两件事容易搅在一起：

1. **体验冷启动**：空会话时「嗨，我是谁」——降低第一次开口的尴尬  
2. **成长冷启动**：相处未满窗口前不改 MUTABLE——避免第一天就把人设拧歪  

再叠加多主角：完整切换是换「我」继续过日子（Catch-up），**不是**把关系进度清零重开教程。

第一性原理：

```
关系 = 可感知的阶段感 + 硬门闸保护默契写入；换角换的是视角，不是把用户当陌生人重置
```

# 推论组 A：两种「冷」

## 二、欢迎在场 ≠ 成长门闸

| | 欢迎冷启动（体验） | 成长冷启动（M22） |
|--|-------------------|------------------|
| 触发 | 空会话 / 新主角见面 UI | `companionGrowthStartedAt` 起算 |
| 产出 | title/subtitle/hint 文案 | 72h 内拒绝自动反思 |
| 目标 | 「有人在」 | 「别太早改默契」 |

两者互补：UI 立刻有人；人格成长却故意慢半拍。  
数值对齐 Alice：**72h** 冷启动 + **24h** 冷却 + 近 7 日消息阈值——可调，但改数要产品确认并单测锁住。

## 三、阶段叙事：陌生 / 熟悉 / 默契

规范层（尚未做成状态机）：

| 阶段 | 体感 | 行为倾向 |
|------|------|----------|
| **陌生** | 刚认识 | 少假定、少反思写入；欢迎文案 + 克制追问 |
| **熟悉** | 有共同语境 | 可更自然；记忆召回变多；仍低频成长 |
| **默契** | 行为默认值已个人化 | MUTABLE 可微调；aside 更贴 |

现状诚实：硬边界主要在**成长门闸 + 会话绑角**；阶段差异大量仍靠模型与 Pack 语气，未做 `relationshipStage` 枚举驱动 Prompt（Gap）。

# 推论组 B：什么时候可以更近

## 四、初次信息采集：问什么、何时问

- 优先记用户**主动分享**的事实（remember / 画像提取）  
- 避免审讯式问卷：「爱好？星座？前任？」连珠炮  
- 高敏信息（健康、财务、隐私路径）跟权限/记忆治理走，不在冷启动硬挖  

判据：第一次会话结束，用户应觉得「认识了一个人」，而不是「填完了一张表」。

## 五、熟悉度与反思启动

反思启动条件（已实现）是**工程代理指标**，不是情感评分：

- 时间：相处时钟 ≥ 72h  
- 密度：近 7 日该角色用户消息 ≥ 5  
- 节奏：距上次反思 ≥ 24h  

够用：防止「聊两句就改人设」。不够用：不区分「深度交心」与「纯敲代码」——更细的熟悉度模型是增强（Gap）。

# 推论组 C：换角与会话

## 六、换角 ≠ 冷启动会话

| 动作 | 含义 |
|------|------|
| 完整切换 | pause 旧 → active=新 → Catch-up≤7 日；**新会话**绑新 `role_id` |
| 会话中途换角 | **禁止**（流式中 `SESSION_ACTIVE`） |
| 空会话欢迎 | 对**当前 active** 说「嗨，我是 X」——不是重置成长时钟 |

每个会话创建时写入 `role_id` 且不可改：打开旧会话仍是当时那个人，避免「顶栏换了人、历史还在用旧嘴说话」的诡异感。  
换角后的欢迎感来自新空会话 + 新 Pack，**不**清 `companionGrowthStartedAt`（除非产品明确要「整档重置」）。

## 七、与记忆 / 成长的接缝

- **M08**：用户画像跨角色；角色专属默契在 MUTABLE  
- **M22**：成长时钟与反思；召唤不成长  
- **M23**：换角 Catch-up 补的是日子，不是「重新自我介绍流程」  

三线并行：记得你（记忆）· 跟你长默契（成长）· 她自己有日子（生活）。
