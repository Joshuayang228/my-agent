# 第一部分：认知框架

## 一、第一性原理：体验可信 = 叙事不断线 × 能力不掺水

伙伴产品有两类「假」：

1. **叙事假**：嘴上、朋友圈、记忆、压缩摘要对不上号——用户觉得「你根本不是同一个人」。  
2. **能力假**：语气无所不能，工具/权限/模型到了临门一脚才露馅——关系越亲，失望越重。

两者常常一起出现：为了「像小说」编日子，同时为了「像能干的助理」吹能力。我们的立场相反——**故事感从同源真相里长出来；能力感从诚实边界里长出来。**

# 推论组 A：叙事如何不断线

> 第一性原理左半边：用户感知到的「同一个她」，靠多条线同源，而不是靠模型临场编。

## 二、三条叙事线：关系线 · 日子线 · 干活线

| 线 | 真相源 | 用户感知 |
|----|--------|----------|
| **关系线** | 记忆 + MUTABLE + 会话历史 | 「她记得我们」 |
| **日子线** | DayScript / Event / Moments / Assets | 「她有自己的生活」 |
| **干活线** | 工具轨迹 / 任务计划 / 权限结果 | 「她能把事办成」 |

**判据**：三条线可以节奏不同（今天猛干活、朋友圈只冒一条），但**不能互相打脸**——对话里说在咖啡馆加班，圈里却显示一整天海边，就是叙事事故。

伙伴感来自三条线同时「像真的」；工具感只要求干活线。我们两样都要，所以比纯 Coding Agent 多两条必须保养的线。

## 三、最小关系记忆：压缩时不可当废纸

长对话必经 Snip / MicroCompact / Collapse（M07）。若关键关系只活在「某次 tool 结果的转述」里，一压缩就蒸发——用户会经历「失忆的演员」。

**不可丢（应已进持久层）**：

- 称呼与沟通偏好（记忆 / MUTABLE）  
- 进行中的共同约定（「这周把 X 做完」）  
- 未完成的情感锚点（用户明确说过「先别提某事」）  

**可丢**：

- 重复的工具输出、过期 debug 过程、已完成步骤的中间态  

**判据**：压缩后问自己——她还知道「我们是谁、卡在哪」吗？不知道 = 叙事断线，不是「省 token 成功」。

**已落地轻量版（M30-G2）**：`relationship-minset` 显式白名单进 compact instruction，并对中段消息启发式抽取后并入 L3/L4（含规则降级）摘要。  
持久层 `remember` / MUTABLE 仍是正道；白名单防的是「只活在对话里、一压就蒸发」。

## 四、事实正确 ≠ 有故事感

事实正确是底线（不编造用户没说过的话、不发明没发生的日子）。故事感是加分，来自：

1. **回调**——提起上周约定、共同玩笑、Catch-up 里的近况（有据）  
2. **节奏**——不是每句都「回忆杀」；该干活时主答干净（M27）  
3. **里程碑**——第一次换角、第一次反思写入、首次默契密度……  
   - **已落地轻量版（M30-G1）**：每角色每种只记一次；toast + Prompt 薄回调；**禁止**成就榜/积分  

**禁止**：为「像连续剧」生成未入库的神装、未 publish 的假动态、未存储的「你说过」。那是叙事毒品——短爽长痛（接 M24/M25/M29）。

**判据**：删掉所有「戏剧性」句子后，事实与承诺是否仍成立？若不成立，说明故事感绑在了谎言上。

## 五、压缩 · 世界 · 召唤：三处接缝

| 接缝 | 风险 | 纪律 |
|------|------|------|
| **压缩** | 摘要改写身份/约定 | 摘要服务「省上下文」，不服务「改人设」；身份以 PROTECTED/MUTABLE 为准 |
| **世界** | 嘴与圈、柜不一致 | 只陈述已有 event/moment/asset；不确定就别演 |
| **召唤** | 串门写成主线 | 对方 Pack 完整，但不 tick、不 Catch-up、不反思；故事是番外 |

换角 Catch-up（M23）补的是**日子线细窗**，不是把关系线清零重开教程（M28）。  
名册短句（M26）是关系线的浅层，禁止把他人 PROTECTED 灌进主对话造成「群戏串味」。

# 推论组 B：能力如何不掺水

> 第一性原理右半边：亲密感放大预期——吹过的牛，跌得更疼。

## 六、高估与低估都有成本

| 偏差 | 用户感受 | 典型触发 | 对策 |
|------|----------|----------|------|
| **高估** | 「你不是说能吗」 | 「包在我身上」却无工具/权限；装会生图朋友圈 | L2 只声明真实工具；不会就说不会；破坏性走确认 |
| **低估** | 「怎么这么废」 | 明明能 `file_read` 却空口猜；plan-first 变成每步求抱抱 | 该调用就调用；计划是为了风险，不是表演谦虚 |

**判据**：能力表达是否与**当前** tool 列表、executionMode、权限结果一致？一致才叫校准，不一致叫演戏。

## 七、硬边界与软边界

| 类型 | 含义 | 用户应感到 |
|------|------|------------|
| **硬边界** | 权限拒绝、沙箱拦、无此工具、召唤不推进生活 | 「系统不允许 / 产品不做」——可解释、可换路径 |
| **软边界** | 模型不确定、缺信息、估时不准 | 「我没把握，需要你补 X」——不装懂（M29） |

硬边界由 M10 / 工具注册表担保；软边界靠对话行为（M27）。  
**两者都不要用「我是全能伙伴」语气盖过去。**

## 八、自然表达「我不擅长」

用主角语气承认，仍给下一步：

1. 主答：边界是什么 + 可选路径（换工具 / 要用户提供 / 降级方案）  
2. aside（可选）：一句心虚或无奈——**不能**承载唯一关键信息（M27）  

例：用户要「直接改生产库」→ 硬边界推回 + 给本地迁移方案；aside 可以是「……这我可不敢偷摸来」。

**暂未实现**：按「用户专家度」自动调节解释粒度（M30-G3）——现在全靠模型自觉与 Pack 语气。

# 推论组 C：张力与验收

> 叙事与能力会打架：有时保故事会耽误事，有时保能力会显得冷。需要显式优先级。

## 九、故事感让位于干活时

当用户处于明确任务流（长工具链、报错、确认弹窗）：

- **主答**服务任务完成；生活碎碎念最多进 aside  
- **禁止**用三句朋友圈近况盖住 diff 结论  
- 生活 ticker 继续静默推进，但**不**弹窗抢焦点（M31）  

**判据**：用户若只截主答发给同事，是否仍是一份合格工作答复？若否，故事抢戏了。

## 十、与透明、权限、Eval 同族

| 模块 | 共同敌人 | 分工 |
|------|----------|------|
| M29 透明 | 装懂、暗记 | 记忆侧诚实 |
| M10 权限 | 偷做危险事 | 行动侧诚实 |
| L2 Capabilities | 工具幻觉 | 系统声明诚实 |
| B01 语气 Eval | 换皮腔 | 像人，但不考核吹能力 |
| 本章 | 叙事打架 + 预期失控 | 线不断 × 牛不吹 |

验收提问可以很朴素：**「她还是同一个人吗？她有没有吹过？」**

## 弯路与取舍

1. **曾经只有 Prompt 人格、没有日子线**——故事全靠临场编，一追问就穿帮。先 W2–W4 同源世界，再谈叙事，是对的顺序。  
2. **能力边界一度想写进 PROTECTED**——工具集会变，圣经不该每周改；放 L2 是正确分层。  
3. **里程碑系统很诱人**——未想清「什么算里程碑、谁写入、会否变成成就绑架」之前不上对象模型；先靠记忆自然堆积。  
4. **初稿方法论过薄**——只有原则标题没有判据与接缝表；本次加厚补上，避免 Part VI 尾章变成目录说明书。

## 设计检查清单

1. 压缩后，关键约定是否仍在持久层可召回？  
2. 对话声称的活动，能否在 events/moments 找到同源？  
3. 有没有承诺当前 tool 列表里不存在的能力？  
4. 权限/沙箱拒绝时，语气是否仍是同一主角、且给了替代路径？  
5. 干活高潮期，主答是否被生活旁白污染？  
6. 召唤番外有没有误写成对方主线成长/生活？
