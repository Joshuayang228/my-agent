# 第一部分：认知框架

## 一、第一性原理：在场是「世界还在过」的可感知证明，不是刷存在感的通知轰炸

纯被动问答 = 抽屉里的工具：用时灵，不用时等于死。  
伙伴要让人觉得「想打开看看」，前提是：**不聊的时候，日子与截面仍在推进（对活跃主角）**，且触达不讨人厌。

第一性原理：

```
主动在场 = 派生自真实世界状态的轻触达 + 打开即见的活人证明；禁止另造假生活刷存在

├─ 推论组 A：证明她还在
│     §二 打开即在场 · §三 截面 > 空聊
│
├─ 推论组 B：触达原则
│     §四 时机 / 形式 / 内容 · §五 与圈/任务/提醒分工
│
└─ 推论组 C：边界
      §六 打扰 vs 依赖 · §七 想打开，而不只是需要时打开
```

# 推论组 A：证明她还在

## 二、打开即在场

空会话欢迎屏：`嗨，我是{名}` + 一句话描述 + 「圈/柜跟当前主角」提示。  
这是成本最低的在场——不推送、不抢焦点，但打开就不是空白输入框。

换角后欢迎跟新 active；成长时钟不因此重置（M28）。

## 三、截面 > 空聊

活人证明优先看**世界派生截面**：

- Moments：她最近 published 的日子  
- Assets：还在的物  
- Catch-up 摘要：你回来时她补上的近况  

比「系统定时发『想我了吗』」更诚实——内容来自 M23–M25，不另造生活（接 M24 投影纪律）。

# 推论组 B：触达原则

## 四、时机 · 形式 · 内容

| 维 | 原则 |
|----|------|
| **时机** | 活跃角色 tick 后有新 moment；用户完成长任务；勿在深夜狂推（未做静默时段引擎 → Gap） |
| **形式** | 应用内截面 > 桌面通知 >（未来）系统推送；形式越强，内容越要「值得」 |
| **内容** | 只派生 World / 用户相关任务状态；禁止生成无关段子刷 DAU |

召唤忙闲的 `presence` 是**查询式在场**（现在在忙什么），不是推送。

## 五、分工

| 通道 | 职责 |
|------|------|
| 欢迎屏 | 身份在场 |
| Moments / Assets | 生活在场 |
| 桌面 Notification | 窗口失焦时回复可达（runtime 已有，偏任务完成而非生活） |
| 任务 pill / 后台任务 | 干活进度，不是情感刷屏 |
| 定时主动问候 | **未做**（Gap）——最易踩打扰线 |

# 推论组 C：边界

## 六、打扰感 / 依赖感

- **打扰**：高频无信息增量的推送；用户工作流中弹气泡  
- **依赖**：设计成「不回消息她就生病」的绑架——我们不做  

默认偏保守：先让「打开有东西看」，再谈「找上门」。

## 七、想打开，而不只是需要时打开

成功指标偏产品体感：

- 愿意点开朋友圈看看她今天怎样  
- 空会话不觉得冷  
- 需要干活时她仍在、且不挡事（生活不挡 Loop，M23）  

不是通知点击率最大化。

## 弯路与取舍

1. **先截面后推送**：推送没有真实 moment 就是假在场。  
2. **文案 shared**：主进程与渲染一致。  
3. **主动问候后置**：打扰模型没想清前不写定时器。
