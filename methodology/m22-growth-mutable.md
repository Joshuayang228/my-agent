# 第一部分：认知框架

## 一、第一性原理：成长是「把默契低频固化进行为默认值」，不是「多记几条事实」

M21 说人格是「一致性 × 成长性」的张力。M22 只回答张力的右半边：**成长性具体写进哪里、多久写一次、写错了怎么退**。

最容易踩的坑有两个：

1. **把成长做成记忆**——用户说「别写太长」，系统只多了一条事实记忆，行为默认值仍是出厂模板；聊一百次还是同一个「不记得你们默契」的演员。  
2. **把成长做成每轮改人设**——每条反馈都改 MUTABLE，人设抖动、KV Cache 失效、还容易漂出 PROTECTED。

第一性原理：

```
成长 = 从相处里提炼「行为默认值」，低频写入 MUTABLE，且永远可回滚

├─ 推论组 A：写什么 / 不写什么
│     §二 MUTABLE vs 记忆 · §三 绝不碰 PROTECTED
│
├─ 推论组 B：何时写、写错怎么办
│     §四 低频门闸 · §五 版本与回滚 · §六 null 也是合法结果
│
└─ 推论组 C：和谁一起成长、和谁只是串门
      §七 活跃主角成长 · 召唤不成长对方 · §八 信号够用即可
```

> **前置边界**：M22 管「行为默契」；事实与偏好条目仍归记忆（M08）。生活世界事件进反思信号是增强项，不是成长核成立条件。

# 推论组 A：写什么 / 不写什么

## 二、MUTABLE vs 记忆：事实归记忆，行为默认值归成长

| | 记忆 | MUTABLE |
|--|------|---------|
| 存什么 | 用户是谁、发生过什么、偏好事实 | 回复节奏、语气、默认表达习惯 |
| 变化频率 | 可较高（工具写入 / 画像提取） | 必须低频 |
| 进 Prompt | L3 检索/画像 | L1 与 PROTECTED 同层（稳定前缀） |
| 错了怎么办 | 删条 / forget | 版本回滚 |

**判据**：这句话变了，还是不是「同一个人」？  
- 变了就不是 → 不该进 MUTABLE（多半是身份/价值观，属 PROTECTED）  
- 变了仍是 TA，只是更懂你 → 可以进 MUTABLE  
- 只是一条可核对的事实 → 进记忆，不进 MUTABLE  

反思 Prompt 必须显式禁止「把流水账事实写进 MUTABLE」。否则成长核会变成第二记忆库，两边抢职责。

## 三、PROTECTED 是硬锚；反思只能软约束

分区的意义在 M21 已说清：演化机制**结构上**只能写用户态 MUTABLE，不能改仓库里的 Pack / PROTECTED。

反思 Runner 额外做两件事：

1. **只读** PROTECTED 摘要进 Prompt，当作防漂移锚点  
2. **指令层**要求：不得发明新身份、不得改核心价值观；不确定则 `newMutable = null`

我们接受一个诚实的缺口：**现阶段没有结构性「越改越不像」校验**（例如 embedding 相似度或规则白名单）。防退化主要靠分区 + Prompt + 人工回滚。这不是忘了，是成本/收益上先保证「写得对地方、写得低频、写得可退」。

# 推论组 B：何时写、写错怎么办

## 四、低频门闸：冷启动 · 冷却 · 信号阈值

「能改」不等于「该改」。门闸是产品选择，对照 Alice `shouldReflectNow`，我们落地为：

| 门闸 | 取值 | Why |
|------|------|-----|
| 冷启动 | 成长时钟起 **72h** 内不反思 | 刚认识就改默契，噪声大、也破坏「先稳定再成长」 |
| 冷却 | 该角色上次反思起 **24h** | 防止一天内反复微调导致人设抖 |
| 信号 | 近 **7 日** 该角色用户消息 **≥ 5** | 没相处密度就别假装有默契 |

触发方式：主对话结束后后台入队（与 profile-extract 同级），门闸不满足则静默跳过——成长不应打扰聊天主路径。

设置页保留「立即反思 / 强制反思」：调试与用户主动固化需要逃生口；`force` 跳过门闸，但仍走同一 Runner 与版本写入。

## 五、版本与回滚：成长必须可后悔

每次成功写入 `setMutable` 都产生版本记录（summary 带 `reflection:` 前缀或人手说明）。  
用户可以在设置里回滚——**没有回滚的成长是绑架**。

实现约束：只写 SQLite 用户态，**永不改** `universes/*/mutable.default.md`。出厂默认永远是回落底。

## 六、null 是一等公民：多数时候不该改

Runner 输出 JSON：`{ newMutable: string|null, summary }`。  
`null` / 与当前正文相同 → **记一次 lastRun（占冷却），但不升版本**。

这是成长核和「自作聪明改 prompt」产品的分水岭：系统被允许判断「现在这样就好」。失败（LLM 挂了、解析失败）同样不写版本，只记 log，避免用垃圾覆盖默契。

# 推论组 C：和谁一起成长

## 七、活跃相处才成长；召唤是串门

同团多主角下：

- **活跃主角**：真实生活世界在转、主会话在聊 → 可以调度反思  
- **召唤子会话**（`session_kind=summon`）：装载对方 Pack 聊天，但不改 `activeRoleId`、不推进对方生活 → **不触发反思**

理由：串门聊两句不该改写对方的长期默契；成长绑定「你正在过的那条关系」。

## 八、信号够用即可，不抄全量 worldFacts

Alice 侧会把更多世界事实喂进反思。我们本轮刻意收窄：

- 近 7 日用户消息摘要  
- `feedback` 类记忆  
- 当前 MUTABLE + PROTECTED 摘要  

生活剧本 / Moments 全量进反思 = 增强项（见 Gap），不挡「成长核成立」。先证明低频固化行为默认值这条链路是通的，再加厚信号。
