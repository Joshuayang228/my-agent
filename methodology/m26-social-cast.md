# 第一部分：认知框架

## 一、第一性原理：卡司是活跃主角视角下的圈子，不是同屏并列主角团

同宇宙可有多个可切换主角，但**每一刻对话只有一个「我」**。  
其他人应以「你认识的人」出现：短关系、可召唤——不是把三份 PROTECTED 糊进同一 Prompt 演群戏。

三个坑：

1. **名册灌全文** → 身份串味、token 爆炸  
2. **召唤 = 换活跃** → 串门毁掉对方生活/成长主权  
3. **卡司 = Swarm** → 人设包装与任务编排搅成一团  


# 推论组 A：主对话如何出现

## 二、relations 是宇宙资产上的边

`relations.json`：`from` / `to` / `type` / `note`。  
组装以 active 为视角 →「你与 X（同事）：…」。  
NPC 可不在 `protagonistIds`；主角之间也可有边。

## 三、名册浅注入：summary / note，绝不他人 protected

Prompt 声明：名册摘要不是完整人设；不要假装成为他们。  

**判据（Eval C01）**：主对话 system 出现其他角色全文 PROTECTED → 架构违规。

只用：`name` + `typeLabel` + `note || summary || description`。

## 四、禁止在 protected 里互抄小传

关系真相在**边与 summary**，不在三份圣经各写一套互相矛盾的人物志。  
否则换角/召唤时「我对她的记忆」与「她对自己的记忆」永久打架。

# 推论组 B：召唤与忙闲

## 五、召唤 = 子会话装载，不改世界主权

用户要的是「跟这个人聊一会儿」。

| 做 | 含义 |
|----|------|
| `session_kind=summon` | 会话级标记 |
| 装载对方完整 Pack（含 protected） | 串门要像那个人 |
| CastPanel「开聊」 | 入口 |

## 六、召唤明确不做的事

| 不做 | 为何 |
|------|------|
| 改 `activeRoleId` | 主权仍在原活跃主角 |
| tick / Catch-up 对方生活 | 串门不推进别人日子 |
| 自动反思写对方 MUTABLE | 串门不长成同居默契 |
| 把召唤当换角捷径 | 产品语义分离 |

**判据**：开聊后 settings 的 active 变了吗？对方 day_scripts 是否无故增多？变了/增多即事故。

## 七、可用性：可婉拒，可 force

对照 Alice `checkFriendAvailability`：

- 忙时段 / 忙日 / declineRate 随机婉拒 + 改约建议  
- 日程槽位优先于静态忙闲表  
- **查询只读**，不 resume 对方  
- `force` 可强开——忙闲是角色感，**不是**硬墙绑架用户  

召唤 Prompt 可带 presence 情境（现在在忙什么），仍不推进生活。

# 推论组 C：边界

## 八、三主角槽是「可切换的我」，不是「同时三个我」

`protagonistIds` 挂满 ≠ 主对话三角色同台。  

| 动作 | 语义 |
|------|------|
| 完整切换 | 换「我」+ pause/Catch-up（M23） |
| 召唤 | 临时以对方身份聊，不换主权 |

## 九、卡司人设包装 ≠ M19 多 Agent 编排

| | 卡司（M26） | 多 Agent（M19） |
|--|------------|----------------|
| 目的 | 关系感、风格一致的「谁」 | 任务拆分、并行工具 |
| 入口 | relations / summon / roster | subagent / 编排器 |
| 失败 | 身份串味、偷推进生活 | 权限泄漏、结果合并乱 |

未来「朋友帮干活」必须先守 M26 边界，再接到 M19——顺序不能反。

## 十、与圈、反思、生活的接缝

| 模块 | 接缝 |
|------|------|
| M24 Moments | 默认只显示 active；投影可挂浅层评论/同框（M26-G1） |
| M22 反思 | 召唤不调度 |
| M23 生活 | 召唤不 tick |
| M31 在场 | presence 是查询式，不是推送式 |

# 第二部分：实战记录

## 做了什么（W5 + 增强）

| 项 | 落点 |
|----|------|
| 名册短句 | `cast/roster.ts` → L3 |
| 召唤摘要 | `loadCastBrief` / CastPanel |
| 忙闲 | `cast/availability.ts` |
| 开聊 | `orchestrator.startSummon` |
| 契约 | Eval C01 |

## 弯路与取舍

1. **先浅注入再完整召唤**——主对话安全第一。  
2. **召唤带全 Pack**——串门要像，但引擎不动。  
3. **force 保留**——角色感服务体验，不绑架。  
4. **初稿补「不做清单」与 M19 分界表**——减少实现时偷换语义。

## 设计检查清单

1. 主对话有无他人 protected 全文？  
2. 召唤后 active 是否不变？  
3. 对方 scripts/反思是否被误触发？  
4. 名册是否以当前 active 为视角？  
5. 忙闲拒绝后 force 是否可用？  
6. 是否把召唤当成换角实现？
